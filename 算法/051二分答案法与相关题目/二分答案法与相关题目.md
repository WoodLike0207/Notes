# 1. 爱吃香蕉的珂珂

测试链接 : https://leetcode.cn/problems/koko-eating-bananas/



## 代码

```java
public class Code01_KokoEatingBananas {
    public int minEatingSpeed(int[] piles, int h) {
        int l = 1;
        int r = 0;

        for (int pile : piles) {
            r = Math.max(r, pile);
        }

        int ans = 0;
        int m = 0;
        while (l <= r) {
            m = l + ((r - l) >> 1);

            if (f(piles, m) <= h) {
                ans = m;
                r = m - 1;
            }else {
                l = m + 1;
            }
        }

        return ans;
    }

    public long f(int[] piles, int speed) {
        long ans = 0;
        for (int pile : piles) {
            ans += (pile + speed - 1) / speed;
        }
        return ans;
    }
}
```



## 思路

这道题是 **“二分答案法” (Binary Search on Answer)** 的入门级经典题目（LeetCode 875）。它展示了当答案具有**单调性**时，如何通过二分搜索直接锁定答案，而不是暴力枚举。



### 1. 【核心思想：二分答案】

- **题目转换**：题目要求找一个最小的整数速度 $k$。

- **单调性**：

  - 如果珂珂吃得越快（$k$ 越大），耗费的时间 $time$ 就越少。
  - 如果珂珂吃得越慢（$k$ 越小），耗费的时间 $time$ 就越多。
  - 这是一个典型的**单调递减**关系。

- **策略**：

  既然速度和时间有单调关系，我们就可以在 **[最小速度, 最大速度]** 的区间内进行二分查找。

  - 每次猜一个速度 `mid`。
  - 如果用 `mid` 速度吃，时间**达标**（$\le h$）：说明这个速度够快了，甚至可能太快了。我们记录答案，并尝试**更慢**的速度（往左找）。
  - 如果用 `mid` 速度吃，时间**超时**（$> h$）：说明这个速度太慢了，必须**更快**（往右找）。

### 2. 【核心细节解析】

#### A. 搜索范围 (`l` 和 `r`)

- **`l` (下界)**: **1**。因为珂珂每小时至少吃 1 根（速度不能为 0）。
- **`r` (上界)**: **`max(piles)`**。
  - 为什么是最大堆的大小？
  - 假设最大的一堆有 100 根。如果速度是 100，吃这一堆要 1 小时。如果速度是 200，吃这一堆还是要 1 小时（题目规定：吃完这堆后，这一小时内不会再吃别的）。
  - 所以，速度超过最大堆的大小没有任何意义，只会浪费算力。

#### B. 向上取整公式 (Ceiling Math)

题目规定：如果一堆有 `pile` 根，速度是 `speed`，不足 `speed` 也算 1 小时。这本质上是**向上取整**。

- **数学公式**：$\lceil \frac{pile}{speed} \rceil$

- **代码技巧**：

  $$\text{time} = (pile + speed - 1) / speed$$

  *(这是整数运算中实现向上取整的通用写法，避免了使用浮点数 `Math.ceil` 带来的精度问题和性能损耗)*

### 3. 【图解二分过程】

假设香蕉堆 `piles = [3, 6, 7, 11]`, `h = 8`。

最大堆是 11，所以搜索区间 `[1, 11]`。

1. **L=1, R=11, Mid=6**
   - 耗时计算：$3/6 \to 1, 6/6 \to 1, 7/6 \to 2, 11/6 \to 2$。总时 $1+1+2+2 = 6$。
   - $6 \le 8$ (达标)。**记录 ans=6**。尝试更慢的 `R = 5`。
2. **L=1, R=5, Mid=3**
   - 耗时计算：$3/3 \to 1, 6/3 \to 2, 7/3 \to 3, 11/3 \to 4$。总时 $1+2+3+4 = 10$。
   - $10 > 8$ (超时)。速度太慢，**L = 4**。
3. **L=4, R=5, Mid=4**
   - 耗时计算：$3/4 \to 1, 6/4 \to 2, 7/4 \to 2, 11/4 \to 3$。总时 $1+2+2+3 = 8$。
   - $8 \le 8$ (达标)。**记录 ans=4**。尝试更慢 `R = 3`。
4. **L=4, R=3** -> 循环结束。返回 **4**。

### 4. 【代码逐行精读】

```java
public static int minEatingSpeed(int[] piles, int h) {
    // 1. 确定二分搜索的边界
    int l = 1;
    int r = 0;
    for (int pile : piles) {
        // 上界是所有香蕉堆中的最大值
        r = Math.max(r, pile);
    }
    
    int ans = 0;
    int m = 0;
    // 2. 标准二分模板
    while (l <= r) {
        m = l + ((r - l) >> 1); // 防溢出的中间值写法
        
        // f() 函数计算以速度 m 吃完需要多少小时
        if (f(piles, m) <= h) {
            // 【达标】
            // 既然 m 速度能做完，记录它。
            // 但我们要找"最小"速度，所以尝试去左边找更小的。
            ans = m;
            r = m - 1;
        } else {
            // 【不达标】(超时了)
            // 说明 m 太慢了，必须加速，去右边找。
            l = m + 1;
        }
    }
    return ans;
}

// 辅助函数：计算总耗时
// 必须用 long，因为累加的时间可能会超过 int 范围
public static long f(int[] piles, int speed) {
    long ans = 0;
    for (int pile : piles) {
        // 【核心技巧】向上取整的整数写法
        // (a + b - 1) / b 等价于 ceil(a / b)
        ans += (pile + speed - 1) / speed;
    }
    return ans;
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N \cdot \log(\max(P)))$。
  - 二分查找的次数是 $\log(\text{max\_pile})$。
  - 每次 `f` 函数检查需要遍历数组，耗时 $O(N)$。
- **空间复杂度**: $O(1)$。
  - 只用了几个变量。

### 6. 【易错点 / 面试考察】

1. **向上取整怎么写？**
   - 普通写法：`(p % k == 0) ? (p / k) : (p / k + 1)`
   - **大神写法**：`(p + k - 1) / k`。不仅代码短，而且在很多语言中效率微高。
2. **`f` 函数返回值的类型**
   - 一定要用 `long`。虽然这道题限制了 `h` 在 int 范围内，但在类似的二分题目中，中间过程的累加和很容易溢出 int。
3. **二分结束条件**
   - `l <= r` 是标准写法，不要漏掉 `=`。

### 7. 【复习闪卡】

- **Q: 什么时候可以用“二分答案法”？**
  - A: 当问题的答案在一个有序区间内（比如正整数），且答案与验证条件之间存在**单调性**（例如：效率越高，耗时越少）时。
- **Q: 为什么上界是 `max(piles)` 而不是 `sum(piles)`？**
  - A: 因为题目限制了“每小时只能选一堆”。即使你速度无限大，吃完一堆也要 1 小时。速度超过最大堆的大小后，时间并不会减少。
- **Q: 向上取整公式 `(a + b - 1) / b` 的原理是什么？**
  - A: 如果 `a` 能被 `b` 整除，`a + b - 1` 除以 `b` 还是 `a/b`。如果 `a` 有余数，`a + b - 1` 刚好能跨过下一个倍数的门槛，导致结果 +1。



# 2. 分割数组的最大值(画匠问题)

测试链接 : https://leetcode.cn/problems/split-array-largest-sum/



## 代码

```java
public class Code02_SplitArrayLargestSum {
    public int splitArray(int[] nums, int k) {
        long sum = 0;
        for (int num : nums) {
            sum += num;
        }

        long ans = 0;
        for(long l = 0, r = sum, m, need; l <= r; ) {
            m = l + ((r - l) >> 1);

            need = f(nums, m);

            if (need <= k) {
                ans = m;
                r = m - 1;
            }else {
                l = m + 1;
            }
        }

        return (int) ans;
    }

    public int f(int[] arr, long limit) {
        int parts = 1;
        int sum = 0;

        for (int num : arr) {
            if (num > limit) {
                return Integer.MAX_VALUE;
            }

            if (sum + num > limit) {
                parts++;
                sum = num;
            }else {
                sum += num;
            }
        }

        return parts;
    }
}
```



## 思路

这道题是 **“二分答案法”** (Binary Search on Answer) 的**最高频、最经典**题目之一（LeetCode 410）。

同类题目还有“运送货物”、“打包包裹”等，本质都是 **“最小化最大值” (Min-Max Problem)**。



### 1. 【核心题目含义】

- **目标**：把一个数组切成 `k` 段（连续子数组）。
- **约束**：每一段的和都不能太大。
- **求什么**：我们需要找到一个“标准”（每一段和的最大值），使得这个标准**尽可能小**，同时还能保证把数组切成不超过 `k` 段。

### 2. 【核心思路：二分答案】

为什么可以用二分？因为**单调性**。

假设我们给每一个子数组规定一个**容量上限 (Capacity)**，记为 `limit`。

- 如果 `limit` 很大（容量无限），只需要 1 个子数组就能装下所有数。
- 如果 `limit` 很小（容量极小），我们需要切成很多很多个子数组。
- **结论**：`limit` 越大，需要的段数 `parts` 越少。
- **策略**：既然段数随着容量单调变化，我们就可以在 **[最小可能容量, 最大可能容量]** 之间二分查找，找到那个**“刚刚好能切成 k 段”**的最小容量。

### 3. 【图解 f 函数 (贪心划分)】

函数 `f(arr, limit)` 的作用是：**如果每段的和最大不能超过 `limit`，我至少需要分多少段？**

**贪心策略**：

只要当前这一段还能塞得下下一个数字，就硬塞！实在塞不下了，再切一刀，开新的段。

假设 `nums = [7, 2, 5, 10, 8]`，限制 `limit = 15`。

**推演过程：**

1. **第1段**：
   - 进来 `7`。和=7 (<=15)，OK。
   - 进来 `2`。和=9 (<=15)，OK。
   - 进来 `5`。和=14 (<=15)，OK。
   - 进来 `10`。和=24 (>15)，**爆了！**
   - **动作**：在 `5` 和 `10` 之间切一刀。段数+1。
   - **重置**：第1段结束，第2段从 `10` 开始。
2. **第2段**：
   - 当前是 `10`。和=10 (<=15)，OK。
   - 进来 `8`。和=18 (>15)，**爆了！**
   - **动作**：在 `10` 和 `8` 之间切一刀。段数+1。
   - **重置**：第2段结束，第3段从 `8` 开始。
3. **第3段**：
   - 当前是 `8`。结束。
4. **结果**：需要 **3** 段。

### 4. 【代码逐行精读】

#### A. 主函数 (二分逻辑)

```java
public static int splitArray(int[] nums, int k) {
    long sum = 0;
    for (int num : nums) {
        sum += num;
    }
    
    // 二分范围确定：
    // 下界 l：理论上最小是数组中的最大值（代码里为了简便写了0，依靠f函数纠正）
    // 上界 r：数组总和（即只分1段的情况）
    long l = 0; 
    long r = sum;
    long ans = 0;
    
    // 标准二分模板
    while (l <= r) {
        // 猜一个"最大和的限制" m
        long m = l + ((r - l) >> 1);
        
        // 调用 f 函数：如果每个子数组最大和是 m，需要分几段？
        long need = f(nums, m);
        
        // 【核心判断】
        if (need <= k) {
            // 如果需要的段数 <= k，说明 limit 足够大，甚至太大。
            // 这是一个"可行解"，记录下来 (ans = m)。
            // 但我们要找"最小"的 limit，所以尝试把 limit 调小一点，去左边找。
            ans = m;
            r = m - 1;
        } else {
            // need > k
            // 说明需要的段数太多了！意味着 limit 给得太小了，塞不下。
            // 必须把 limit 调大，去右边找。
            l = m + 1;
        }
    }
    return (int) ans;
}
```

#### B. 辅助函数 f (贪心检查)

```java
// 返回值：在 limit 限制下，最少需要分几段
public static int f(int[] arr, long limit) {
    int parts = 1; // 初始至少有 1 段
    int sum = 0;   // 当前这一段的累加和
    
    for (int num : arr) {
        // 【边界情况】
        // 如果单个数字比 limit 还大，那无论怎么分都不可能满足。
        // 直接返回无穷大，让二分逻辑去右边找（增大 limit）。
        if (num > limit) {
            return Integer.MAX_VALUE;
        }
        
        // 如果当前段 + 新数字 > limit，说明装不下了
        if (sum + num > limit) {
            parts++;      // 切一刀，段数+1
            sum = num;    // 新的一段从当前数字开始
        } else {
            sum += num;   // 还能装，继续累加
        }
    }
    return parts;
}
```

### 5. 【难点解析：为什么是 `need <= k`？】

很多同学会纠结：题目要求分成 `k` 段，为什么 `need < k` 也是达标？

- **含义**：`need` 是在 `limit` 限制下，我们**最少**需要的段数。
- **解释**：如果算出来 `need = 3`，而题目给的 `k = 5`。说明我们在满足限制的情况下，哪怕只分 3 段都够了。
- **操作**：既然 3 段都行，那我随便把其中的某一段再切两刀，变成 5 段，每一段的和只会变小，不会变大，所以 limit 依然成立。
- **结论**：只要 `need <= k`，说明当前的 `limit` 是一个**可行解**（虽然可能不是最优解），我们要记录它，然后尝试压缩它。

### 6. 【复杂度分析】

- **时间复杂度**: $O(N \cdot \log(\Sigma nums))$。
  - 二分的范围是数组的总和（`Sum`）。二分次数是 $\log(\text{Sum})$。
  - 每次二分内部跑一次 `f` 函数，遍历数组 $O(N)$。
- **空间复杂度**: $O(1)$。

### 7. 【复习闪卡】

1. **Q: 这道题为什么不是动态规划？**
   - A: 可以用 DP 做，但 DP 复杂度通常是 $O(N^2 \cdot K)$，会超时。这道题是典型的 **"Min-Max"** 问题，首选二分答案。
2. **Q: `f` 函数中 `sum + num > limit` 时，`sum` 变成了什么？**
   - A: `sum` 变成了 `num`。因为之前的段已经结账（切断）了，当前这个 `num` 成为新一段的开头。
3. **Q: 二分查找的 `l` 和 `r` 初始值建议怎么设？**
   - A: `l = max(nums)`（单个元素最大值），`r = sum(nums)`（所有元素之和）。代码中写 `l=0` 也没错，因为 `f` 函数会拦截不合法的情况自动右移。



# 3. 机器人跳跃问题

## 代码

```java
/**
 * @Title: Code03_RobotPassThroughBuilding
 * @Author Wood
 * @Package PACKAGE_NAME
 * @Date 2026/2/12 22:16
 * @description:

public class Code03_RobotPassThroughBuilding {
    public static int MAXN = 100001;

    public static int[] arr = new int[MAXN];

    public static int n;

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StreamTokenizer in = new StreamTokenizer(br);
        PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));

        while (in.nextToken() != StreamTokenizer.TT_EOF) {
            n = (int) in.nval;
            int l = 0;
            int r = 0;

            for (int i = 1; i <= n; i++) {
                in.nextToken();
                arr[i] = (int) in.nval;
                r = Math.max(r, arr[i]);
            }
            out.println(compute(l, r, r));
        }

        out.flush();
        out.close();
        br.close();
    }

    public static int compute(int l, int r, int max) {
        int m, ans = -1;
        while (l <= r) {
            m = l + ((r - l) >> 1);

            if (f(m,max)) {
                ans = m;
                r = m - 1;
            }else {
                l = m + 1;
            }
        }

        return ans;
    }

    public static boolean f(int energy, int max) {
        for (int i = 1; i <= n; i++) {
            if (energy <= arr[i]) {
                energy -= arr[i] - energy;
            }else {
                energy += energy - arr[i];
            }

            if (energy >= max) {
                return true;
            }
            if (energy < 0) {
                return false;
            }
        }
        return true;
    }
}
```

## 思路

这道题是 **“二分答案法” (Binary Search on Answer)** 的一个非常典型的应用场景，同时包含了一个**极易忽略的数学陷阱**（溢出问题）。



### 1. 【题目核心逻辑推导】

**能量转移公式的统一：**

题目中描述了两种情况：

1. **能量不足跳高处** ($H > E$)：失去 $H - E$。
   - 新能量 $E_{new} = E - (H - E) = 2E - H$
2. **能量充足跳低处** ($H \le E$)：得到 $E - H$。
   - 新能量 $E_{new} = E + (E - H) = 2E - H$

**结论**：无论哪种情况，下一跳的能量公式都是 **$E_{new} = 2E - H_{next}$**。

### 2. 【为什么使用二分答案？】

这个问题满足**单调性**：

- 如果以初始能量 $X$ 能通关，那么任何比 $X$ 大的能量肯定也能通关（只会剩余更多）。
- 如果以初始能量 $X$ 无法通关（中途变成负数），那么任何比 $X$ 小的能量肯定也无法通关。

既然答案具备单调性，且我们要求的是“最小达标值”，这正是 **二分查找** 的拿手好戏。

- **下界 (L)**: 0 (能量是非负的)。
- **上界 (R)**: `max(arr)` (所有建筑的最大高度)。
  - *推导*：如果初始能量等于最高的建筑高度，那么 $E \ge H$ 永远成立，每一次跳跃能量都会增加或持平 ($E_{new} \ge E$)，绝对不可能死掉。所以最大高度是一个绝对安全的上界。

### 3. 【图解二分逻辑】

我们猜一个初始能量 `mid`，然后模拟跳跃过程：

1. **Check(mid) 成功**：说明 `mid` 够用，记录答案，尝试更小的能量 (`r = m - 1`)。
2. **Check(mid) 失败**：说明 `mid` 不够，必须增加能量 (`l = m + 1`)。

### 4. 【代码核心：防溢出陷阱】

这道题最阴险的地方在 `f` 函数（检查函数）里。

**陷阱分析：**

公式 $E_{new} = 2E - H$ 本质上是**指数级增长**的。

如果当前的 $E$ 远大于 $H$，每一次跳跃能量几乎翻倍。

如果有 $10^5$ 个建筑，能量可能翻倍 $10^5$ 次，这将是一个天文数字，**直接导致 `int` 甚至 `long` 溢出变成负数**，从而导致逻辑错误判负。

**解决方案（剪枝）：**

在模拟过程中，一旦发现 `energy >= max` (当前能量已经超过了所有建筑的最大高度)，**直接返回 true**。

- **原理**：当 $E \ge H_{max}$ 时：

  $$E_{new} = 2E - H_{next} \ge 2H_{max} - H_{max} = H_{max}$$

  也就是说，一旦能量达到最大高度，它以后永远不会掉下来，只会越来越大（或者持平），绝对能通关。

### 5. 【代码逐行精读】

```java
public static int compute(int l, int r, int max) {
    int m, ans = -1;
    // 标准二分模板
    while (l <= r) {
        m = l + ((r - l) >> 1);
        // f(m, max) 返回用 m 能量能不能通关
        if (f(m, max)) {
            ans = m;    // 达标了！记录答案
            r = m - 1;  // 贪心：试试能不能更少
        } else {
            l = m + 1;  // 不达标，必须加钱
        }
    }
    return ans;
}

public static boolean f(int energy, int max) {
    for (int i = 1; i <= n; i++) {
        // 下面两行等价于 energy = 2 * energy - arr[i]
        // 只是为了对应题目描述
        if (energy <= arr[i]) {
            energy -= arr[i] - energy;
        } else {
            energy += energy - arr[i];
        }
        
        // 【核心高能预警】
        // 如果没有这句判断，energy 会呈指数级爆炸增长导致整型溢出
        // 只要能量超过了路上的最大障碍，后面就是无敌模式，直接通过
        if (energy >= max) {
            return true;
        }
        
        // 能量为负，Game Over
        if (energy < 0) {
            return false;
        }
    }
    return true;
}
```

### 6. 【复杂度分析】

- **时间复杂度**: $O(N \cdot \log(\text{max\_height}))$。
  - 二分查找范围是 `0` 到 `max_height`，迭代次数 $\log(\text{max\_height})$。
  - 每次 `check` 需要遍历 $N$ 个建筑。
- **空间复杂度**: $O(N)$。
  - 用于存储建筑高度数组。

### 7. 【复习闪卡】

1. **Q: 机器人跳跃问题的能量转移公式是什么？**
   - A: $E_{new} = 2E - H_{next}$。
2. **Q: 为什么二分的上界是建筑的最大高度？**
   - A: 因为只要初始能量大于等于最高建筑，能量永远非递减，一定能通关。
3. **Q: `f` 函数中 `if (energy >= max) return true;` 这句代码能删吗？**
   - A: **绝对不能**。删了会因为能量指数级增长导致 `int` 溢出（变成负数），从而误判为任务失败。这是这道题最大的坑。
4. **Q: 还有其他解法吗？**
   - A: 有，**逆推法**。从最后一个建筑往回推。要跳到 $H(i)$ 且剩余能量 $E \ge 0$，推导出前一步需要的最小能量是 $\lceil (E + H(i)) / 2 \rceil$。这种方法时间复杂度 $O(N)$，比二分更优，但二分法思路更通用。



# 4. 找出第K小的数对距离

测试链接 : https://leetcode.cn/problems/find-k-th-smallest-pair-distance/



## 代码

```java
public class Code04_FindKthSmallestPairDistance {
    public int smallestDistancePair(int[] nums, int k) {
        int n = nums.length;
        Arrays.sort(nums);
        int ans = 0;

        for (int l = 0, r = nums[n - 1] - nums[0], m, cnt; l <= r; ) {
            m = l + ((r - l) >> 1);

            cnt = f(nums, m);

            if (cnt < k) {
                l = m + 1;
            }else {
                ans = m;
                r = m - 1;
            }
        }

        return ans;
    }

    public int f(int[] arr, int limit) {
        int ans = 0;

        for (int l = 0, r = 0; l < arr.length; l++) {
            while (r + 1 < arr.length && arr[r + 1] - arr[l] <= limit) {
                r++;
            }

            ans += r - l;
        }

        return ans;
    }
}
```





## 思路

这道题是 **“二分答案法” (Binary Search on Answer)** 结合 **“滑动窗口/双指针”** 的经典 Hard 题目（LeetCode 719）。

它解决了一个看似需要 $O(N^2)$ 计算所有数对差值的问题，通过二分将复杂度降到了接近 $O(N \log N)$。



### 1. 【核心痛点与解决策略】

- **暴力法痛点**：如果数组长度 $N=10000$，数对就有 $N^2/2 \approx 5 \times 10^7$ 个。生成所有数对再排序求第 K 小，内存和时间都会爆炸。
- **解决策略**：**二分答案**。
  - 我们不直接找第 K 小的距离，而是去**猜**一个距离 `mid`。
  - **问题转化为**：如果所有数对中，距离 $\le mid$ 的数对有 `cnt` 个。
  - 如果 `cnt < k`：说明 `mid` 太小了，还没够到第 K 小的门槛 $\rightarrow$ 猜大一点。
  - 如果 `cnt >= k`：说明 `mid` 够大了，可能是答案，也可能比答案大 $\rightarrow$ 记录答案，尝试猜小一点。

### 2. 【核心步骤】

1. **排序**：这是使用双指针的前提。排序后，$nums[j] - nums[i]$ (其中 $j > i$) 就是距离。
2. **确定二分范围**：
   - 最小距离 `L = 0` (两个相同的数)。
   - 最大距离 `R = nums[N-1] - nums[0]` (最大值减最小值)。
3. **核心校验函数 `f(limit)`**：
   - 计算数组中有多少对数字的差值 $\le limit$。
   - 利用**滑动窗口**在 $O(N)$ 时间内完成计数。

### 3. 【图解：滑动窗口计数法】

假设 `nums = [1, 1, 3, 5, 8]`, `limit = 2`。

我们要找差值 $\le 2$ 的数对数量。

**推演过程：**

我们固定左端点 `l`，寻找最大的右端点 `r`，使得 `nums[r] - nums[l] <= limit`。

- **l=0 (`1`)**:
  - `r` 扩到下标 2 (`3`)。`3-1=2` (OK)。`r` 再扩到下标 3 (`5`) 就不行了。此时 `r=2`。
  - 有效数对：`(0,1)`, `(0,2)`。
  - 数量：`r - l = 2 - 0 = 2` 个。
- **l=1 (`1`)**:
  - `r` 还是下标 2 (`3`)。`3-1=2` (OK)。
  - 有效数对：`(1,2)`。
  - 数量：`r - l = 2 - 1 = 1` 个。
- **l=2 (`3`)**:
  - `r` 扩到下标 3 (`5`)。`5-3=2` (OK)。
  - 有效数对：`(2,3)`。
  - 数量：`r - l = 3 - 2 = 1` 个。
- **l=3 (`5`)**:
  - `r` 还是下标 3。因为 `nums[4](8) - 5 > 2`。
  - 数量：`r - l = 0` 个。

**总数 `cnt` = 2 + 1 + 1 + 0 = 4 对。**

### 4. 【代码逐行精读】

```java
public static int smallestDistancePair(int[] nums, int k) {
    int n = nums.length;
    // 1. 必须排序，为了计算距离和使用双指针
    Arrays.sort(nums);
    
    // 2. 二分距离的范围
    // 最小距离是0，最大距离是最大值减最小值
    int l = 0; 
    int r = nums[n - 1] - nums[0];
    int ans = 0;
    
    while (l <= r) {
        // 猜一个中间距离 m
        int m = l + ((r - l) >> 1);
        
        // f 函数：统计有多少对儿的距离 <= m
        int cnt = f(nums, m);
        
        // 3. 二分逻辑
        if (cnt >= k) {
            // 如果 <= m 的数对数量超过了 k，说明 m 可能是第 k 小，或者比它大。
            // 这是一个"达标"的解，记录下来，然后尝试找更小的距离。
            ans = m;
            r = m - 1;
        } else {
            // 数对数量不够 k 个，说明限制得太死了，距离 m 太小了。
            l = m + 1;
        }
    }
    return ans;
}

// 辅助函数：双指针计数
// 统计差值 <= limit 的数对个数
public static int f(int[] arr, int limit) {
    int ans = 0;
    // 窗口：[l ... r]
    // 对于每一个 l，找到最大的 r，使得 arr[r] - arr[l] <= limit
    for (int l = 0, r = 0; l < arr.length; l++) {
        // r 只要不越界，且差值达标，就一直往右扩
        // 注意：这里 r 是单调不回退的！这是 O(N) 的关键
        // 实际上每次 l++ 后，r 不需要回退，因为 l 变大了，arr[r]-arr[l] 只会变小，更满足条件
        // 我们只需要看 r 能不能继续往右走
        while (r + 1 < arr.length && arr[r + 1] - arr[l] <= limit) {
            r++;
        }
        
        // 结算：
        // 以 l 为左端点的有效数对有：(l, l+1), (l, l+2) ... (l, r)
        // 个数正好是 r - l
        ans += r - l;
    }
    return ans;
}
```

### 5. 【难点解析：为什么 `ans += r - l`？】

这是双指针统计对数的一个技巧。

- 当窗口 `[l, r]` 满足条件时，意味着：

  `nums[r] - nums[l] <= limit`。

- 由于数组有序，`r` 左边的数字 `k` ($l < k < r$) 肯定也满足 `nums[k] - nums[l] <= limit`。

- 所以，固定左边是 `l`，右边可以是 `l+1` 到 `r` 中的任意一个。

- 这区间的长度就是 `r - l`。

### 6. 【复杂度分析】

- **时间复杂度**: $O(N \log N + N \log D)$。
  - $N \log N$: 初始排序。
  - $\log D$: 二分查找的次数，其中 $D = \max(nums) - \min(nums)$ (最大距离)。
  - $N$: 每次二分内部调用 `f` 函数，双指针遍历一次数组。
- **空间复杂度**: $O(1)$。
  - 只使用了几个变量（假设排序是原地堆排序，如果是快排则有 $O(\log N)$ 栈空间）。

### 7. 【复习闪卡】

1. **Q: 这道题为什么不能用最小堆（PriorityQueue）做？**
   - A: 最小堆适合找前 K 小，但这里 $N$ 很大，数对总数是 $N^2$ 级别，全部入堆会内存溢出 (OOM) 或超时。
2. **Q: 二分的判定条件 `cnt >= k` 意味着什么？**
   - A: 意味着当前的距离限制 `limit` 比较“宽松”，圈进来了至少 `k` 个数对。真正的第 `k` 小距离一定 $\le$ 当前 `limit`。
3. **Q: `f` 函数中 `r` 指针为什么不需要每次重置？**
   - A: 数组有序。当 `l` 向右移（数值变大），`nums[r] - nums[l]` 会变小。如果旧的 `r` 满足条件，新的 `l` 对应的 `r` 至少也是旧的 `r`，甚至可以更靠右。所以 `r` 单调递增，总复杂度 $O(N)$。

## 思路

这道题是 **二分答案法 (Binary Search on Answer)** 的一个非常巧妙的应用，对应 LeetCode 2141 题。

核心难点在于如何把“随意切换电池”这个复杂的物理过程，转化为一个简单的**数学判定**问题。



### 1. 【一句话核心】

**“削峰填谷，大电池单带，小电池凑单”**：

如果我们假设目标时间是 `T`，那么任何电量大于 `T` 的电池，最多只能贡献 `T` 的电量（因为它不能分身，也不能同时给一台电脑供电超过 `T` 分钟）。剩下的“小电池”则汇入一个总池子，看看够不够填满剩下的电脑。

### 2. 【核心思维转化】

题目说“可以随意切换电池”，这听起来很麻烦，好像要模拟调度。但实际上我们只需要关心 **“能量总量是否足够”**。

**判定逻辑推导 (`f1` 函数)：**

假设我们要挑战的目标时间是 `time`。

1. **大电池 (电量 > `time`)**：
   - 这个电池非常强，它自己就能让一台电脑跑满 `time` 分钟，甚至还有富余。
   - 但是，多出来的电量在这个 `time` 周期内无法给其他电脑用（因为同一时刻它被占用了）。
   - **处理**：让它负责一台电脑，**这台电脑和这个电池都“毕业”了**。我们要解决的问题规模缩小：电脑数减 1 (`num--`)。
2. **小电池 (电量 <= `time`)**：
   - 这个电池不够跑完全程。它变成“碎片能量”，扔进一个公共池子里 (`sum += x`)。
   - 这些碎片能量可以通过“切换”的方式，灵活地分配给剩下的电脑。
3. **最终判定**：
   - 看 **公共池子里的总电量** 是否大于等于 **剩余电脑 $\times$ 目标时间**。
   - 即：`sum >= remaining_num * time`。

### 3. 【图解原理】

假设有 2 台电脑 (`n=2`)，电池为 `[10, 2, 3]`。

总和 15。理论最大平均值 7.5。

**猜测 目标时间 T = 4**：

- 电池 10 (> 4)：**大电池**。负责一台电脑。`num` 剩 1。
- 电池 2 (<= 4)：**小电池**。`sum += 2`。
- 电池 3 (<= 4)：**小电池**。`sum += 3`。
- **结算**：池子 `sum = 5`。剩余需求 `1 * 4 = 4`。
- $5 \ge 4$，**成功！** (T 可以更大)

**猜测 目标时间 T = 6**：

- 电池 10 (> 6)：**大电池**。负责一台电脑。`num` 剩 1。
- 电池 2 (<= 6)：**小电池**。`sum += 2`。
- 电池 3 (<= 6)：**小电池**。`sum += 3`。
- **结算**：池子 `sum = 5`。剩余需求 `1 * 6 = 6`。
- $5 < 6$，**失败！** (T 太大了)

```java
public static long maxRunTime1(int num, int[] arr) {
    long sum = 0;
    for (int x : arr) {
        sum += x;
    }
    long ans = 0;
    
    // 二分范围：
    // L = 0 (或者 1，最小时间)
    // R = sum (理论最大时间，其实 sum/num 更紧凑，但 sum 也没错)
    for (long l = 0, r = sum, m; l <= r;) {
        m = l + ((r - l) >> 1); // 猜一个时间 m
        
        // f1 函数：判断能不能让 num 台电脑都运行 m 分钟
        if (f1(arr, num, m)) {
            ans = m;    // 达标，试试更长的
            l = m + 1;
        } else {
            r = m - 1;  // 不行，缩短时间
        }
    }
    return ans;
}

// 核心判定逻辑
public static boolean f1(int[] arr, int num, long time) {
    // 碎片电量总和
    long sum = 0;
    for (int x : arr) {
        if (x > time) {
            // 【关键点1】大电池单带一路
            // 电量超过 time 的，视为"完美电池"，解决掉一台电脑
            num--; 
        } else {
            // 【关键点2】小电池聚沙成塔
            // 电量不足 time 的，全部贡献给剩下的电脑
            sum += x;
        }
        
        // 【剪枝优化】
        // 如果在遍历过程中，碎片电量已经够剩下的电脑用了，直接返回 true
        if (sum >= (long) num * time) {
            return true;
        }
    }
    // 遍历完了还没返回 true，说明碎片不够分
    return false;
}
```

### 5. 【难点解析：为什么碎片电池可以随意组合？】

这是一个数学上的推论。只要碎片电池的总量足够，且没有任何单一碎片电池超过 `time`（因为超过的已经被我们剔除出去了），那么通过无限次的切换，一定可以填满剩下的矩形区域。

可以想象成把这些小电池里的水倒进一个底面积为 `remaining_num`，高度为 `time` 的大池子里。只要水够多，就一定能填满。

### 6. 【复杂度分析】

- **时间复杂度**: $O(N \cdot \log(\text{Sum}))$.
  - 二分范围是总电量 `Sum`，迭代次数 $\log(\text{Sum})$。
  - 每次 `check` 需要遍历数组 $O(N)$。
- **空间复杂度**: $O(1)$.
  - 只使用了常数个变量。

### 7. 【复习闪卡】

1. **Q: 这道题可以用贪心吗？比如每次用最大的电池？**
   - A: 很难直接贪心模拟。因为切换策略太复杂。转化为“判定是否存在可行解”的**二分答案法**是最佳路径。
2. **Q: 为什么 `x > time` 时 `num--`，多余的电量去哪了？**
   - A: 多余的电量被“浪费”了。因为在 `time` 这段时间内，这块电池一直在给某台电脑供电，它没法分身去帮别人。这就是“短板效应”的反向——**长板受限**。
3. **Q: 二分的上界 `r` 可以优化吗？**
   - A: 可以。`r` 最大不可能超过 `sum / num`（平均分配）。用 `sum` 虽然范围大了一点，但在 $\log$ 级别下对效率影响微乎其微。



## 优化

这是对 **Code05_MaximumRunningTimeOfNComputers** 优化版代码（`maxRunTime2`）的深度解析。

相比于第一版代码，这个版本增加了一个 **“贪心剪枝”** 的逻辑，极大地优化了特定情况下的执行效率。



### 1. 【核心优化点：数学剪枝】

代码中增加的这段逻辑是整个优化的灵魂：

```java
// 核心剪枝逻辑
if (sum > (long) max * num) {
    return sum / num;
}
```

这段代码在问一个问题：**“如果所有电池的电量加起来非常多，多到平均每台电脑能分到的电量，甚至超过了最大的那块电池，会发生什么？”**

#### **推导过程：**

1. **假设**：理论上的平均运行时间是 `Avg = sum / num`。
2. **条件**：如果 `sum > max * num`，那么一定有 `Avg > max`。
3. **含义**：
   - 这意味着我们需要运行的时间 $T$ (即 `Avg`)，比手中 **最大** 的那块电池的电量还要大。
   - 回顾 `f1/f2` 函数的逻辑：只有当 `Battery_Capacity > T` 时，电池才会被“截断/浪费”。
   - 既然 $T > max$，那么对于数组里所有的电池 $x$，都有 $T > x$。
4. **结论**：
   - 在这种情况下，**没有任何一块电池会被“截断”**。
   - **所有电池**都变成了“碎片电量”（`Fragment`）。
   - 既然都是碎片，都能完美地利用，那么总运行时间就是简单的 **总电量 / 电脑数**。
   - 即 `return sum / num`。

#### **直观例子：**

- 2 台电脑 (`num=2`)。
- 电池：`[10, 10, 10]`。`max=10`，`sum=30`。
- 判断：`30 > 10 * 2` (30 > 20) 成立。
- 结果：`30 / 2 = 15` 分钟。
  - 因为目标是 15 分钟，而最大电池只有 10，没有任何电池会被“浪费”，大家都是小电池，拼命凑就行了。

------

### 2. 【二分范围的缩减】

如果上面的 `if` 不成立（即 `sum <= max * num`），说明什么？

说明 **最终的答案一定小于等于 `max`**。

- **旧代码**：二分范围是 `[0, sum]`。`sum` 可能非常大（所有电池之和）。
- **新代码**：二分范围是 `[0, max]`。
  - 既然我们已经排除了 `ans > max` 的情况（由上面的 if 排除），那么答案必然落在 `[0, max]` 区间内。
  - `max` 通常远小于 `sum`，这大大减少了二分查找的次数。

------

### 3. 【代码逻辑图解】

我们把逻辑分为两条路：

- **快车道 (Shortcut)**：
  - **条件**：电量极其充裕 (`Avg > Max_Battery`)。
  - **行为**：直接返回平均值。无视二分。
  - **复杂度**：$O(N)$ (仅遍历一次求和)。
- **慢车道 (Binary Search)**：
  - **条件**：电量一般，受限于最大电池的瓶颈。
  - **行为**：在 `[0, max]` 范围内二分。
  - **复杂度**：$O(N \cdot \log(\text{Max\_Battery}))$。

### 4. 【代码逐行精读】

```java
public static long maxRunTime2(int num, int[] arr) {
    int max = 0;
    long sum = 0;
    // 1. 预处理：找最大值和总和
    for (int x : arr) {
        max = Math.max(max, x);
        sum += x;
    }

    // 2. 【核心优化】数学剪枝 / 贪心判断
    // 如果总电量够分，且平均值比最大的电池还大
    // 说明所有电池都是"小电池"，没有瓶颈
    if (sum > (long) max * num) {
        return sum / num;
    }

    // 3. 二分查找
    // 既然上面的 if 没过，说明答案一定 <= max
    // 范围缩小为 [0, max]，比 [0, sum] 快很多
    int ans = 0;
    for (int l = 0, r = max, m; l <= r;) {
        m = l + ((r - l) >> 1);
        if (f2(arr, num, m)) {
            ans = m;
            l = m + 1;
        } else {
            r = m - 1;
        }
    }
    return ans;
}
```

| **特殊情况处理** | 无，傻傻地二分             | 有，`Avg > max` 时直接返回   |
| **效率**         | 较慢，尤其是电池很多时     | 极快，能直接秒杀很多测试用例 |

**为什么这个优化很重要？**

在 LeetCode 的判题机中，如果测试用例给了一个超级大的 `sum`，普通版虽然能过（是对数复杂度），但常数项较大。而优化版可以直接跳过二分循环，在 $O(N)$ 时间内给出答案，这在工程上是巨大的性能提升。





# 6. 计算等位时间

题目概述：

给定一个数组arr长度为n，表示n个服务员，每服务一个人的时间

## 代码

```java
public class Code06_WaitingTime {
    public static int waitingTime1(int[] arr, int m) {
        PriorityQueue<int[]> heap = new PriorityQueue<>((a,b) -> (a[0] - b[0]));

        int n = arr.length;

        for (int i = 0; i < n; i++) {
            heap.add(new int[]{0, arr[i]});
        }

        for (int i = 0; i < m; i++) {
            int[] cur = heap.poll();
            cur[0] += cur[1];
            heap.add(cur);
        }

        return heap.peek()[0];
    }

    public static int waitingTime2(int[] arr, int w) {

                r = m - 1;
```

## 思路



### 1. 【题目核心场景】

- **输入**：
  - `arr`: 一个数组，表示 $N$ 个服务员的效率（服务一个人需要的时间）。
  - `m`: 目前正在排队的 $m$ 个人。
- **目标**：你是第 $m+1$ 个人，请问你**开始接受服务**的时间点是多久？
- **挑战**：$m$ 可能高达 $10^9$，简单的模拟（排队）会超时。

------

### 2. 【解法一：堆模拟 (直观但慢)】

- **思路**：使用**小根堆**维护每个服务员“下一次空闲的时间点”。
- **流程**：
  1. 每次弹出堆顶（最早空闲的人）。
  2. 安排一个人给他，更新他的空闲时间：`cur_time += efficiency`。
  3. 重复 $m$ 次。
- **瓶颈**：时间复杂度是 $O(m \cdot \log N)$。当 $m$ 很大时，循环次数太多，跑不动。
- **作用**：仅用于验证小数据，或者当 $m$ 很小的时候。

------

### 3. 【解法二：二分答案法 (最优解)】

**核心思维转换**：

不要去问“第 $m$ 个人在什么时候被服务”，而是反过来问：“**如果给定时间 $T$，所有服务员加起来一共能让多少人开始接受服务？**”

#### **A. 核心公式与物理意义**

这是本题最关键的理解点。给定时间 `time`，服务员 $i$ 能接待的人数（开启的窗口数）是：

$$\text{count} = (\text{time} / \text{arr}[i]) + 1$$

- **`time / arr[i]`**：代表在 `time` 之前，已经**完整结束**的服务轮数。
- **`+1`**：代表 **$T=0$ 时刻开启的那一轮**。哪怕这一轮还没结束，只要 `time >= 0`，这一轮的名额就已经被占用了。
- **总含义**：在 `time` 时刻截止时，该服务员总共允许了多少人“坐下”。

**图解演示**：

假设服务员效率是 3 (`arr[i]=3`)，当前时间猜的是 7 (`time=7`)。

- **0时刻**：第1人坐下（开始）。
- **3时刻**：第2人坐下（开始）。
- **6时刻**：第3人坐下（开始）。
- **7时刻**：时间截止。
- **计算**：$7/3 + 1 = 2 + 1 = 3$ 人。
- **结论**：在时刻 7，虽然第 3 个人还没服务完（他要到 9 才完），但他已经“进去了”，不再属于“等待队列”。

#### **B. 二分策略**

利用**单调性**：时间给得越长，能接待的人越多。

1. **范围**：
   - $L = 0$。
   - $R = \min(arr) \times m$ (最坏情况：让最快的人独自干完)。
2. **判断 (`check` 函数)**：
   - 计算在 `mid` 时间内，所有人能接待的总人数 `capacity`。
   - **如果 `capacity >= m + 1`**：说明在这个时间点，连第 $m+1$ 个（你）都已经坐下了。$\rightarrow$ 记录答案，尝试更早的时间 (`right` 左移)。
   - **如果 `capacity < m + 1`**：说明时间不够，你还在门外站着。$\rightarrow$ 增加时间 (`left` 右移)。

------

### 4. 【代码精读】

Java

```
// 最优解：二分答案法
public static int waitingTime2(int[] arr, int w) { // w 就是 m
    int min = Integer.MAX_VALUE;
    for (int x : arr) min = Math.min(min, x); // 找到效率最高的服务员
    
    // 二分时间轴
    // 注意：如果 w 很大，min * w 可能会溢出 int，面试时建议用 long
    int l = 0;
    int r = min * w; 
    int ans = 0;
    
    while (l <= r) {
        int m = l + ((r - l) >> 1); // 猜一个时间 m
        
        // f(arr, m) 返回 m 时间内能让多少人"开始服务"
        // 我们的目标是第 w+1 个人也能开始
        if (f(arr, m) >= w + 1) {
            ans = m;    // 时间充裕，试试能不能更早
            r = m - 1;
        } else {
            l = m + 1;  // 时间不够，得加时
        }
    }
    return ans;
}

// 核心计数逻辑
public static int f(int[] arr, int time) {
    int ans = 0;
    for (int num : arr) {
        // 这里的 +1 是核心
        // 代表 0 时刻就开始的那一单
        ans += (time / num) + 1;
    }
    return ans;
}
```

------

### 5. 【复杂度与细节分析】

- **时间复杂度**：$O(N \cdot \log(\text{Range}))$。
  - Range 大约是 $m \times \min(arr)$。
  - 即便 $m=10^9$，$\log(10^9) \approx 30$。计算量非常小，完全能过。
- **空间复杂度**：$O(1)$。
- **易错点（溢出陷阱）**：
  - **问题**：题目中 $m$ 最大 $10^9$。如果 $min=10$，那么 $min \times m = 10^{10}$，这超过了 Java `int` 的最大值 ($2 \times 10^9$)。
  - **修正**：在实际面试或生产环境中，二分的 `l`, `r`, `m` 变量以及 `f` 函数的返回值，**必须使用 `long` 类型**，否则会因为溢出导致死循环或错误答案。

------

### 6. 【复习闪卡】

1. **Q: 为什么堆模拟法不行？**
   - A: 因为它要一步一步模拟。当 $m$ 很大时，循环次数太多，超时。
2. **Q: 为什么公式是 `(time / arr[i]) + 1` 而不是 `time / arr[i]`？**
   - A: 因为 0 时刻不需要等待，直接开始服务。`+1` 补的是初始的那一次。
3. **Q: 二分判断条件为什么是 `>= w + 1`？**
   - A: 因为我们要找的是“第 $w+1$ 个人”开始服务的时间。只要总容量能覆盖到 $w+1$，就说明轮到他了。



# 7. 刀砍毒杀怪兽问题

题目概述：

怪兽的初始血量是一个整数hp，给出每一回合刀砍和毒杀的数值cuts和poisons
第i回合如果用刀砍，怪兽在这回合会直接损失cuts[i]的血，不再有后续效果
第i回合如果用毒杀，怪兽在这回合不会损失血量，但是之后每回合都损失poisons[i]的血量
并且你选择的所有毒杀效果，在之后的回合都会叠加
两个数组cuts、poisons，长度都是n，代表你一共可以进行n回合
每一回合你只能选择刀砍或者毒杀中的一个动作
如果你在n个回合内没有直接杀死怪兽，意味着你已经无法有新的行动了
但是怪兽如果有中毒效果的话，那么怪兽依然会在血量耗尽的那回合死掉
返回至少多少回合，怪兽会死掉
数据范围 : 
1 <= n <= 10^5
1 <= hp <= 10^9
1 <= cuts[i]、poisons[i] <= 10^9

```java
public class Code07_CutOrPoison {
    public static int fast1(int[] cuts, int[] poisons, int hp) {
        int sum = 0;
        for (int num : poisons) {
            sum += num;
        }
        int[][][] dp = new int[cuts.length][hp + 1][sum + 1];
        return f1(cuts, poisons, 0, hp, 0, dp);
    }

    // 不做要求
    public static int f1(int[] cuts, int[] poisons, int i, int r, int p, int[][][] dp) {
        r -= p;
        if (r <= 0) {
            return i + 1;
        }
        if (i == cuts.length) {
            if (p == 0) {
                return Integer.MAX_VALUE;
            } else {
                return cuts.length + 1 + (r + p - 1) / p;
            }
        }
        if (dp[i][r][p] != 0) {
            return dp[i][r][p];
        }
        int p1 = r <= cuts[i] ? (i + 1) : f1(cuts, poisons, i + 1, r - cuts[i], p, dp);
        int p2 = f1(cuts, poisons, i + 1, r, p + poisons[i], dp);
        int ans = Math.min(p1, p2);
        dp[i][r][p] = ans;
        return ans;
    }

    public static int fast2(int[] cuts, int[] poisons, int hp) {
        int ans = Integer.MAX_VALUE;

        for (int l = 1, r = hp + 1, m; l <= r; ) {
            m = l + ((r-l) >> 1);

            if (f(cuts, poisons, hp, m)) {
                ans = m;
                r = m - 1;
            }else {
                l = m + 1;
            }
        }

        return ans;
    }

    public static boolean f(int[] cuts, int[] posions, long hp, int limit) {
        int n = Math.min(cuts.length, limit);

        for (int i = 0, j = 1; i < n; i++, j++) {
            hp -= Math.max((long) cuts[i], (long) (limit - j) * (long) posions[i]);

            if (hp <= 0) {
                return true;
            }
        }

        return false;
    }
```

## 思路

### 1. 【核心痛点与破局点】

- **常规思维的痛点（为什么想用 DP？）**：

  在任意一回合，如果你选了“毒杀”，怪兽本回合不掉血，但未来的**每一回合**都会掉血。这种“当前选择影响未来状态”的机制，看起来有着极强的后效性，很容易让人陷入必须要用 DP 一步步推导状态的泥潭。

- **破局点：二分答案法（固定生命周期）**：

  怪兽死掉的回合数具备**单调性**。如果怪兽在 10 个回合内必定能死，那么给它 11 个回合它更是死透了；如果它在 5 个回合内死不了，那 4 个回合也绝对没戏。

  因此，我们可以**二分猜一个总回合数 `limit`**。

### 2. 【封神之笔：上帝视角的贪心（f 函数）】

一旦我们通过二分**固定了总回合数 `limit`**，原本复杂的后效性瞬间就瓦解了！我们可以开启“上帝视角”，独立结算每一回合的收益。

假设我们现在要在限定的 `limit` 回合内打出最高伤害：

- **第 $j$ 回合（$j$ 从 1 开始计算）**：
  - 如果选**刀砍**：在这个 `limit` 的生命周期内，它总共贡献的伤害就是 `cuts[i]`（只有一刀的直接伤害）。
  - 如果选**毒杀**：怪兽在这回合不掉血，但在剩下的 `limit - j` 个回合里，每回合都会掉 `poisons[i]` 的血。所以在这个生命周期内，它总共贡献的伤害是 `poisons[i] * (limit - j)`。

**贪心策略**：

既然总回合数已经固定是 `limit` 了，各回合的决策实际上变成了**相互独立**的！

我们只需要在第 $j$ 回合，比较 `cuts[i]` 和 `poisons[i] * (limit - j)` 哪个大，就选哪个。把所有回合的最大期望伤害累加，看能不能超过怪兽的初始血量 `hp` 即可。

### 3. 【二分边界分析】

- **下界 `l`**：1 回合（最快一回合秒杀）。
- **上界 `r`**：`hp + 1` 回合。
  - 为什么是 `hp + 1`？最极端的非零伤害是每回合只打 1 滴血，总共需要 `hp` 回合。所以怪兽存活的极限回合数绝对不会超过 `hp`。`hp + 1` 是一个绝对安全的上限。

### 4. 【代码逐行精读 (最优解 fast2)】

```java
public static int fast2(int[] cuts, int[] poisons, int hp) {
    int ans = Integer.MAX_VALUE;
    // 二分范围：[1, hp + 1]
    for (int l = 1, r = hp + 1, m; l <= r;) {
        // m 中点：代表我们当前猜测的"必须在 m 回合内杀死怪兽"
        m = l + ((r - l) >> 1);
        
        // 校验：在限定 m 回合内，我们能打死它吗？
        if (f(cuts, poisons, hp, m)) {
            // 能打死！说明回合数够用，甚至可能给多了。
            // 记录答案，并尝试去左边找更少的回合数
            ans = m;
            r = m - 1;
        } else {
            // 打不死！说明 m 回合太短了，伤害还没打够。
            // 去右边找更长的回合数
            l = m + 1;
        }
    }
    return ans;
}

// 核心贪心校验函数
// 返回在限制 limit 回合内，能否把 hp 打到 0 及以下
public static boolean f(int[] cuts, int[] posions, long hp, int limit) {
    // 怪兽死之前，我们最多只能行动 limit 次。
    // 同时，我们的技能数组只有 cuts.length 这么长，打完就没牌了。
    // 所以实际能进行决策的回合数 n 是这两者的最小值。
    int n = Math.min(cuts.length, limit);
    
    // i 是数组下标 (0 开始)，j 是真实回合数 (1 开始)
    for (int i = 0, j = 1; i < n; i++, j++) {
        
        // 【核心公式】
        // 刀砍伤害: (long) cuts[i]
        // 毒杀在剩余回合(limit - j)里的总伤害: (long) (limit - j) * (long) posions[i]
        // 贪心：谁大选谁，直接从 hp 中扣除
        hp -= Math.max((long) cuts[i], (long) (limit - j) * (long) posions[i]);
        
        // 如果中途怪兽血量已经 <= 0，提前宣布胜利
        if (hp <= 0) {
            return true;
        }
    }
    // 所有回合决策完了，怪兽还有血，说明 limit 回合内杀不死
    return false;
}
```

### 5. 【复杂度与避坑指南】

- **时间复杂度**：$O(n \log(hp))$。二分次数是 $\log(hp)$ 级别，每次二分调用一次 `f` 函数，`f` 函数内部只需遍历 $O(n)$。对比 DP 方法的时间复杂度（指数级/多维乘积），这是降维打击。

- **空间复杂度**：$O(1)$。

- **⚠️ 致命陷阱（防溢出）**：

  题目中 `limit` 最大可达 `10^9`，`poisons[i]` 最大也可达 `10^9`。

  所以在 `f` 函数中算毒杀总伤害时，`limit - j` 和 `poisons[i]` **必须强转成 `long` 再相乘**。如果直接 `(limit - j) * posions[i]`，会立刻触发 `int` 溢出变成负数，导致永远打不死怪兽。

### 6. 【复习闪卡】

1. **Q: 为什么毒杀的伤害可以一次性用 `poisons[i] \* (limit - j)` 计算出来？**
   - A: 因为我们二分的时候已经预先“钦定”了战斗会在第 `limit` 回合结束。既然寿命已定，这口毒药能在它有生之年发作多少次就是确定的，直接用乘法算出总收益，从而化解了动态规划的状态转移。
2. **Q: 为什么 `f` 函数里的循环上限是 `Math.min(cuts.length, limit)`？**
   - A: 如果 `limit < cuts.length`，说明怪兽在我们的技能没用完前就死了，我们只关心前 `limit` 步的决策。如果 `limit > cuts.length`，说明我们把牌打光了怪兽还没死，剩下的时间只能干等着毒药发作，此时没有任何“新动作”可以决策，所以循环到 `cuts.length` 即可。
