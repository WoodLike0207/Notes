# 1. 按奇偶排序数组II

测试链接 : https://leetcode.cn/problems/sort-array-by-parity-ii/



## 代码

```java
public class Code01_SortArrayByParityII {
    public int[] sortArrayByParityII(int[] nums) {
        int n = nums.length;

        for (int even = 0, odd = 1; even < n && odd < n; ) {
            if ((nums[n - 1] & 1) == 1) {
                swap(nums, odd, n-1);
                odd += 2;
            }else {
                swap(nums,even,n-1);
                even += 2;
            }
        }

        return nums;
    }

    public static void swap(int[] nums, int i, int j) {
        int tmp = nums[i];
        nums[i] = nums[j];
        nums[j] = tmp;
    }
}
```



## 思路

这道题是 **双指针 (Two Pointers)** 的经典应用，但这一个版本的代码写法非常独特，采用了一种 **“末尾发牌”** 的策略。



### 1. 【一句话核心】

**“发牌员思维”**：把数组的最后一个位置 `nums[n-1]` 当作“中转站”或“手牌”，如果是奇数就发给 `odd` 指针位置，如果是偶数就发给 `even` 指针位置，并在发牌的同时把对方位置上的“未知牌”换回来继续处理。

### 2. 【核心逻辑解析】

通常这道题的解法是“寻找不匹配的一对进行交换”，但你的代码采用了一种更激进的 **交换填坑** 逻辑：

- **`even` 指针**：永远指向下一个需要填入 **偶数** 的位置（初始 0，步长 2）。
- **`odd` 指针**：永远指向下一个需要填入 **奇数** 的位置（初始 1，步长 2）。
- **`nums[n-1]` (关键)**：它是当前的“待分配元素”。
  - **如果它是奇数**：
    1. 说明它应该去 `odd` 的位置。
    2. 于是我们把它和 `nums[odd]` 交换。
    3. 交换后，`odd` 位置坐实了是奇数，`odd` 指针前移 (`odd += 2`)。
    4. 换回来的那个数（原 `nums[odd]`）到了 `n-1` 位置，下一轮循环继续判断它。
  - **如果它是偶数**：
    1. 说明它应该去 `even` 的位置。
    2. 于是我们把它和 `nums[even]` 交换。
    3. 交换后，`even` 位置坐实了是偶数，`even` 指针前移 (`even += 2`)。

### 3. 【图解原理】

假设数组 `[4, 2, 5, 7]`，`n=4`。

**详细推演：**

- **Init**: `even=0`, `odd=1`. 待处理：`nums[3] = 7` (奇)。
- **Round 1**: `7` 是奇数 $\rightarrow$ 发给 `odd` (idx 1)。
  - 交换 `nums[3]` 和 `nums[1]` (也就是 7 和 2 互换)。
  - 数组变 `[4, 7, 5, 2]`。`odd` 变为 3。
  - *注：现在 idx 1 搞定了，待处理变成了换回来的 2。*
- **Round 2**: 待处理 `nums[3] = 2` (偶)。
  - 交换 `nums[3]` 和 `nums[0]` (也就是 2 和 4 互换)。
  - 数组变 `[2, 7, 5, 4]`。`even` 变为 2。
- **Round 3**: 待处理 `nums[3] = 4` (偶)。
  - 交换 `nums[3]` 和 `nums[2]` (也就是 4 和 5 互换)。
  - 数组变 `[2, 7, 4, 5]`。`even` 变为 4。
- **End**: `even` 越界，循环结束。结果正确。

### 4. 【代码逐行精读】

```java
public class Code01_SortArrayByParityII {
    public int[] sortArrayByParityII(int[] nums) {
        int n = nums.length;

        // even: 偶数位的进度条 (0, 2, 4...)
        // odd:  奇数位的进度条 (1, 3, 5...)
        // 循环条件：只要偶数位或奇数位还有一个没填满，就继续
        for (int even = 0, odd = 1; even < n && odd < n; ) {
            
            // 检查数组末尾 nums[n-1] 的奇偶性
            // (x & 1) == 1 等价于 x % 2 != 0，判断奇数效率更高
            if ((nums[n - 1] & 1) == 1) { 
                // 如果是奇数，把它发配到 odd 位置
                swap(nums, odd, n-1);
                // odd 位置这就填好了，进度条前进
                odd += 2;
            } else {
                // 如果是偶数，把它发配到 even 位置
                swap(nums, even, n-1);
                // even 位置这就填好了，进度条前进
                even += 2;
            }
        }

        return nums;
    }

    // 标准交换函数
    public static void swap(int[] nums, int i, int j) {
        int tmp = nums[i];
        nums[i] = nums[j];
        nums[j] = tmp;
    }
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N)$。
  - 每次循环，要么 `odd` 加 2，要么 `even` 加 2。总共只遍历一遍数组。
- **空间复杂度**: $O(1)$。
  - 原地交换，只用了几个变量，没有额外数组。

### 6. 【对比与思考】

- **常规解法 vs 本解法**：
  - **常规解法**：通常是 `even` 找错的，`odd` 找错的，两个都找到错的就互换。
  - **本解法 (末尾交换)**：不需要同时找两个错的。利用数组最后一个位置作为 buffer，不管是啥都换到它该去的地方，把未知数换回来接着处理。代码写起来往往更简洁，不需要嵌套 `while`。
- **易错点**：
  - 循环条件必须是 `even < n && odd < n`。虽然理论上填满一个另一个也就满了，但为了保险起见，防止越界。
  - 位运算优先级：`(nums[n-1] & 1)` 的括号不能省，因为 `==` 优先级比 `&` 高。如果不加括号就变成了 `nums[n-1] & (1 == 1)`，逻辑完全变了。



# 2. 寻找重复数

测试链接 : https://leetcode.cn/problems/find-the-duplicate-number/



## 代码

```java
public class Code02_FindTheDuplicateNumber {
    public int findDuplicate(int[] nums) {
        if (nums == null || nums.length < 2) {
            return -1;
        }

        int slow = nums[0];
        int fast = nums[nums[0]];

        while (slow != fast) {
            slow = nums[slow];
            fast = nums[nums[fast]];
        }

        fast = 0;

        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }

        return slow;
    }
}
```



## 思路

这道题是 **快慢指针 (Floyd's Tortoise and Hare)** 算法的教科书级应用，也是面试中 **“数组模拟链表”** 的经典题目。

### 1. 【一句话核心】

**“数组当链表，判圈找入口”**：

虽然是数组，但因为数值范围的限制 ($1 \sim n$)，我们可以把数组下标看作当前节点，数组的值看作 `next` 指针。因为有重复数，意味着**多个下标指向了同一个值**，这在链表视角里就形成了一个**环**。重复的那个数，就是环的**入口节点**。

### 2. 【核心转化逻辑：为什么是链表？】

- **节点 (Node)**: 数组的**下标** $i$。
- **指针 (Next Pointer)**: 数组的**值** $nums[i]$。
  - 例如 `nums[0] = 3`，意味着从节点 0 指向节点 3。
- **为什么一定有环？**
  - 数组大小 $n+1$，数值范围 $1 \sim n$。
  - 这就好比 $n+1$ 个点，只有 $n$ 个坑位可去。根据**鸽巢原理**，必然有两个点指向了同一个坑位。
  - 在这个“链表”图中，这就表现为环。而那个被多个人指向的点（重复数），就是环的入口。
- **为什么从下标 0 开始？**
  - 因为数值范围是 $1 \sim n$，**没有任何一个位置的值是 0**。
  - 这意味着没有任何指针指向下标 0。
  - 所以下标 0 是天然的**头节点 (Head)**，从这里出发一定能走进环里，而不会在环里打转出不来。

### 3. 【算法流程：弗洛伊德判圈法】

该算法分为两个阶段：

**Phase 1: 快慢指针相遇 (Detect Cycle)**

- **Slow**: 每次走一步 `slow = nums[slow]`。
- **Fast**: 每次走两步 `fast = nums[nums[fast]]`。
- 因为有环，快指针最终一定会追上慢指针（套圈）。

**Phase 2: 寻找入口 (Find Entry)**

- 当两者相遇时，保持 `slow` 在相遇点不动。
- 将 `fast` **重置回起点 (下标 0)**。
- 然后两个指针**每次都只走一步**。
- **数学定理保证**：它们再次相遇的位置，一定是环的**入口**（即重复数）。

### 4. 【图解原理】

假设 `nums = [1, 3, 4, 2, 2]`。

映射关系：$0 \to 1$, $1 \to 3$, $2 \to 4$, $3 \to 2$, $4 \to 2$。

**详细推演：**

1. **Phase 1 (相遇)**:
   - Init: `slow=1` (nums[0]), `fast=3` (nums[nums[0]]).
   - Step 1: `slow`=$3$ (nums[1]), `fast`=$4$ (nums[2] -> nums[4]).
   - Step 2: `slow`=$2$ (nums[3]), `fast`=$2$ (nums[4] -> nums[2]).
   - **相遇！** 相遇点是数值 **2** (下标3或4)。
2. **Phase 2 (找入口)**:
   - Reset: `fast` 设为 **0** (起点)。`slow` 保持在 **2** (注意这里 slow 是下标/值在这个题里混用了，严谨说是停留在相遇位置)。
   - Step 1:
     - `fast` 走一步: $0 \to 1$。
     - `slow` 走一步: $2 \to 4$。
   - Step 2:
     - `fast` 走一步: $1 \to 3$。
     - `slow` 走一步: $4 \to 2$。
   - Step 3:
     - `fast` 走一步: $3 \to 2$。
     - `slow` 走一步: $2 \to 4$ (这里看代码逻辑，slow 其实是数值)。
   - *(注：这道题的具体数值模拟比较绕，因为值和下标互为映射，但核心逻辑不变：**相遇后一个回起点，同步走，必相遇于入口**)*。

### 5. 【代码逐行精读】

```java
public static int findDuplicate(int[] nums) {
    if (nums == null || nums.length < 2) {
        return -1;
    }
    
    // --- 阶段 1：快慢指针找相遇点 ---
    // slow 走一步：nums[0]
    int slow = nums[0];
    // fast 走两步：nums[nums[0]]
    int fast = nums[nums[0]];
    
    // 只要没相遇就一直走
    while (slow != fast) {
        slow = nums[slow];           // 走 1 步
        fast = nums[nums[fast]];     // 走 2 步
    }
    
    // --- 阶段 2：重置快指针，同速寻找入口 ---
    // fast 回到起点 (下标 0)
    fast = 0;
    while (slow != fast) {
        fast = nums[fast]; // 走 1 步
        slow = nums[slow]; // 走 1 步
    }
    
    // 再次相遇的点，就是环的入口，也就是重复数
    return slow;
}
```

### 6. 【复杂度分析】

- **时间复杂度**: $O(N)$。两个指针在环里转圈，次数与链表长度线性相关。
- **空间复杂度**: $O(1)$。只用了 `slow` 和 `fast` 两个变量，符合题目“不修改数组、常量空间”的苛刻要求。

### 7. 【复习闪卡】

1. **Q: 为什么可以用快慢指针解决数组重复数问题？**
   - A: 因为数值范围 $[1, n]$ 构成了合法的下标跳转，重复数意味着多个下标指向同一个位置，形成了**环**。问题转化为链表找环入口。
2. **Q: Phase 2 为什么要把 `fast` 放回 0？**
   - A: 这是 Floyd 判圈算法的数学结论。$Head$ 到 $Entry$ 的距离，等于 $MeetingPoint$ 到 $Entry$ 的距离（在环内绕圈意义下）。
3. **Q: 为什么 `fast` 一开始是 `nums[nums[0]]` 而不是 `0`？**
   - A: 类似于 `do-while` 逻辑。如果不先动一下，一开始 `slow == fast` (都是起点) 循环就进不去了。先动一步再判断更方便。



# 3. 接雨水

测试链接 : https://leetcode.cn/problems/trapping-rain-water/



## 代码

```java
public class Code03_TrappingRainWater {
    public int trap1(int[] height) {
        int n = height.length;
        int[] lmax = new int[n];
        int[] rmax = new int[n];

        lmax[0] = height[0];
        for (int i = 1; i < n ; i++) {
            lmax[i] = Math.max(lmax[i - 1], height[i]);
        }

        rmax[n-1] = height[n-1];
        for (int i = n - 2; i >= 0; i--) {
            rmax[i] = Math.max(rmax[i + 1], height[i]);
        }

        int ans = 0;

        for (int i = 1; i < n -1; i++) {
            ans += Math.max(0, Math.min(lmax[i - 1], rmax[i+1]) - height[i]);
        }

        return ans;
    }

    public int trap2(int[] height) {
        int l = 1, r = height.length - 2, lmax = height[0], rmax = height[height.length - 1];
        int ans = 0;
        while (l <= r) {
            if (lmax <= rmax) {
                ans += Math.max(0, lmax - height[l]);
                lmax = Math.max(lmax, height[l++]);
            }else {
                ans += Math.max(0, rmax - height[r]);
                rmax = Math.max(rmax, height[r--]);
            }
        }
        return ans;
    }
}
```



## 思路

这道题是 **数组与双指针** 领域的“皇冠明珠”，也是大厂面试中出现频率最高的题目之一（LeetCode 42）。

### 1. 【物理核心：木桶效应】

一个位置 `i` 能接多少水，取决于**它左边最高的柱子** (`lmax`) 和 **它右边最高的柱子** (`rmax`) 中**较矮**的那一个。

- **公式**：

  $$Water[i] = \min(lmax, rmax) - height[i]$$

  *(如果结果小于0，则为0)*

- **直观理解**：只有左右两边都有比自己高的墙，中间才能存住水。水位高度由两边“短板”决定。

------

### 2. 【解法一：辅助数组法 (预处理)】

**思路**：

既然每个位置都需要知道它左边和右边的最大值，那我们就先把这些信息算出来存好。

- **步骤**：
  1. **左侧扫描**：生成 `lmax[]` 数组，`lmax[i]` 表示 `0...i` 范围内的最大高度。
  2. **右侧扫描**：生成 `rmax[]` 数组，`rmax[i]` 表示 `i...n-1` 范围内的最大高度。
  3. **计算**：遍历每个柱子，取 `min(lmax[i-1], rmax[i+1]) - nums[i]` 累加。
- **复杂度**：
  - 时间：$O(N)$ (三次遍历)。
  - 空间：$O(N)$ (需要额外的数组空间)。

------

### 3. 【解法二：双指针法 (最优解)】

**思路**：

这是对辅助数组法的空间优化。我们真的需要知道每一个位置确切的 `rmax` 吗？

**不！我们只需要知道“短板”在哪。**

- **核心逻辑（PK 逻辑）**：

  维护两个指针 `l` (左) 和 `r` (右)，以及两个变量 `lmax` (左边目前遇到的最大值) 和 `rmax` (右边目前遇到的最大值)。

  - **如果 `lmax < rmax`**：
    - 说明对于 `l` 位置来说，左边的墙 (`lmax`) 肯定是**短板**。
    - **为什么？** 因为 `rmax` 只是右边目前的最高，右边真实的最高墙只可能 $\ge rmax$。既然 `lmax` 已经比 `rmax` 小了，那它一定比右边真实的最高墙也小。
    - **决策**：结算 `l` 位置的水量，然后 `l` 右移。
  - **如果 `lmax >= rmax`**：
    - 说明对于 `r` 位置来说，右边的墙 (`rmax`) 肯定是**短板**。
    - **决策**：结算 `r` 位置的水量，然后 `r` 左移。

### 4. 【代码逐行精读 (解法二)】

```java
public static int trap2(int[] nums) {
    // 左右指针初始化：跳过 0 和 n-1，因为两端的柱子绝对没法接水
    int l = 1, r = nums.length - 2;
    
    // 初始化左右两边的"墙"的高度
    int lmax = nums[0];
    int rmax = nums[nums.length - 1];
    
    int ans = 0;
    
    while (l <= r) {
        // 【核心判断】谁小结算谁
        if (lmax <= rmax) {
            // 左墙更矮，瓶颈在左边
            // 1. 如果 l 位置比 lmax 矮，能接水：lmax - nums[l]
            // 2. 如果 l 位置比 lmax 高，接不了水(结果为负)，但 Math.max(0,...) 会处理
            //    同时更新 lmax 供后面使用
            ans += Math.max(0, lmax - nums[l]);
            
            // 更新 lmax，并移动指针
            lmax = Math.max(lmax, nums[l++]);
        } else {
            // 右墙更矮，瓶颈在右边
            ans += Math.max(0, rmax - nums[r]);
            
            // 更新 rmax，并移动指针
            rmax = Math.max(rmax, nums[r--]);
        }
    }
    return ans;
}
```

### 5. 【易错点 / 细节】

1. **边界处理**：
   - `l` 从 `1` 开始，`r` 从 `n-2` 开始。这是因为下标 `0` 和 `n-1` 的位置作为边界，水一定会流走，不可能存水。
2. **`lmax` 和 `rmax` 的更新时机**：
   - 代码中有两种写法：先更新 max 再算水，或者先算水再更新 max。
   - 本代码采用的是：**使用当前的 max 结算当前格，然后用当前格去更新 max 给下一格用**。这是很顺畅的逻辑。
3. **`Math.max(0, ...)`**：
   - 虽然逻辑上只有低洼处存水，但代码中为了简洁，包含了 `lmax < nums[l]` (即当前柱子比墙高) 的情况。此时 `lmax - nums[l]` 是负数，`Math.max(0, ...)` 将其变为 0，随后更新 `lmax`。

### 6. 【复习闪卡】

1. **Q: 接雨水的核心原理是什么？**
   - A: 木桶效应（短板原理）。当前位置的水量 = $\min(\text{左边最高}, \text{右边最高}) - \text{当前高度}$。
2. **Q: 为什么双指针法可以优化掉辅助数组？**
   - A: 因为我们计算水量只需要知道“较小”的那个高度。双指针通过比较 `lmax` 和 `rmax`，可以确定哪一侧是短板，从而直接结算该侧的水量，无需知道另一侧确切的最大值。
3. **Q: 双指针法的时间和空间复杂度？**
   - A: 时间 $O(N)$，空间 $O(1)$。



# 4. 救生艇

 测试链接 : https://leetcode.cn/problems/boats-to-save-people/



## 代码

```java
public class Code04_BoatsToSavePeople {
    public int numRescueBoats(int[] people, int limit) {
        Arrays.sort(people);
        int ans = 0;
        int l = 0, r = people.length - 1;
        int sum = 0;

        while (l <= r) {
            sum = l == r ? people[l] : people[l] + people[r];

            if (sum > limit) {
                r--;
            }else {
                l++;
                r--;
            }

            ans++;
        }

        return ans;
    }
}
```



## 思路

这道题是 **贪心算法 (Greedy) + 双指针** 的典型应用。解决这道题的关键在于理解题目中的两个限制：**“重量限制”** 和 **“人数限制（最多2人）”**。



### 1. 【一句话核心】

**“最重的带最轻的”**：

为了让船的数量最少，我们要尽可能让每艘船都坐满 2 个人。

策略是：每次都让**当前最重的人**尝试带上**当前最轻的人**。如果带不动，最重的人只能独自坐船走（因为连最轻的都带不动，其他人更带不动）。

### 2. 【核心策略推导】

1. **为什么必须排序？**
   - 贪心策略依赖于我们要随时找到“当前最重”和“当前最轻”的人。只有排序后，首尾指针才能分别代表轻重极值。
2. **贪心选择逻辑**：
   - 设 `L` 指向最轻的人，`R` 指向最重的人。
   - **情况 A：`people[L] + people[R] <= limit`**
     - 最重的人能带上最轻的人。太好了，两人共用一艘船。
     - **操作**：`L++` (轻的走了)，`R--` (重的走了)，`ans++`。
   - **情况 B：`people[L] + people[R] > limit`**
     - 最重的人太重了，连最轻的人都带不动。
     - 这意味者 `people[R]` 无法与剩下任何人配对（因为 `people[L]` 已经是体重最小的了）。
     - **操作**：`R--` (重的只能自己坐一艘船走)，`L` 不动 (轻的留给下一个较重的人带)，`ans++`。

### 3. 【图解演示】

假设 `people = [3, 2, 2, 1]`, `limit = 3`。

1. **排序**：`[1, 2, 2, 3]`。
2. **Round 1**:
   - `L`指向 1 (值1), `R`指向 3 (值3)。
   - `1 + 3 = 4 > 3`。带不动。
   - **决策**：3号 (R) 独自走。`R` 左移。`ans = 1`。
3. **Round 2**:
   - `L`指向 0 (值1), `R`指向 2 (值2)。
   - `1 + 2 = 3 <= 3`。能带上！
   - **决策**：2号 (R) 带上 1号 (L) 一起走。`L` 右移，`R` 左移。`ans = 2`。
4. **Round 3**:
   - `L`指向 1, `R`指向 1 (指向同一个值 2)。
   - `L == R`，只剩一个人。
   - **决策**：自己坐船走。`ans = 3`。

### 4. 【代码逐行精读】

```java
public static int numRescueBoats(int[] people, int limit) {
    // 1. 贪心的前提是排序
    Arrays.sort(people);
    
    int ans = 0;
    int l = 0;
    int r = people.length - 1;
    int sum = 0;
    
    // 2. 双指针向中间靠拢
    while (l <= r) {
        // 特判：如果 l==r，说明只剩一个人了，sum 就是他自己的体重
        // 否则 sum 是 一轻 + 一重
        sum = l == r ? people[l] : people[l] + people[r];
        
        // 3. 核心贪心判断
        if (sum > limit) {
            // 超重了：最重的人(r)带不动最轻的人(l)。
            // r 只能自己走，l 留在岸上等下一个机会。
            r--;
        } else {
            // 没超重：最重的人(r)成功带上了最轻的人(l)。
            // 两个人一起走。
            l++;
            r--;
        }
        // 无论是一起走还是单独走，都消耗了一艘船
        ans++;
    }
    return ans;
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N \log N)$。
  - 虽然双指针遍历是 $O(N)$，但排序的开销是 $O(N \log N)$，这是主导项。
- **空间复杂度**: $O(1)$ 或 $O(\log N)$。
  - 取决于排序算法的实现（Java 的 `Arrays.sort` 对于基本类型使用双轴快速排序，会有栈空间开销）。代码本身只用了几个变量。

### 6. 【易错点 / 面试考察】

1. **为什么是 $O(N \log N)$ 而不是 $O(N)$？**
   - 很多同学看到双指针就答 $O(N)$，忽略了这题必须先排序。
2. **如果题目限制每艘船不限人数，只要总重 < limit 怎么办？**
   - 那就变成了一个 **装箱问题 (Bin Packing Problem)**，属于 NP-Hard 问题，无法用简单的双指针贪心解决，通常需要回溯或近似算法。这题“最多2人”的限制至关重要。
3. **循环条件 `l <= r`**：
   - 必须包含 `=`。当 `l == r` 时，表示岸上还剩最后一个人，他也需要一艘船。

### 7. 【复习闪卡】

- **Q: 救生艇问题的核心贪心策略是什么？**
  - A: **最大匹配最小**。最重的人如果能带最轻的就一起走，带不动就自己走。
- **Q: 如果不排序能做吗？**
  - A: 不能高效地做。不排序无法快速找到当前的“最重”和“最轻”，无法执行贪心策略。
- **Q: 这道题的关键限制条件是什么？**
  - A: 每艘船**最多坐两人**。没有这个限制就不能用双指针。





# 5. 盛最多水的容器

测试链接 : https://leetcode.cn/problems/container-with-most-water/



## 代码

```java
public class Code05_ContainerWithMostWater {
    public int maxArea(int[] height) {
        int ans = 0;
        for (int l = 0, r = height.length - 1; l < r; ) {
            ans = Math.max(ans, Math.min(height[l], height[r]) * (r - l));
            if (height[l] <= height[r]) {
                l++;
            }else {
                r--;
            }
        }

        return ans;
    }
}
```



## 思路

这道题是 **双指针 (Two Pointers) + 贪心 (Greedy)** 的经典入门题（LeetCode 11）。它和“接雨水”虽然都在讲水，但逻辑完全不同，千万不要混淆。



### 1. 【一句话核心】

**“短板效应”**：

决定容器容量的永远是**两边最短的那块板子**。为了争取更大的容量，我们必须**舍弃当前最短的那块板**，去寻找可能更长的板子（虽然宽度会变小，但高度有可能暴增）。

### 2. 【核心推导：为什么要动短的那边？】

公式：$Area = (r - l) \times \min(height[l], height[r])$

- **现状**：假设我们现在的边界是 `l` 和 `r`。
- **必然**：无论我们移动 `l` 还是 `r`，宽度 `(r - l)` **一定会减小**（因为是向内收缩）。
- **博弈**：既然宽度肯定变小了，要让面积变大，**高度必须变大**才行。
  - **如果移动较高的板子**：
    - 新高度**绝不可能**超过原来较矮的那块板（因为瓶颈还在）。
    - 结果：宽度减小，高度不变或更小 $\rightarrow$ **面积一定变小**。
    - *结论：动高板是死路一条。*
  - **如果移动较矮的板子**：
    - 虽然宽度减小了，但新遇到的板子**有可能**非常高。
    - 结果：高度可能大幅提升，从而弥补宽度的损失 $\rightarrow$ **面积可能变大**。
    - *结论：动矮板才有希望。*

### 3. 【图解流程】

假设 `height = [1, 8, 6, 2, 5, 4, 8, 3, 7]`

**详细推演：**

1. **初始状态**：
   - `l = 0` (高 1), `r = 8` (高 7).
   - 宽度 8，瓶颈是 **1**。面积 $1 \times 8 = 8$。
   - **决策**：1 太矮了，拖后腿。**弃掉左边 (l++)**。
2. **第二步**：
   - `l = 1` (高 8), `r = 8` (高 7).
   - 宽度 7，瓶颈是 **7**。面积 $7 \times 7 = 49$。 (更新最大值)
   - **决策**：7 比 8 矮。**弃掉右边 (r--)**。
3. **第三步**：
   - `l = 1` (高 8), `r = 7` (高 3).
   - 宽度 6，瓶颈是 **3**。面积 $3 \times 6 = 18$。
   - **决策**：3 比 8 矮。**弃掉右边 (r--)**。
4. **...持续收缩...** 直到 `l` 和 `r` 相遇。

### 4. 【代码逐行精读】

```java
public static int maxArea(int[] height) {
    int ans = 0;
    // 双指针：l 从头开始，r 从尾开始
    // 每次循环计算面积，并移动指针
    for (int l = 0, r = height.length - 1; l < r;) {
        
        // 1. 计算当前面积
        // 底: (r - l)
        // 高: Math.min(height[l], height[r])
        // 只要比历史最大值大，就更新 ans
        ans = Math.max(ans, Math.min(height[l], height[r]) * (r - l));
        
        // 2. 贪心决策：谁矮谁尴尬，谁矮谁动
        if (height[l] <= height[r]) {
            // 左边矮，左边往右移，试图找个更高的
            l++;
        } else {
            // 右边矮，右边往左移
            r--;
        }
    }
    return ans;
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N)$。双指针一共扫描一遍数组。
- **空间复杂度**: $O(1)$。

### 6. 【易错点 / 面试考察】

1. **和“接雨水”的区别**：
   - **接雨水**：关注的是每个柱子顶上能存多少水（累加和），受限于左右最高墙。
   - **盛最多水**：关注的是**两条线**哪怕隔得很远，它们中间围出来的那个大矩形（底 $\times$ 高）。
2. **如果左右一样高怎么办？**
   - 代码中写的是 `if (height[l] <= height[r])`，所以相等时会移动 `l`。
   - 其实两边一样高时，移动任意一边（或者同时移动两边）都可以。因为这两个特定的板子围成的面积已经算过了，如果不换掉其中一个，面积不可能再变大。

### 7. 【复习闪卡】

- **Q: 为什么“盛最多水”可以用贪心法？**
  - A: 因为向内移动指针时，宽度一定减小。如果保留短板，高度不可能增加，面积必减小。只有舍弃短板，才有可能找到更高的板子来抵消宽度的损失。
- **Q: 代码中 `for` 循环里为什么没有 `i++`？**
  - A: 因为步进条件不是固定的，而是根据 `height[l]` 和 `height[r]` 的大小关系动态决定的（可能是 `l++` 也可能是 `r--`）。





# 6. 供暖器

测试链接 : https://leetcode.cn/problems/heaters/



## 代码

```java
public class Code06_Heaters {
    public int findRadius(int[] houses, int[] heaters) {
        Arrays.sort(houses);
        Arrays.sort(heaters);
        int ans = 0;

        for (int i = 0, j = 0; i < houses.length; i++) {
            while (!best(houses, heaters, i, j)) {
                j++;
            }
            ans = Math.max(ans, Math.abs(heaters[j] - houses[i]));
        }

        return ans;
    }

    public boolean best(int[] houses, int[] heaters, int i, int j) {
        return j == heaters.length - 1
                ||
               Math.abs(heaters[j] - houses[i]) < Math.abs(heaters[j + 1] - houses[i]);
    }
}
```



## 思路



### 1. 【图解核心原理】

这道题的目标是找到一个最小的半径，使得每个房子都能被至少一个供暖器覆盖。

这实际上是一个**“木桶效应”**问题：

1. 对于**每一栋**房子，找到离它**最近**的那个供暖器，计算出这个最短距离。
2. 为了覆盖**所有**房子，所需的供暖半径必须能够覆盖那个“离供暖器最远”的房子。
3. 因此，最终答案是所有这些“最短距离”中的**最大值**。

请配合下图理解这个过程：

- 我们分别计算了 House 1, 2, 3 离它们最近供暖器的距离（分别是 1, 3, 2）。
- House 2 是最难覆盖的（距离为 3）。
- 所以，最终半径必须至少是 3。

### 2. 【核心策略：排序 + 双指针】

如何高效地找到每栋房子最近的供暖器？

- **暴力法**：对于 $N$ 栋房子，每栋都遍历 $M$ 个供暖器。复杂度 $O(N \times M)$。太慢。
- **优化思路（贪心 + 单调性）**：
  - 如果我们将房子和供暖器都按照位置**排序**。
  - 当我们考察位置靠后的房子 `houses[i+1]` 时，离它最近的供暖器，一定不会比 `houses[i]` 的最近供暖器更靠左。
  - 这意味着供暖器的指针 `j` 只需要**一路向右**移动，不需要回退。

### 3. 【算法流程推演】

假设已经排序：`houses = [1, 5, 8]`, `heaters = [2, 10]` (如图所示)

![image-20260211224144962](%E5%8F%8C%E6%8C%87%E9%92%88%E6%8A%80%E5%B7%A7%E4%B8%8E%E7%9B%B8%E5%85%B3%E9%A2%98%E7%9B%AE.assets/image-20260211224144962.png)

1. **初始化**：`i=0` (House 1 在位置 1)，`j=0` (Heater A 在位置 2)。全局最大半径 `ans = 0`。
2. **处理 House 1 (位置 1)**：
   - 比较当前供暖器 `j` (Heater A, 位置2) 和下一个供暖器 `j+1` (Heater B, 位置10)。
   - 距离 A: $|2 - 1| = 1$。
   - 距离 B: $|10 - 1| = 9$。
   - 显然 $1 < 9$，当前 `j` 是最优的。不需要移动 `j`。
   - 更新 `ans = max(0, 1) = 1`。
3. **处理 House 2 (位置 5)**：
   - `i` 移动到 1。此时 `j` 还在 0 (Heater A)。
   - 比较 `j` (Heater A) 和 `j+1` (Heater B)。
   - 距离 A: $|2 - 5| = 3$。
   - 距离 B: $|10 - 5| = 5$。
   - 显然 $3 < 5$，当前 `j` 依然是最优的。不需要移动 `j`。
   - 更新 `ans = max(1, 3) = 3`。
4. **处理 House 3 (位置 8)**：
   - `i` 移动到 2。此时 `j` 还在 0 (Heater A)。
   - **关键判断**：比较 `j` (Heater A) 和 `j+1` (Heater B)。
   - 距离 A: $|2 - 8| = 6$。
   - 距离 B: $|10 - 8| = 2$。
   - 发现 $6 \ge 2$，说明 Heater A 已经太远了（或者说 Heater B 更近了）。
   - **贪心决策**：放弃 Heater A，指针 `j` 向右移动到 1 (指向 Heater B)。
   - 此时 `j` 已是最后一个，循环结束。
   - 更新 `ans = max(3, 2) = 3`。
5. **结束**：返回 3。

### 4. 【代码关键点精读】

```java
public static int findRadius(int[] houses, int[] heaters) {
    // 【关键点1】必须排序，这是使用双指针贪心策略的前提
    Arrays.sort(houses);
    Arrays.sort(heaters);
    int ans = 0;
    // i 指向房子，j 指向供暖器
    // j 定义在循环外，全程只增不减，保证了线性的扫描效率
    for (int i = 0, j = 0; i < houses.length; i++) {
        // 【关键点2】寻找离当前 houses[i] 最近的供暖器
        // best 函数判断：当前的 heaters[j] 是否比下一个 heaters[j+1] 更近？
        // 如果不是 (!best)，说明 j 偏左了，需要往右移 (j++)
        while (!best(houses, heaters, i, j)) {
            j++;
        }
        // 此时的 j 就是离 houses[i] 最近的供暖器
        // 【关键点3】木桶效应，取所有最短距离中的最大值
        ans = Math.max(ans, Math.abs(heaters[j] - houses[i]));
    }
    return ans;
}

// 判断 heaters[j] 是否是 houses[i] 的最优解
public static boolean best(int[] houses, int[] heaters, int i, int j) {
    // 如果 j 已经是最后一个了，没得选了，那它就是最优的
    return j == heaters.length - 1 
            || 
           // 否则比较：当前距离 是否小于 下一个距离
           Math.abs(heaters[j] - houses[i]) < Math.abs(heaters[j + 1] - houses[i]);
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N \log N + M \log M)$。
  - 排序消耗了主要时间。
  - 双指针扫描的过程是线性的 $O(N + M)$，因为 `i` 和 `j` 都只遍历各自的数组一次。
- **空间复杂度**: $O(\log N)$ 或 $O(1)$，取决于排序算法的实现开销。

### 6. 【复习闪卡】

- **Q: 这道题核心思路是什么？**
  - A: 先排序。对于每栋房子，用双指针找到离它最近的供暖器距离。最后取这些距离的最大值。
- **Q: 为什么双指针 `j` 不需要回退？**
  - A: 因为数组有序。如果 `heaters[j]` 已经是 `houses[i]` 的最近邻，那么对于更靠右的 `houses[i+1]`，其最近邻不可能在 `heaters[j]` 的左侧。
- **Q: `best` 函数中判断距离为什么不能用 `<=`？**
  - A: 如果 `当前距离 == 下一个距离`，说明两个供暖器一样好。但为了让 `j` 尽可能向右移动以适应后面的房子，我们应该倾向于选择右边的那个。所以只有当 `当前距离 < 下一个距离` 严格成立时，我们才认为当前 `j` 是必须保留的，否则就尝试往右走。



# 7. 缺失的第一个正数

测试链接 : https://leetcode.cn/problems/first-missing-positive/



## 代码

```java
public class Code07_FirstMissingPositive {
    public int firstMissingPositive(int[] nums) {
        int l = 0;
        int r = nums.length;

        while (l < r) {
            if (nums[l] == l + 1) {
                l++;
            }else if (nums[l] > r || nums[l] <= l || nums[l] == nums[nums[l] - 1]) {
                swap(nums, l, --r);
            }else {
                swap(nums, l, nums[l] - 1);
            }
        }

        return l + 1;
    }


    public void swap(int[] arr, int i, int j) {
        int tmp = arr[i];
        arr[i] = arr[j];
        arr[j] = tmp;
    }
}
```



## 思路

这道题是 **数组原地哈希 (In-place Hashing)** 的巅峰之作（LeetCode 41），也是一道非常高频的 Hard 级别面试题。它的核心难点在于如何利用数组本身的下标作为“哈希表”，从而满足 $O(1)$ 额外空间的要求。



### 1. 【核心思想：一个萝卜一个坑】

我们要找“缺失的第一个正数”。

- 如果数组长度为 $N$，理论上最好的情况是数组里刚好填满了 `1, 2, 3, ..., N`。
- 如果少了某个数，那么缺失的最小正数一定在 `[1, N+1]` 之间。
- **策略**：我们将数组看作是一个排好序的“坑位”。
  - 下标 `0` 的坑，应该放数字 `1`。
  - 下标 `1` 的坑，应该放数字 `2`。
  - ...
  - 下标 `i` 的坑，应该放数字 `i+1`。

我们的任务就是：**通过交换，尽量把数字归位（让 `nums[i] == i+1`）。**

### 2. 【核心变量定义】

这份代码采用了一种 **“双指针 + 垃圾区”** 的高阶写法，比普通的交换法更严谨：

- **`l` (Left)**: **已就位区的右边界**。
  - 含义：`0 ~ l-1` 范围内的数字都已经“归位”了（即 `arr[0]=1`, `arr[1]=2`...）。
  - 我们永远盯着 `l` 位置看，试图把正确的数字（`l+1`）换过来，然后扩大 `l`。
- **`r` (Right)**: **预期最差情况的边界 / 垃圾区的左边界**。
  - 含义：初始时 `r = N`，表示我们预期能凑齐 `1 ~ N`。
  - 当发现一个“垃圾数字”（不合法的、或者多余的）时，我们把它扔到 `r-1` 位置，并将 `r` 左移。
  - `r` 的左边是待处理区，右边是垃圾区。

### 3. 【图解原理】

假设 `arr = [3, 4, -1, 1]`, `N=4`。

**详细推演：**

- **Init**: `l=0`, `r=4`. 目标：`arr[l]` 应该放 `1`。
- **Round 1**: `arr[l]` 是 `3`。
  - `3` 是垃圾吗？不是。它在 `(0, 4]` 范围内。
  - 它该去哪？它该去 `arr[3-1]` 即下标 2 的位置。
  - **Swap**: 把 `3` 和下标 2 的 `-1` 交换。
  - 状态：`[-1, 4, 3, 1]`, `l=0`, `r=4`.
- **Round 2**: `arr[l]` 是 `-1`。
  - `-1` 是垃圾吗？是的（`<=0`）。
  - **Action**: 把它扔到垃圾区 (`--r`)。和 `arr[3]` (数字1) 交换。
  - 状态：`[1, 4, 3, -1]`, `l=0`, `r=3`.
  - *潜台词：现在我们最好情况也只能找到 1~3 了。*
- **Round 3**: `arr[l]` 是 `1`。
  - `1` 刚好等于 `l+1`。**归位成功！**
  - **Action**: `l++`.
  - 状态：`[1, 4, 3, -1]`, `l=1`, `r=3`.
- **Round 4**: `arr[l]` 是 `4`。
  - `4` 是垃圾吗？现在的 `r=3`，意味着我们只期待 `1~3`。`4 > r`，所以 `4` 也是垃圾（对于当前的预期来说）。
  - **Action**: 把它扔到垃圾区 (`--r`)。和 `arr[2]` (数字3) 交换。
  - 状态：`[1, 3, 4, -1]`, `l=1`, `r=2`.
- **Round 5**: `arr[l]` 是 `3`。
  - `3` 是垃圾吗？`3 > r` (3 > 2)，也是垃圾！
  - **Action**: 扔到垃圾区 (`--r`)。
  - 状态：`[1, 4, 3, -1]`, `l=1`, `r=1`.
- **End**: `l=1`, `r=1`。循环结束。
  - 返回 `l + 1 = 2`。
  - (数组其实变成了 `[1, ...]`，缺失的确实是 2)。

### 5. 【难点解析：为什么有 `arr[l] <= l` 这个判断？】

这一步非常精妙。通常我们认为 `arr[l] <= 0` 是垃圾。但这里写的是 `arr[l] <= l`。

- 因为 `l` 左边已经是 `1 ~ l` 排好了。
- 如果当前位置来了一个数字 `k <= l`，说明这个 `k` 其实是**重复**的（因为它应该在左边的某个位置，而那个位置已经就位了）。
- 既然是重复的，对于“寻找缺失的第一个正数”来说，它就是没用的“垃圾”。

### 6. 【复杂度分析】

- **时间复杂度**: $O(N)$。
  - 虽然是 `while` 循环，但每次操作要么 `l++`（也就位一个），要么 `r--`（淘汰一个），要么把一个数字归位。每个数字最多被交换常数次。
- **空间复杂度**: $O(1)$。
  - 只用了 `l`, `r` 几个变量，利用原数组空间。

### 7. 【复习闪卡】

1. **Q: 这道题的核心思路是什么？**
   - A: **原地哈希 (In-place Swap)**。尝试把数字 `i` 放到数组下标 `i-1` 的位置上。
2. **Q: 什么样的数字被视为“垃圾”？**
   - A:
     1. 非正数（`<=0`）。
     2. 超出当前预期范围的数（`> r`）。
     3. **重复**的数（目标位置已经有了该有的数）。
3. **Q: 为什么最后返回 `l + 1`？**
   - A: 因为代码保证了 `0 ~ l-1` 的位置上放着 `1 ~ l`。这说明 `1` 到 `l` 都不缺，缺的自然是下一个 `l+1`。
