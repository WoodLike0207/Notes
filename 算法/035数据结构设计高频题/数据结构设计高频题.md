# 1. setAll功能的哈希表

测试链接 : https://www.nowcoder.com/practice/7c4559f138e74ceb9ba57d76fd169967

注意：setAll方法的时间复杂度也要为O(1)



## 代码

```java
import java.io.*;
import java.util.HashMap;

/**
 * @Title: Code01_SetAllHashMap
 * @Author Wood
 * @Package PACKAGE_NAME
 * @Date 2026/1/3 21:21
 * @description: setAll功能的哈希表
 */
public class Code01_SetAllHashMap {
    public static HashMap<Integer,int[]> map = new HashMap<>();
    public static int setAllValue;
    public static int setAllTime;
    public static int cnt;

    public static void put(int k, int v) {
        if (map.containsKey(k)) {
            int[] value = map.get(k);
            value[0] = v;
            value[1] = cnt++;
        }else {
            map.put(k,new int[]{v,cnt++});
        }
    }

    public static void setAll(int v) {
        setAllValue = v;
        setAllTime = cnt++;
    }

    public static int get(int k) {
        if (!map.containsKey(k)){
            return -1;
        }

        int[] value = map.get(k);
        if (value[1] > setAllTime) {
            return value[0];
        }else {
            return setAllValue;
        }
    }

    public static int n, op, a, b;

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StreamTokenizer in = new StreamTokenizer(br);
        PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));

        while (in.nextToken() != StreamTokenizer.TT_EOF) {
            map.clear();
            setAllValue = 0;
            setAllTime = -1;
            cnt = 0;
            n = (int) in.nval;
            for (int i = 0; i < n; i++) {
                in.nextToken();
                op = (int) in.nval;
                if (op == 1) {
                    in.nextToken();
                    a = (int) in.nval;
                    in.nextToken();
                    b = (int) in.nval;
                    put(a, b);
                } else if (op == 2) {
                    in.nextToken();
                    a = (int) in.nval;
                    out.println(get(a));
                } else {
                    in.nextToken();
                    a = (int) in.nval;
                    setAll(a);
                }
            }
        }
        out.flush();
        out.close();
        br.close();
    }
}
```



## 思路

这份代码解决了一个非常高频的面试设计题：**如何设计一个 Map，支持 `put`、`get` 以及 `setAll`（将所有元素重置为同一个值），并且这三个操作的时间复杂度都是 O(1)**。

普通的 HashMap `put` 和 `get` 是 O(1)，但要实现 `setAll` 通常需要遍历所有 Key，那是 O(N)。要把 O(N) 变成 O(1)，就必须使用**“懒更新”**的思想。



#### 1. 【一句话核心】

**“时间戳大法”**：给每一个存入的数据打上“时间戳”，同时也记录一个全局的 `setAll` 操作的“时间戳”。取数据时，谁的时间戳更新（更大），就信谁。

#### 2. 【算法技巧操作】

- **包装 Value**：哈希表里存的不再是简单的 `int value`，而是 `int[] {value, time}`。
  - `arr[0]`：数值。
  - `arr[1]`：该数值写入时的系统时间（计数器）。
- **全局时钟**：维护一个全局递增变量 `cnt`，每发生一次写入操作（无论是 `put` 还是 `setAll`），`cnt` 都要 `++`。
- **懒更新 (Lazy Evaluation)**：当调用 `setAll` 时，我不去遍历 Map 修改每一个值（太累了）。我只是记录下：“我在第 100 秒执行了全部变 5 的操作”。等你去 `get` 某个具体的 Key 时，我们再现场比对。

#### 3. 【图解原理】

假设全局时钟 `cnt = 0`。

1. **操作 `put(A, 10)`**：
   - Map 存入：`A -> {10, time: 1}`。
   - `cnt` 变为 1。
2. **操作 `setAll(999)`**：
   - 记录全局状态：`setAllValue = 999`，`setAllTime = 2`。
   - `cnt` 变为 2。
   - *注意：此时 Map 里 A 的数据还是 {10, 1}，根本没动它。*
3. **操作 `put(B, 20)`**：
   - Map 存入：`B -> {20, time: 3}`。
   - `cnt` 变为 3。

**现在查询：**

- **`get(A)`**：
  - A 的时间是 1，全局 setAll 时间是 2。
  - **1 < 2**（个人时间 < 全局重置时间）。说明 A 是“前朝遗老”，过时了。
  - **返回全局值 999**。
- **`get(B)`**：
  - B 的时间是 3，全局 setAll 时间是 2。
  - **3 > 2**（个人时间 > 全局重置时间）。说明 B 是“新朝权贵”，是最新的。
  - **返回个人值 20**。

#### 4. 【代码逐行精读】

**Part 1: 核心数据结构**

```java
// Key 是 Integer
// Value 是 int[]，其中 [0]是值, [1]是时间戳
public static HashMap<Integer, int[]> map = new HashMap<>();

// 记录最后一次 setAll 的数值和时间
public static int setAllValue;
public static int setAllTime;

// 全局计数器（模拟系统时间）
public static int cnt;
```

**Part 2: put 操作**

```java
public static void put(int k, int v) {
    if (map.containsKey(k)) {
        int[] value = map.get(k);
        value[0] = v;
        value[1] = cnt++; // 更新值的同时，务必更新时间戳
    } else {
        map.put(k, new int[] { v, cnt++ }); // 新增记录，打上当前时间戳
    }
}
```

**Part 3: setAll 操作 (O(1) 核心)**

```java
public static void setAll(int v) {
    setAllValue = v;   // 记录要把所有变成几
    setAllTime = cnt++; // 记录这条指令是什么时候下的
}
```

**Part 4: get 操作 (判断逻辑)**

```java
public static int get(int k) {
    if (!map.containsKey(k)) {
        return -1;
    }
    int[] value = map.get(k);
    
    // 【核心判断】
    // 只有当 单个记录的时间(value[1]) > 全局重置的时间(setAllTime)
    // 才说明这个数据是在 setAll 之后刚刚更新的，是有效的。
    if (value[1] > setAllTime) {
        return value[0];
    } else {
        // 否则，说明这个数据是在 setAll 之前放进去的，它已经被“覆盖”了
        return setAllValue;
    }
}
```

Part 5: ACM 模式输入输出 (笔试必备)

这段 main 函数是专门为了通过牛客网/力扣的 ACM 模式（自己处理输入输出）写的快读模版。

- `StreamTokenizer`: 处理数字输入极快，比 `Scanner` 快很多倍。
- `PrintWriter`: 输出缓冲，比 `System.out.println` 快。
- **注意**：这种写法在 Java 后端面试的**笔试环节**（特别是处理大数据量时）非常重要，防止因为 IO 慢而超时（TLE）。

------

#### 5. 【死记硬背点 / 易错点】

1. **计数器必增**：无论是 `put` 还是 `setAll`，只要有数据变动，`cnt` 必须 `++`。因为时间是永远流动的，不能停止。
2. **比较符号**：`value[1] > setAllTime`。一定是严格大于。如果等于怎么办？（其实在这个逻辑里不会等于，因为 cnt 每次都加，但逻辑上大于代表“更新”）。
3. **Value 类型**：不要用 `class Node { int val, time; }`，直接用 `int[]` 数组省空间且创建速度稍微快一点点（在刷题时）。

------

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 如何让 setAll 达到 O(1)？**
   - A: 不遍历修改，而是记录全局 `setAll` 的**发生时间**。
2. **Q: 只有 setAll 的时候才更新时间戳吗？**
   - A: 错！`put` 操作也要打上时间戳，用来和全局时间比较。
3. **Q: `get` 的时候遵循什么原则？**
   - A: **谁大听谁的**。单条数据时间 > 全局时间，返回单条数据；否则返回全局 SetAll 的值。



# 2. 实现LRU结构

测试链接：https://leetcode.cn/problems/lru-cache/



## 代码

```java
import java.util.HashMap;
import java.util.Map;

public class Code02_LRU {

    class LRUCache {
        class Node {
            int key;
            int value;
            Node prev;
            Node next;

            Node(int k, int v) {
                key = k;
                value = v;
            }

            Node(int k, int v, Node prev, Node next) {
                key = k;
                value = v;
                this.prev = prev;
                this.next = next;
            }
        }

        class List {
            Node head;
            Node tail;

            List() {
                head = null;
                tail = null;
            }

            public void addNode(Node newNode) {
                if (newNode == null) {
                    return;
                }

                if (head == null) {
                    head = newNode;
                    tail = newNode;
                }else {
                    tail.next = newNode;
                    newNode.prev = tail;
                    tail = newNode;
                }
            }

            public void moveNodeToTail(Node node) {
                if (node == tail) {
                    return;
                }

                if (node == head) {
                    head = node.next;
                    head.prev = null;
                }else {
                    node.prev.next = node.next;
                    node.next.prev = node.prev;
                }

                tail.next = node;
                node.next = null;
                node.prev = tail;
                tail = node;
            }

            public Node removeHead() {
                if (head == null) {
                    return null;
                }
                Node ans = head;
                if (head == tail) {
                    head = null;
                    tail = null;
                }else {
                    head = ans.next;
                    head.prev = null;
                    ans.next = null;
                }

                return ans;
            }
        }

        private Map<Integer,Node> map;
        private List list;
        private Integer capacity;

        public LRUCache(int capacity) {
            map = new HashMap<>();
            list = new List();
            this.capacity = capacity;
        }

        public int get(int key) {
            if (map.containsKey(key)) {
                Node ans = map.get(key);
                list.moveNodeToTail(ans);
                return ans.value;
            }

            return -1;
        }

        public void put(int key, int value) {
            if (map.containsKey(key)) {
                Node node = map.get(key);
                node.value = value;
                list.moveNodeToTail(node);
            }else {
                if (map.size() == capacity) {
                    Node removed = list.removeHead();
                    map.remove(removed.key);
                }

                Node newNode = new Node(key, value);
                map.put(key,newNode);
                list.addNode(newNode);
            }
        }
    }
}
```



## 思路



#### 1. 【一句话核心】

**“哈希表查人，双向链表排座次”**：用 HashMap 保证查找是 O(1)，用双向链表保证维持“最近使用”的顺序是 O(1)。越靠近链表**尾部**的越新（最近用过），越靠近链表**头部**的越老（很久没用）。

#### 2. 【算法操作技巧】

- **为什么必须是双向链表？**
  - 单链表删除某个中间节点需要遍历找到前驱，时间是 O(N)。
  - 双向链表节点自己知道 `prev` 是谁，删除自己只需要 O(1)。
- **Node 里面为什么要存 Key？**
  - 这是一个非常隐蔽的面试坑！
  - 当缓存满了需要淘汰链表头部节点（`removeHead`）时，我们拿到了这个要被删掉的 `Node`。
  - 但是，我们还得去 HashMap 里把这个记录也删掉。如果 `Node` 里只存了 `Value` 没存 `Key`，我们就不知道去 Map 里删谁了（Map 删除需要 Key）。
- **手动实现 List**：
  - 虽然 Java 有 `LinkedList`，但在面试中手写双向链表能体现你对指针操作的掌控力，而且 Java 原生的 LinkedList 封装太深，操作 Node 节点不直观。

#### 3. 【图解原理】

假设容量为 3。

1. **put(1, A), put(2, B), put(3, C)**:
   - 链表：`Head -> 1 -> 2 -> 3 -> Tail`
   - Map 指向对应的节点。
2. **get(1)** (1 被使用了，变成最新的):
   - 把 1 从头部摘下来，挂到尾部。
   - 链表：`Head -> 2 -> 3 -> 1 -> Tail`
3. **put(4, D)** (容量满了，要淘汰最老的):
   - 谁是最老的？Head 指向的 `2`。
   - 删除 `2` (从链表删，从 Map 删)。
   - 把 `4` 加到尾部。
   - 链表：`Head -> 3 -> 1 -> 4 -> Tail`

#### 4. 【代码逐行精读】

**Part 1: 节点设计 (Node)**

```java
class Node {
    int key;   // 【关键】存 key 是为了在淘汰时反向去 map 里删除
    int value;
    Node prev;
    Node next;
    // ... 构造函数 ...
}
```

Part 2: 双向链表实现 (List)

这个内部类专门负责指针操作，把复杂的断链、连链逻辑封装起来。

- **`addNode` (加到尾巴)**：
  - 如果链表为空，Head/Tail 都指向它。
  - 否则，Tail.next 指向它，它.prev 指向 Tail，更新 Tail。
  - *物理含义：新来的或者刚用过的，都放在尾巴，代表“最新”。*
- **`moveNodeToTail` (移到尾巴)**：
  - 这是 `get` 和更新 `put` 时的核心操作。
  - **情况 1**：如果它本来就是 Tail，不用动。
  - **情况 2**：如果它是 Head，Head 指针后移。
  - **情况 3**：如果在中间，把它的前后节点连起来（`node.prev.next = node.next`...）。
  - 最后把它挂到 Tail 后面，更新 Tail。
- **`removeHead` (淘汰最老)**：
  - 当缓存满时调用。
  - 返回被删除的节点（为了拿到它的 Key 去删 Map）。
  - 处理好 Head 指针后移，如果删完链表空了，Tail 也要置空。

**Part 3: 业务逻辑 (LRUCache)**

- **`get(key)`**:

  ```java
  if (map.containsKey(key)) {
      Node ans = map.get(key);
      list.moveNodeToTail(ans); // 【核心】既然被访问了，就是最新的，去尾部
      return ans.value;
  }
  return -1;
  ```

- **`put(key, value)`**:

  ```java
  if (map.containsKey(key)) {
      // 1. key 已经存在：更新值，并标记为最新（移到尾部）
      Node node = map.get(key);
      node.value = value;
      list.moveNodeToTail(node);
  } else {
      // 2. key 不存在：需要新增
      if (map.size() == capacity) {
          // 容量满了？先杀掉最老的（头部）
          Node removed = list.removeHead();
          map.remove(removed.key); // 【注意】这里用到了 Node 里的 key
      }
      // 创建新的，加到 Map，加到链表尾部
      Node newNode = new Node(key, value);
      map.put(key, newNode);
      list.addNode(newNode);
  }
  ```

#### 5. 【死记硬背点 / 易错点】

1. **三个 O(1)**：`get` 是 O(1)，`put` 是 O(1)，内部的节点移动也是 O(1)。
2. **断链顺序**：在手写双向链表时，操作 `prev` 和 `next` 指针非常容易空指针异常（NPE）。一定要先判断 `head == null` 或 `head == tail` 这种边界情况。
3. **淘汰机制**：时刻记住，**Head 是最老的（等待被宰），Tail 是最新的（刚被宠幸）**。不要搞反了。

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 为什么 LRU 里面需要一个双向链表，单链表不行吗？**
   - A: 单链表无法在 O(1) 时间内删除一个指定节点（因为找不到前驱），会退化成 O(N)。
2. **Q: 在 `Node` 类定义中，为什么要保存 `key`？**
   - A: 为了在链表容量满进行淘汰时，能通过淘汰的节点反向找到 HashMap 中的 Key 并删除映射。
3. **Q: `get` 操作除了返回 value，还隐含了什么副作用？**
   - A: 会把该节点移动到双向链表的尾部（标记为最近使用）。



# 3.  插入、删除和获取随机元素O(1)时间的结构

测试链接：https://leetcode.cn/problems/insert-delete-getrandom-o1/



## 代码

```java
class RandomizedSet {
    private Map<Integer,Integer> map;
    private List<Integer> arr;

    public RandomizedSet() {
        map = new HashMap<>();
        arr = new ArrayList<>();
    }

    public boolean insert(int val) {
        if (map.containsKey(val)) {
            return false;
        }

        map.put(val,arr.size());
        arr.add(val);
        return true;
    }

    public boolean remove(int val) {
        if (!map.containsKey(val)) {
            return false;
        }

        Integer valueIndex = map.get(val);
        Integer endValue = arr.get(arr.size() - 1);
        map.put(endValue,valueIndex);
        arr.set(valueIndex,endValue);
        map.remove(val);
        arr.remove(arr.size() - 1);
        return true;
    }

    public int getRandom() {
        return arr.get((int) (Math.random() * arr.size()));
    }
}
```



## 思路



#### 1. 【一句话核心】

**“哈希表记位置，数组存数值”**：因为哈希表无法做到 O(1) 随机获取（key 是无序的），而数组无法做到 O(1) 任意删除（中间删除需要挪动）；所以我们要**结合两者**：Map 记录 `val -> index`，ArrayList 实际存储 `val`。

#### 2. 【算法操作技巧】

- **鸠占鹊巢（Swap to Delete）**：
  - 在数组中删除中间的一个元素，通常需要把后面的所有元素往前挪，这是 O(N) 的。
  - **技巧**：既然我不关心顺序，那我就把**数组最后一个元素**拿过来，填补到要删除的那个位置（覆盖掉死者），然后直接删掉数组末尾的元素。这样就把 O(N) 的“挪动”变成了 O(1) 的“覆盖”。

#### 3. 【图解原理：删除操作】

假设数组是 `[10, 20, 30, 40]`，Map 是 `{10:0, 20:1, 30:2, 40:3}`。

我们要 **remove(20)**（他在 index 1）。

1. **定位**：查 Map 发现 20 在 `index = 1`。
2. **找替补**：找来数组最后一个元素 40（`endValue`）。
3. **覆盖**：把 `index = 1` 的位置改成 40。数组变成 `[10, 40, 30, 40]`。
4. **更新索引**：在 Map 里告诉 40：“你搬家了，新地址是 1”。Map: `{..., 40:1}`。
5. **清理现场**：
   - Map 删除 20。
   - 数组删除最后一个元素（因为已经拷贝到前面去了）。
   - 最终数组：`[10, 40, 30]`。

#### 4. 【代码逐行精读】

**Part 1: 插入 (Insert)**

Java

```
public boolean insert(int val) {
    if (map.containsKey(val)) {
        return false;
    }
    // 1. Map 记录：值 -> 它在数组里的下标（也就是当前的 size）
    map.put(val, arr.size());
    // 2. 数组：直接追加到末尾
    arr.add(val);
    return true;
}
```

**Part 2: 删除 (Remove) —— 核心难点**

Java

```
public boolean remove(int val) {
    if (!map.containsKey(val)) {
        return false;
    }

    // 1. 拿到“死者”的下标
    Integer valueIndex = map.get(val);
    // 2. 拿到“替补”（数组最后一个元素）
    Integer endValue = arr.get(arr.size() - 1);

    // 3. 【重要】更新“替补”在 Map 中的地址
    // 必须先更新，再删死者。防止死者和替补是同一个（数组只有一个元素时）
    map.put(endValue, valueIndex);

    // 4. 【重要】在数组里，用“替补”覆盖“死者”
    arr.set(valueIndex, endValue);

    // 5. 物理删除
    map.remove(val); // 删 Map 记录
    arr.remove(arr.size() - 1); // 删数组最后一位（因为搬走了）

    return true;
}
```

**Part 3: 随机获取 (GetRandom)**

Java

```
public int getRandom() {
    // Math.random() -> [0, 1)
    // * size -> [0, size)
    // (int) -> 取整，刚好是合法的下标范围
    return arr.get((int) (Math.random() * arr.size()));
}
```

#### 5. 【死记硬背点 / 易错点】

1. **删除只有一个元素的情况**：如果数组只有 `[10]`，要删 `10`。死者是 10，替补也是 10。
   - 代码逻辑：Map 更新 10 的位置 -> Map 删除 10。
   - 如果你先删 Map 再更新 Map，就会导致错误。**建议顺序：先处理替补的 Map 更新，最后再执行 remove。**
2. **Map 的 Value 是什么？**：Map 的 Key 是数值，Value **必须是该数值在 ArrayList 中的下标**。没有这个下标，你就没法在 O(1) 时间内去数组里找到它并覆盖它。

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 为什么不能只用 HashMap？**
   - A: HashMap 虽然插入删除是 O(1)，但它无法实现 `getRandom` O(1)。因为它的 Key 是无序存储的，你没法随机拿到第 K 个 Key。
2. **Q: 为什么不能只用 ArrayList？**
   - A: ArrayList 随机读取是 O(1)，但删除某个特定数值（如果不给下标）需要遍历查找，是 O(N)；且普通删除会导致后续元素移位，也是 O(N)。
3. **Q: 在数组中间 O(1) 删除元素的秘诀是什么？**
   - A: **与末尾元素交换（覆盖）**，然后删除末尾。因为我们不关心集合内部的顺序。



# 4. 插入、删除和获取随机元素O(1)时间且允许有重复数字的结构

测试链接：https://leetcode.cn/problems/insert-delete-getrandom-o1-duplicates-allowed/



## 代码

```java
class RandomizedCollection {
    private Map<Integer, Set<Integer>> map;
    private List<Integer> arr;

    public RandomizedCollection() {
        map = new HashMap<>();
        arr = new ArrayList<>();
    }

    public boolean insert(int val) {
        arr.add(val);
        Set<Integer> set = map.getOrDefault(val, new HashSet<Integer>());
        set.add(arr.size() - 1);
        map.put(val, set);
        return set.size() == 1;
    }

    public boolean remove(int val) {
        if (!map.containsKey(val)) {
            return false;
        }

        Set<Integer> valIndexSet = map.get(val);
        Integer valAnyIndex = valIndexSet.iterator().next();
        Integer endValue = arr.get(arr.size() - 1);
        if (endValue == val) {
            valIndexSet.remove(arr.size() - 1);
        }else {
            Set<Integer> endValIndexSet = map.get(endValue);
            endValIndexSet.add(valAnyIndex);
            arr.set(valAnyIndex,endValue);
            endValIndexSet.remove(arr.size() - 1);
            valIndexSet.remove(valAnyIndex);
        }

        arr.remove(arr.size() - 1);
        if (valIndexSet.isEmpty()) {
            map.remove(val);
        }

        return true;
    }

    public int getRandom() {
        return arr.get((int) (Math.random() * arr.size()));
    }
}
```



## 思路

这份代码是 LeetCode 381 题：**O(1) 时间插入、删除和获取随机元素 - 允许重复** (Insert Delete GetRandom O(1) - Duplicates allowed)。

它是上一题（Code08）的**进阶版**。核心难点在于：当数组里有多个相同的数字时，如何正确地删除其中某一个，并维护好下标映射，不弄乱哈希表。



#### 1. 【一句话核心】

**“多对多映射 + 覆盖删除”**：因为允许重复，数值和下标的关系变成了“一对多”，所以 Map 的 Value 必须是 `Set<Integer>`（存该数值的所有下标）。删除时，依然用**“末尾元素覆盖法”**，但更新下标时要格外小心，防止把自己给删丢了。

#### 2. 【算法操作技巧】

- **Map 结构的升级**：
  - 以前：`Map<Integer, Integer>` (值 -> 下标)
  - 现在：`Map<Integer, Set<Integer>>` (值 -> {下标1, 下标2, ...})
  - *为什么用 Set？* 因为删除时我们需要快速找到并移除一个特定的下标，Set 的 `remove` 是 O(1) 的。
- **Iterator 的妙用**：
  - `valIndexSet.iterator().next()`：当我要删一个值（比如 10），但我不在乎删哪一个位置的 10。利用迭代器随便拿一个下标出来删，这就是 O(1)。
- **防御性编程（特判自己）**：
  - 在删除逻辑中，有一个 `if (endValue == val)` 的特判。这是为了防止**“我要删的元素”和“用来填坑的末尾元素”值相同**时，对同一个 Set 进行又加又减的操作导致逻辑错误。

#### 3. 【图解原理：复杂的删除逻辑】

假设数组：`[10, 20, 10, 30]` (下标 0, 1, 2, 3)

Map：`10->{0, 2}`, `20->{1}`, `30->{3}`

**场景：`remove(10)`**

1. **选下标**：从 `10` 的集合 `{0, 2}` 里随便拿一个，假设拿到了 **0** (`valAnyIndex`)。
2. **找替补**：数组末尾元素是 **30** (`endValue`)，下标是 3。
3. **填坑与更新**（最乱的地方）：
   - **填坑**：把 `arr[0]` 变成 30。数组变为 `[30, 20, 10, 30]`。
   - **通知替补**：30 原来的下标是 3，现在搬到了 0。
     - `map.get(30).add(0)`
     - `map.get(30).remove(3)`
   - **删除死者**：10 原来的下标 0 被占了。
     - `map.get(10).remove(0)`
4. **物理删除**：删掉数组末尾。数组变为 `[30, 20, 10]`。

**Part 2: 删除 (Remove) —— 核心中的核心**

Java

```
public boolean remove(int val) {
    if (!map.containsKey(val)) {
        return false;
    }

    // 1. 获取要删除值的下标集合，并随便取一个下标（比如要删的数在 index=5）
    Set<Integer> valIndexSet = map.get(val);
    Integer valAnyIndex = valIndexSet.iterator().next();
    
    // 2. 获取数组最后一位的值（替补，比如在 index=10）
    Integer endValue = arr.get(arr.size() - 1);

    // 【特殊情况】如果要删的值，恰好就是末尾那个值（比如数组是 [A, B, A]，要删 A）
    // 或者数组里最后一位本来就是 A，而我们要删前面的 A。
    // 为了逻辑清晰，这里分了两种情况，防止操作同一个 Set 搞乱。
    if (endValue == val) {
        // 如果末尾就是我要删的值，且我正好选中了末尾这个下标，或者值相同
        // 直接从 Set 里移除末尾下标即可，不需要做“覆盖”操作
        // 注意：这里其实有个隐含逻辑，如果 valAnyIndex != lastIndex 但 val == endValue
        // 这一步只删除了 lastIndex。其实更严谨的写法应该覆盖，但因为值一样，不覆盖也没事。
        // *你的代码逻辑是：如果值相同，直接删掉末尾下标记录，下面 arr.remove 也会删掉末尾。*
        // *但这有一个小 BUG：如果选中的 valAnyIndex 不是末尾，你只删了末尾记录，却没把末尾挪过来覆盖。*
        // *不过，利用 Set 的特性，如果要删的值等于末尾值，我们其实可以直接认为“我删的就是末尾那个”，不用动前面的。*
        valIndexSet.remove(arr.size() - 1);
    } else {
        // 【标准情况】替补(endValue) 和 死者(val) 不一样
        Set<Integer> endValIndexSet = map.get(endValue);
        
        // 1. 替补搬家：在 Map 里给替补添加新地址 (valAnyIndex)
        endValIndexSet.add(valAnyIndex);
        // 2. 物理覆盖：在数组里把死者位置变成替补
        arr.set(valAnyIndex, endValue);
        // 3. 替补注销旧地址：在 Map 里移除替补的原地址 (末尾)
        endValIndexSet.remove(arr.size() - 1);
        // 4. 死者注销：在 Map 里移除死者的地址
        valIndexSet.remove(valAnyIndex);
    }

    // 物理删除数组末尾
    arr.remove(arr.size() - 1);
    
    // 如果这个值删光了，把 Key 从 Map 移除
    if (valIndexSet.isEmpty()) {
        map.remove(val);
    }

    return true;
}
```

#### 5. 【代码逻辑修正与深度解析】

请注意你的代码中 `if (endValue == val)` 这一块。

逻辑是：**如果数组末尾的值(`endValue`) 等于 想要删除的值(`val`)**。

不管你 `iterator().next()` 选中了哪个位置的 `val`（假设数组是 `[10, 20, 10]`，`val=10`）：

- **情况 A**：选中了下标 2 (末尾)。直接删，没问题。
- **情况 B**：选中了下标 0。
  - 你的代码逻辑：`valIndexSet.remove(2)`。然后 `arr.remove(2)`。
  - 结果：数组变成了 `[10, 20]`。Map 里 10 的下标剩下了 `{0}`。
  - **效果**：虽然你本想删下标 0，但实际上你删了下标 2。
  - **这合法吗？** **合法！** 题目只要求删除一个 `val`，没指定删哪一个。既然末尾就是 `val`，我直接把末尾删了，既省去了 swap 的开销，又满足了题意。
  - **结论**：这个写法是**极其聪明**的偷懒写法，避免了值相同时复杂的 Set 操作。

------

#### 6. 【死记硬背点 / 易错点】

1. **Set 代替 Integer**：这是和上一题唯一的区别，因为要存重复元素的下标。
2. **先 Add 后 Remove**：在 `else` 分支里，更新 `endValue` 的 Set 时，建议**先 add 新位置，再 remove 旧位置**。虽然大部分时候没区别，但如果是同一个位置（边界情况），先删再加可能会出问题（虽然这题有 size 判断规避了）。
3. **偷懒逻辑**：如果 `endValue == val`，不管 `val` 在哪，直接删末尾。这是这道题最快最稳的解法。

#### 7. 【复习闪卡 (Flashcard)】

1. **Q: 允许重复时，Map 的 Value 变成了什么？**
   - A: `Set<Integer>`，用来存储该值出现的所有下标。
2. **Q: 当要删除的值和数组末尾的值相等时，最简单的处理方式是什么？**
   - A: **直接删除末尾的那一个**。不需要做覆盖交换，因为值是一样的，删哪个都算完成任务，删末尾最省事。
3. **Q: 为什么删除时需要 `iterator().next()`？**
   - A: 因为题目只说删除一个值为 `val` 的元素，没指定位置。Set 是无序的，用迭代器随便取一个下标出来删即可。



# 5. 快速获得数据流的中位数的结构

测试链接：https://leetcode.cn/problems/find-median-from-data-stream/



## 代码

```java
class MedianFinder {
    private PriorityQueue<Integer> minHeap;
    private PriorityQueue<Integer> maxHeap;

    public MedianFinder() {
        minHeap = new PriorityQueue<>((a,b) -> a - b);
        maxHeap = new PriorityQueue<>((a,b) -> b - a);
    }

    public void addNum(int num) {
        if (maxHeap.isEmpty() || num <= maxHeap.peek()) {
            maxHeap.add(num);
        }else {
            minHeap.add(num);
        }

        balance();
    }

    public double findMedian() {
        if (maxHeap.size() == minHeap.size()) {
            return (double) (maxHeap.peek() + minHeap.peek()) / 2;
        }else {
            return maxHeap.size() > minHeap.size() ? maxHeap.peek() : minHeap.peek();
        }
    }


    private void balance() {
        if (Math.abs(maxHeap.size() - minHeap.size()) == 2) {
            if (maxHeap.size() > minHeap.size()) {
                minHeap.add(maxHeap.poll());
            }else {
                maxHeap.add(minHeap.poll());
            }
        }
    }
}
```



## 思路

这是**堆（Heap）**应用中最经典、最完美的案例。它利用“对顶堆”结构，将时间复杂度从 O(N log N)（排序）降低到了 O(log N)（插入）和 O(1)（查询）。

#### 1. 【一句话核心】

**“三八线分治法”**：把所有数字按大小切成两半，**较小的一半**扔进大根堆（我们要这堆里最大的，也就是靠近中间的），**较大的一半**扔进小根堆（我们要这堆里最小的，也是靠近中间的）。两个堆顶就是整个数据流最中间的两个数。

#### 2. 【左神算法“骚”操作】

- **守门员逻辑 (`addNum`)**：
  - 谁来守门？**大根堆 (`maxHeap`)** 的堆顶。
  - 新来的数 `num` 如果比守门员小（`<= maxHeap.peek()`），说明它属于“小数值阵营”，进大根堆。
  - 否则，属于“大数值阵营”，进小根堆。
  - *注：第一个数直接进大根堆作为初始守门员。*
- **动态平衡 (`balance`)**：
  - 不像某些写法强制规定“大根堆必须比小根堆多一个”，这份代码允许**任意一边比另一边多 1 个**。
  - 只有当差值达到 **2** 时，才触发搬运（把多的那边的堆顶，弹出来给少的那边）。
- **中位数公式**：
  - 两堆一样多？堆顶相加除以 2。
  - 不一样多？谁胖（size 大）谁的堆顶就是中位数。

#### 3. 【图解原理】

假设数据流：`5, 2, 8, 10`

1. **Add 5**:
   - `maxHeap` 空，5 进大根堆。
   - 状态：Max:[5], Min:[]。
2. **Add 2**:
   - 2 <= 5 (守门员)，2 进大根堆。
   - 状态：Max:[5, 2], Min:[]。
   - **Balance**: 差值=2。Max 太多，把堆顶(5)给 Min。
   - 状态：Max:[2], Min:[5]。
3. **Add 8**:
   - 8 > 2，8 进小根堆。
   - 状态：Max:[2], Min:[5, 8]。
   - Balance: 差值=1，不动。
4. **Add 10**:
   - 10 > 2，10 进小根堆。
   - 状态：Max:[2], Min:[5, 8, 10]。
   - **Balance**: 差值=2。Min 太多，把堆顶(5)给 Max。
   - 状态：Max:[5, 2], Min:[8, 10]。

**找中位数**: 此时两边一样多，(5+8)/2 = 6.5。

#### 4. 【代码逐行精读】

**Part 1: 初始化**

// maxHeap: 大根堆，存“较小的一半数”，堆顶是这一半里最大的

    // 如果大根堆没人，或者新来的数比大根堆堆顶小，说明它属于小数值那一半

        maxHeap.add(num);
    } else {

```java
private void balance() {
    // 只要差值到了 2，就说明失衡了，需要“削峰填谷”
    if (Math.abs(maxHeap.size() - minHeap.size()) == 2) {
        if (maxHeap.size() > minHeap.size()) {
            // 大根堆多了，把老大(最大值)给小根堆
            minHeap.add(maxHeap.poll());
        } else {
            // 小根堆多了，把老小(最小值)给大根堆
            maxHeap.add(minHeap.poll());
        }
    }
}
```

**Part 4: 算中位数 (`findMedian`)**

```java
public double findMedian() {
    if (maxHeap.size() == minHeap.size()) {
        // 偶数个：取两个堆顶的平均值
        return (double) (maxHeap.peek() + minHeap.peek()) / 2;
    } else {
        // 奇数个：谁多出来的那个，谁就是中位数
        return maxHeap.size() > minHeap.size() ? maxHeap.peek() : minHeap.peek();
    }
}
```

#### 5. 【死记硬背点 / 易错点】

1. **比较器的方向**：`maxHeap` 必须是 `b - a`（大根堆），`minHeap` 必须是 `a - b`（小根堆）。搞反了就完全错了。
2. **判空逻辑**：`addNum` 里的 `maxHeap.isEmpty()` 判断不能少。如果不判断，直接调用 `peek()` 会报空指针异常（或者返回 null 导致比较错误）。
3. **返回值类型**：中位数可能是 `.5`，所以返回值必须是 `double`，计算平均值时记得强转 `(double)`。

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 为什么求中位数要用两个堆？**
   - A: 一个存前半段（大根堆），一个存后半段（小根堆），这样能 O(1) 拿到中间的两个边界值。
2. **Q: 什么时候触发 `balance` 操作？**
   - A: 当两个堆的大小差值达到 **2** 的时候。
3. **Q: 如果数据流的总数是奇数，中位数在哪里？**
   - A: 元素个数更多的那个堆的堆顶。



# 6. 最大频率栈

测试链接 : https://leetcode.cn/problems/maximum-frequency-stack/



## 代码

```java
class FreqStack {
    private int topTimes;
    // 键为出现次数，值为出现次数对应的元素
    private Map<Integer, List<Integer>> cntValues;
    // 词频表，键为元素，值为元素出现的次数
    private Map<Integer, Integer> valueTimes = new HashMap<>();

    public FreqStack() {
        cntValues =  new HashMap<>();
        valueTimes = new HashMap<>();
    }

    public void push(int val) {
        valueTimes.put(val, valueTimes.getOrDefault(val, 0) + 1);
        Integer curTopTimes = valueTimes.get(val);

        if (!cntValues.containsKey(curTopTimes)) {
            cntValues.put(curTopTimes, new ArrayList<>());
        }

        List<Integer> curTopValues = cntValues.get(curTopTimes);
        curTopValues.add(val);

        topTimes = Math.max(topTimes,curTopTimes);
    }


    public int pop() {
        List<Integer> topTimeValues = cntValues.get(topTimes);
        Integer ans = topTimeValues.remove(topTimeValues.size() - 1);

        if (topTimeValues.isEmpty()) {
            cntValues.remove(topTimes--);
        }

        Integer times = valueTimes.get(ans);
        if (times == 1) {
            valueTimes.remove(ans);
        }else {
            valueTimes.put(ans,times - 1);
        }
        
        return ans;
    }
}
```



## 思路

这是一道非常经典的**哈希表 + 栈**的设计题。难点在于：当有多个元素频率相同时，怎么保证弹出的是“最新入栈”的那一个？以及弹出后，如何快速更新频率？



#### 1. 【一句话核心】

**“千层蛋糕法”**：不要把同一个元素看成一个整体，而是把它出现的第 1 次、第 2 次、第 N 次分别存在不同的“层”（List）里。弹出时，直接去最高的层拿最晚进来的那个。

#### 2. 【算法操作技巧】

- **反向索引 (`cntValues`)**：
  - 普通的逻辑是 `Value -> Count`。
  - 这里的核心是 `Count -> List<Value>`。也就是：所有出现次数为 1 的放在一组，出现次数为 2 的放在一组...
- **List 当栈用**：
  - `cntValues` 里的 `List<Integer>` 实际上就是一个栈。因为 `add` 是加到尾部，`remove` 是删掉尾部，这正好符合“后进先出”。
- **影子副本**：
  - 如果你 push 了三次 `5`，那么 `5` 会同时存在于第 1 层、第 2 层和第 3 层的 List 中。
  - 当你从第 3 层 pop 掉一个 `5` 后，第 1 层和第 2 层的 `5` 依然还在，这样就不用费劲去修改历史数据了。O(1) 的秘诀就在这里。

#### 3. 【图解原理】

假设操作顺序：`push(5), push(7), push(5), push(7), push(5), push(4)`

**状态演变：**

1. **Push 5** (第1次): `Level 1: [5]`
2. **Push 7** (第1次): `Level 1: [5, 7]`
3. **Push 5** (第2次): `Level 1: [5, 7]`, `Level 2: [5]`
4. **Push 7** (第2次): `Level 1: [5, 7]`, `Level 2: [5, 7]`
5. **Push 5** (第3次): `Level 1: [5, 7]`, `Level 2: [5, 7]`, `Level 3: [5]`
6. **Push 4** (第1次): `Level 1: [5, 7, 4]`, ...

**此时 `topTimes` = 3。**

**Pop 操作：**

1. 去 Level 3 (`topTimes`) 找。List 是 `[5]`。
2. 弹出末尾的 `5`。
3. Level 3 空了，`topTimes` 降为 2。
4. 此时 `5` 的频率在 `valueTimes` 里减为 2。

------

#### 4. 【代码逐行精读】

**Part 1: 变量定义**

```java
// 记录当前最高的频率是多少（楼盖到了第几层）
private int topTimes;
// 【核心】层级表：Key=频率, Value=该频率下的所有元素列表(其实是栈)
private Map<Integer, List<Integer>> cntValues;
// 词频表：Key=元素, Value=当前总共出现的次数
private Map<Integer, Integer> valueTimes = new HashMap<>();
```

**Part 2: Push 操作**

```java
public void push(int val) {
    // 1. 词频 + 1
    valueTimes.put(val, valueTimes.getOrDefault(val, 0) + 1);
    // 拿到它现在是“第几次”出现
    Integer curTopTimes = valueTimes.get(val);

    // 2. 如果这一层还没有列表，建一个新的
    if (!cntValues.containsKey(curTopTimes)) {
        cntValues.put(curTopTimes, new ArrayList<>());
    }

    // 3. 【关键】把它加到对应频率层的列表末尾
    // 注意：即使它在第 1、2 层也有副本，这里只管第 3 层
    List<Integer> curTopValues = cntValues.get(curTopTimes);
    curTopValues.add(val);

    // 4. 更新最高楼层高度
    topTimes = Math.max(topTimes, curTopTimes);
}
```

**Part 3: Pop 操作**

```java
public int pop() {
    // 1. 直接去最高层找人
    List<Integer> topTimeValues = cntValues.get(topTimes);
    
    // 2. 弹出列表末尾的元素（满足：频率最高 + 最晚入栈）
    Integer ans = topTimeValues.remove(topTimeValues.size() - 1);

    // 3. 【核心维护】如果这一层空了，说明没人达到这个频率了
    // 楼层降低一层 (topTimes--)
    if (topTimeValues.isEmpty()) {
        cntValues.remove(topTimes--); 
    }

    // 4. 更新词频表 (ans 的次数 - 1)
    Integer times = valueTimes.get(ans);
    if (times == 1) {
        valueTimes.remove(ans);
    } else {
        valueTimes.put(ans, times - 1);
    }
    
    return ans;
}
```

#### 5. 【死记硬背点 / 易错点】

1. **为什么 topTimes-- 不需要循环去找下一个最大值？**
   - 因为频率是**连续**变化的。如果最大频率是 3，被删空了，那剩下的最大频率一定是 2，不可能是 1 或者 0（除非栈空了）。所以直接减 1 即可，这是 O(1) 的关键。
2. **同一个元素存多份**：千万别想着 push 的时候把第 1 层的 `5` 删掉移到第 2 层。要保留第 1 层的 `5`，这样等你把第 2 层的 `5` pop 掉之后，第 1 层的 `5` 自动生效。

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 为了实现 O(1) 的最大频率栈，我们需要哪两个 Map？**
   - A: 一个存 `<值, 频率>` (用来查询当前是第几次)，一个存 `<频率, List<值>>` (用来分层存数据)。
2. **Q: 当最高频率层被取空后，`topTimes` 如何更新？**
   - A: 直接减 1 (`topTimes--`)。因为频率是连续累加的，中间不会断层。
3. **Q: 为什么 `cntValues` 的 Value 要用 List 而不是 Set？**
   - A: 因为题目要求频率相同时弹出**最近**加入的元素。List 有序（且用作栈），能保留入栈顺序；Set 无序，无法满足题意。



# 7. 全O(1)的数据结构

测试链接 : https://leetcode.cn/problems/all-oone-data-structure/



## 代码

```java
class AllOne {
    class Bucket {
        public HashSet<String> set;
        public int cnt;
        public Bucket prev;
        public Bucket next;

        public Bucket(String s, int c) {
            cnt = c;
            set = new HashSet<>();
            set.add(s);
        }
    }

    private void insert(Bucket cur, Bucket pos) {
        cur.next.prev = pos;
        pos.next = cur.next;
        cur.next = pos;
        pos.prev = cur;
    }

    public void remove(Bucket cur) {
        cur.prev.next = cur.next;
        cur.next.prev = cur.prev;
    }

    Bucket head;
    Bucket tail;
    HashMap<String, Bucket> map;

    public AllOne() {
        head = new Bucket("", 0);
        tail = new Bucket("", Integer.MAX_VALUE);
        head.next = tail;
        tail.prev = head;
        map = new HashMap<>();
    }

    public void inc(String key) {
        if (!map.containsKey(key)) {
            if (head.next.cnt == 1) {
                map.put(key,head.next);
                head.next.set.add(key);
            }else {
                Bucket newBucket = new Bucket(key,1);
                map.put(key,newBucket);
                insert(head, newBucket);
            }
        }else {
            Bucket bucket = map.get(key);
            if (bucket.next.cnt == bucket.cnt + 1) {
                map.put(key,bucket.next);
                bucket.next.set.add(key);
            }else {
                Bucket newBucket = new Bucket(key, bucket.cnt + 1);
                map.put(key,newBucket);
                insert(bucket,newBucket);
            }
            bucket.set.remove(key);

            if (bucket.set.isEmpty()) {
                remove(bucket);
            }
        }
    }

    public void dec(String key) {
        Bucket bucket = map.get(key);

        if (bucket.cnt == 1) {
            map.remove(key);
        }else {
            if (bucket.prev.cnt == bucket.cnt - 1) {
                map.put(key,bucket.prev);
                bucket.prev.set.add(key);
            }else {
                Bucket newBucket = new Bucket(key, bucket.cnt - 1);
                map.put(key, newBucket);
                insert(bucket.prev,newBucket);
            }
        }

        bucket.set.remove(key);
        if (bucket.set.isEmpty()) {
            remove(bucket);
        }
    }

    public String getMaxKey() {
        return tail.prev.set.iterator().next();
    }

    public String getMinKey() {
        return head.next.set.iterator().next();
    }
}
```



## 思路

这份代码解决了 LeetCode 432 题：**全 O(1) 的数据结构** (All O`one Data Structure)。

这是一道非常有名的**设计类难题**。要求实现 `inc` (增加计数)、`dec` (减少计数)、`getMaxKey` (计数最大)、`getMinKey` (计数最小)，且所有操作的时间复杂度必须是严格的 **$O(1)$**。



#### 1. 【一句话核心】

**“频率桶 + 双向链表”**：把所有出现次数相同的 Key 放在同一个“桶”（Bucket）里，把这些桶按照次数从小到大连成一个双向链表。Map 记录 Key 在哪个桶里。

#### 2. 【算法操作技巧】

- **桶的动态管理**：
  - 不需要预先建立 1 到 N 的所有桶。
  - **用时即建**：如果我从次数 1 变成次数 2，且此时链表里没有次数 2 的桶，我就现造一个，插在次数 1 的桶后面。
  - **空了即删**：如果某个桶里的 Key 都跑光了，这个桶就没用了，直接从链表里摘除。这样保证链表里所有的节点都是“有货”的，且有序。
- **哨兵节点 (Sentinel)**：
  - 只要是双向链表，左神的代码习惯几乎必定会有 `head` 和 `tail` 两个哨兵。
  - `head` 代表计数 0（或起点），`tail` 代表无穷大。这样在头部插入（次数1）或尾部操作时，不需要做判空的边界检查。

#### 3. 【图解原理】

假设当前状态：`A=1, B=1, C=2`。

链表结构：

```java
Head(0) <-> Bucket(1: {A, B}) <-> Bucket(2: {C}) <-> Tail(MAX)
```

**操作 1：`inc("B")` (B 从 1 变 2)**

1. 找到 B 在 `Bucket(1)`。

2. 看后面是不是 `Bucket(2)`？是。

3. 把 B 从 `Bucket(1)` 移动到 `Bucket(2)`。

4. `Bucket(1)` 只剩 A，不空，保留。

   **状态变更为**：`Head <-> Bucket(1: {A}) <-> Bucket(2: {C, B}) <-> Tail`

**操作 2：`inc("A")` (A 从 1 变 2)**

1. 找到 A 在 `Bucket(1)`。

2. 移动 A 到 `Bucket(2)`。

3. `Bucket(1)` 变空了！**删除 Bucket(1)**。

   **状态变更为**：`Head <-> Bucket(2: {C, B, A}) <-> Tail`

------

#### 4. 【代码逐行精读】

**Part 1: 桶结构 (Inner Class Bucket)**

```java
class Bucket {
    public HashSet<String> set; // 存哪些 key 是这个频率
    public int cnt;             // 频率是多少
    public Bucket prev, next;   // 双向指针

    public Bucket(String s, int c) {
        cnt = c;
        set = new HashSet<>();
        set.add(s);
    }
}
```

**Part 2: 增加计数 (`inc`)**

```java
public void inc(String key) {
    if (!map.containsKey(key)) {
        // --- 情况 A: 新来的 Key (之前没出现过) ---
        // 它的目标是“次数1”。检查 Head 后面是不是“次数1”的桶？
        if (head.next.cnt == 1) {
            map.put(key, head.next);
            head.next.set.add(key);
        } else {
            // 如果后面是次数 5 (或者 tail)，说明没有次数 1 的桶，新建一个
            Bucket newBucket = new Bucket(key, 1);
            map.put(key, newBucket);
            insert(head, newBucket); // 插在 head 后面
        }
    } else {
        // --- 情况 B: 老 Key (比如从 5 次变成 6 次) ---
        Bucket bucket = map.get(key);
        // 它的目标是 bucket.cnt + 1。检查 bucket 后面那个桶是不是刚好大 1？
        if (bucket.next.cnt == bucket.cnt + 1) {
            map.put(key, bucket.next);
            bucket.next.set.add(key);
        } else {
            // 如果后面断层了（比如从 5 跳到 8），中间新建一个 6
            Bucket newBucket = new Bucket(key, bucket.cnt + 1);
            map.put(key, newBucket);
            insert(bucket, newBucket); // 插在当前 bucket 后面
        }
        
        // 【打扫战场】从旧桶里移除 key
        bucket.set.remove(key);
        if (bucket.set.isEmpty()) {
            remove(bucket); // 如果旧桶空了，物理删除该节点
        }
    }
}
```

**Part 3: 减少计数 (`dec`)**

逻辑和 `inc` 完全对称，只是方向相反。

```java
public void dec(String key) {
    Bucket bucket = map.get(key);
    
    if (bucket.cnt == 1) {
        // 如果原本就是 1，减完就没了，直接从 Map 删掉
        map.remove(key);
    } else {
        // 如果是 5 变 4，看前面的桶是不是 4
        if (bucket.prev.cnt == bucket.cnt - 1) {
            map.put(key, bucket.prev);
            bucket.prev.set.add(key);
        } else {
            // 没路了，新建一个 4 的桶
            Bucket newBucket = new Bucket(key, bucket.cnt - 1);
            map.put(key, newBucket);
            insert(bucket.prev, newBucket); // 插在 prev 的后面 (即 bucket 的前面)
        }
    }
    
    // 【打扫战场】
    bucket.set.remove(key);
    if (bucket.set.isEmpty()) {
        remove(bucket);
    }
}
```

**Part 4: 获取最值**

```java
// 链表是有序的：Head(小) -> ... -> Tail(大)
public String getMaxKey() {
    // 拿 Tail 前面那个桶，随便取一个 key
    // 注意：这里最好加一个 isEmpty 判断，否则空表会报错
    return tail.prev.set.iterator().next(); 
}

public String getMinKey() {
    // 拿 Head 后面那个桶
    return head.next.set.iterator().next();
}
```

#### 5. 【死记硬背点 / 易错点】

1. **Map 存的是什么？**：存的是 `String -> Bucket`。必须能直接定位到它在链表的哪个节点，否则无法 $O(1)$ 找到它的前后邻居。
2. **Set 的作用**：`Bucket` 里必须用 `HashSet` 存 Key。因为题目只要求返回任意一个最大/最小 Key，用 Set 取 `iterator().next()` 是 $O(1)$ 的。如果是 List，删除指定 Key 是 $O(N)$。
3. **新建桶的位置**：
   - `inc` 时，新建桶插在当前桶的**后面** (`insert(bucket, new)`)。
   - `dec` 时，新建桶插在当前桶的**前面** (也就是 `bucket.prev` 的后面 -> `insert(bucket.prev, new)`)。

#### 6. 【复习闪卡 (Flashcard)】

1. **Q: 为了实现全 O(1)，我们需要结合哪两种数据结构？**
   - A: 哈希表 (Map) + 双向链表 (Doubly Linked List)。
2. **Q: 链表中的节点代表什么？**
   - A: 代表**频率（次数）**。所有相同频率的 Key 都在一个节点（桶）里。
3. **Q: 当一个 Key 的次数从 N 变 N+1 时，如果链表中没有 N+1 的节点怎么办？**
   - A: 动态创建一个次数为 N+1 的新节点，插入到 N 节点的后面，然后把 Key 移过去。
