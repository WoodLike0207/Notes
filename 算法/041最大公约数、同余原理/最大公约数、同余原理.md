# 2. 题目练习：第n个神奇的数字

测试链接 : https://leetcode.cn/problems/nth-magical-number/



## 代码

```java
public static int nthMagicalNumber(int n, int a, int b) {
    long lcm = lcm(a, b);
    long ans = 0;

    for(long l = 0, r = (long) Math.min(a, b) * n , m = 0; l <= r; ){
        m = (l + r) / 2;

        if (m/a + m/b - m/lcm >= n) {
            ans = m;
            r = m - 1;
        }else {
            l = m + 1;
        }
    }

    return (int) (ans % 1000000007);
}

public static long gcd(long a, long b) {
    return b == 0 ? a : gcd(b, a % b);
}

public static long lcm(long a, long b) {
    return a / gcd(a, b) * b;
}
```





## 思路

这是 LeetCode 878 题：**第 N 个神奇数字 (Nth Magical Number)**。

这道题是**二分答案法**（Binary Search on Answer）结合**容斥原理**（Inclusion-Exclusion Principle）的经典应用。

------

### 1. 【一句话核心】

**“不做加法做猜想”**：不要试图一个一个生成神奇数字，而是利用**二分查找**去“猜”一个数字 $X$，然后用**容斥原理** $O(1)$ 计算出“小于等于 $X$ 的神奇数字有几个”，看它是否就是我们要找的第 $N$ 个。

### 2. 【算法技巧操作】

- **二分答案 (Binary Search on Answer)**：
  - 答案具有**单调性**：数值越大，包含的神奇数字越多。
  - 我们可以给定一个范围，猜中间值 `mid`，计算 `mid` 是第几个神奇数字。
  - 如果排名 $\ge N$，说明答案可能是 `mid` 或者更小，往左缩 (`r = mid - 1`)。
  - 如果排名 $< N$，说明答案比 `mid` 大，往右找 (`l = mid + 1`)。
- **容斥原理 (Inclusion-Exclusion Principle)**：
  - 如何快速计算 $X$ 以内有多少个能被 $a$ 或 $b$ 整除的数？
  - 公式：**`count = X/a + X/b - X/lcm(a, b)`**。
  - 含义：(能被 $a$ 整除的个数) + (能被 $b$ 整除的个数) - (能被 $a$ 和 $b$ **同时**整除的个数，即被最小公倍数整除，因为这部分加了两次)。
- **数学与溢出控制**：
  - **LCM 计算**：$\text{lcm}(a, b) = (a \times b) / \text{gcd}(a, b)$。代码中写作 `(long) a / gcd(a, b) * b` 是为了防止 `a*b` 先溢出。
  - **区间上界**：第 $N$ 个神奇数字一定不会超过 $N \times \min(a, b)$（最坏情况全是 $\min(a,b)$ 的倍数）。

### 3. 【图解原理：容斥与二分】

我们以 $N=5, a=2, b=3$ 为例。我们要找第 5 个神奇数字。

#### 第一步：理解集合（韦恩图概念）

想象一个数轴，$X=6$ 时的情况：

```java
数值:  1   2   3   4   5   6
----------------------------
被2整除:   ✓       ✓       ✓   (共 3 个: 2, 4, 6) -> 6/2 = 3
被3整除:       ✓           ✓   (共 2 个: 3, 6)    -> 6/3 = 2
----------------------------
合  并:    ✓   ✓   ✓       ✓   (共 4 个: 2, 3, 4, 6)

计算: 3 + 2 = 5？不对，6 被算了两次！
修正: 减去同时被2和3整除的数 (即被 lcm(2,3)=6 整除的数)。
      6/6 = 1 个。
最终: 3 + 2 - 1 = 4 个。
```

#### 第二步：二分查找过程

目标 $N=5$。

上界 $R = 5 \times 2 = 10$。范围 `[0, 10]`。

1. **Guess 1**: `mid = 5`
   - $5/2 + 5/3 - 5/6 = 2 + 1 - 0 = 3$ 个。
   - $3 < 5$，太小了！答案在右边。
   - `L` 变为 6。
2. **Guess 2**: `mid = 8` (区间 [6, 10])
   - $8/2 + 8/3 - 8/6 = 4 + 2 - 1 = 5$ 个。
   - $5 \ge 5$，满足条件！记录 `ans = 8`。
   - 尝试找更小的，`R` 变为 7。
3. **Guess 3**: `mid = 6` (区间 [6, 7])
   - $6/2 + 6/3 - 6/6 = 3 + 2 - 1 = 4$ 个。
   - $4 < 5$，太小了！
   - `L` 变为 7。
4. **Guess 4**: `mid = 7` (区间 [7, 7])
   - $7/2 + 7/3 - 7/6 = 3 + 2 - 1 = 4$ 个。
   - $4 < 5$，太小了！
   - `L` 变为 8。

此时 $L > R$，循环结束。答案是之前记录的 **8**。

*(注：虽然7算出来是4个，8算出来是5个，看似直接跳过了第5个，但实际上第5个神奇数字就是8。因为7不是神奇数字，它对计数没有贡献。)*

### 4. 【代码逐行精读】

```java
public static int nthMagicalNumber(int n, int a, int b) {
    // 1. 预处理最小公倍数 (LCM)
    // 用于容斥原理中减去重复部分
    long lcm = lcm(a, b);
    long ans = 0;
    
    // 2. 确定二分查找范围
    // l: 下界 0
    // r: 上界 N * min(a, b)。这是最坏情况，假设只靠较小的那个数去凑 N 个。
    // 注意必须转 long，防止计算范围时溢出
    for (long l = 0, r = (long) n * Math.min(a, b), m = 0; l <= r;) {
        m = (l + r) / 2; // 取中间值
        
        // 3. 容斥原理计算 (核心 check 逻辑)
        // 1...m 范围内的神奇数字个数 = (m/a) + (m/b) - (m/lcm)
        if (m / a + m / b - m / lcm >= n) {
            // 如果个数 >= n，说明 m 可能是答案，或者答案比 m 更小
            ans = m;
            r = m - 1; // 往左边缩，试图找更小的满足条件的数
        } else {
            // 个数 < n，说明 m 太小了，还没凑够 n 个
            l = m + 1; // 往右边找
        }
    }
    
    // 4. 返回结果取模
    // 题目要求对 10^9 + 7 取模。注意是在最后取模，二分过程中不能取模！
    return (int) (ans % 1000000007);
}

// 欧几里得算法求最大公约数
public static long gcd(long a, long b) {
    return b == 0 ? a : gcd(b, a % b);
}

// 求最小公倍数
public static long lcm(long a, long b) {
    // 先除后乘，防止 a * b 直接溢出 long
    return (long) a / gcd(a, b) * b;
}
```

### 5. 【死记硬背点 / 易错点】

1. **`long` 的使用**：这道题非常容易溢出！
   - `lcm` 计算时要用 long。
   - 二分查找的边界 `r` 和中间值 `m` 必须是 `long`，因为第 $10^9$ 个神奇数字会非常大，远超 `int` 范围。
   - 只有在最后 `return` 时才取模转 `int`。
2. **取模时机**：千万不能在二分查找的 `if` 判断里取模。比如 `m` 很大，取模后变小了，会导致二分逻辑完全错乱。
3. **LCM 公式细节**：写 `(a * b) / gcd(a, b)` 是危险的，要写 `(a / gcd(a, b)) * b`。

### 6. 【复习闪卡】

1. **Q: 求 1 到 X 之间能被 A 或 B 整除的数有多少个（公式）？**
   - A: `X/A + X/B - X/lcm(A, B)`。
2. **Q: 为什么这道题可以用二分查找？**
   - A: 因为数值越大，包含的神奇数字个数单调递增（或不变），满足二分查找的单调性条件。
3. **Q: 为什么二分过程中不能对 `m` 取模？**
   - A: 取模会破坏数值的**单调性**（大小关系），导致无法正确判断 `l` 和 `r` 的移动方向。



# 3. 同余原理



### 1. 介绍背景：为什么要用同余原理？

在算法题（尤其是 LeetCode 和竞赛）中，你经常会看到题目最后有一句话：

> **“答案可能很大，请返回答案对 `1000000007` 取模后的结果。”**

**为什么要这样？**

因为在计算过程中（比如求阶乘、斐波那契数列、排列组合），数值会以指数级爆炸增长。

- `int` 的上限大约是 $2 \times 10^9$。
- `long` 的上限大约是 $9 \times 10^{18}$。
- 但像 $100!$（100的阶乘）这种数，连 `long` 都装不下。

**核心思想：**

同余原理告诉我们，**“边算边取模”和“算完再取模”的结果是一样的（针对加、减、乘）。 所以，为了防止溢出（爆 `long`），我们必须在计算的每一步**都进行取模，把数值一直压制在 `mod` 的范围内。

------

### 2. 加法、乘法：每一步算完直接模

对于加法和乘法，规则非常简单粗暴：**只要发生了运算，立刻取模**。

- **加法公式**：

  $$(a + b) \pmod m = ((a \pmod m) + (b \pmod m)) \pmod m$$

- **乘法公式**：

  $$(a \times b) \pmod m = ((a \pmod m) \times (b \pmod m)) \pmod m$$

**实战写法：**

不要等到循环结束再取模，要在循环里面取模。

Java

```java
// 错误写法：等到最后 ans 早就溢出变成负数了
long ans = 0;
for(int x : nums) {
    ans += x; 
}
return (int)(ans % mod);

// 正确写法：步步取模
long ans = 0;
for(int x : nums) {
    ans = (ans + x) % mod; // 加一次，模一次
}
return (int) ans;
```

------

### 3. 减法：最容易错的地方 `(a - b + m) % m`

减法有一个大坑：在编程语言（如 Java, C++）中，**负数对正数取模，结果依然是负数**。

比如：$2 - 5 = -3$，而 `-3 % 7` 在 Java 中等于 `-3`，但在数学同余中我们希望得到的是 `4`。

为了修正这个问题，我们需要**手动加一个 `m`**，把结果拉回正数范围。

- **减法公式**：

  $$(a - b) \pmod m = (a - b + m) \pmod m$$

**实战写法：**

```java
int mod = 1000000007;
long a = 2;
long b = 5;

// 错误写法：可能得到负数
long ans = (a - b) % mod; // 结果可能是负数

// 正确写法：加一个 mod 再取模
long ans = (a - b + mod) % mod; // 结果永远是正数 [0, mod-1]
```

------

### 4. 防止溢出：乘法中间用 `long`

即使你每一步都取模了，**两个接近 `mod` 的 `int` 相乘**，瞬间结果还是会超过 `int` 的范围，甚至可能超过 `long`（虽然 $10^9+7$ 的平方在 `long` 范围内，但更安全的做法是时刻警惕）。

**场景还原：**

假设 `mod = 10^9 + 7`。

如果有两个数 `a` 和 `b` 都接近 $10^9$（在 `int` 范围内）。

执行 `int c = (a * b) % mod;` 时：

1. CPU 先计算 `a * b`，结果是 $10^{18}$。
2. 此时结果已经爆掉了 `int`（变成了奇怪的负数）。
3. 然后再 `% mod`，得到的一定是错误答案。

**实战写法：**

必须强制把中间结果转为 `long` 进行计算。

```java
int MOD = 1000000007;
int a = 1000000000;
int b = 1000000000;

// 危险写法：a*b 在取模前就已经爆 int 了
int ans = (a * b) % MOD; 

// 安全写法：强制转 long 再乘，算完取模后再转回 int（如果题目要求返回int）
long temp = (long) a * b; // 先变成 long，能装下 10^18
int ans = (int) (temp % MOD);
```

### 总结闪卡 (Flashcard)

1. **Q: 什么时候用同余原理？**
   - A: 当题目要求“对 1000000007 取模”或者数据极大容易溢出时。
2. **Q: 减法取模的公式是什么（死记硬背）？**
   - A: `(a - b + mod) % mod`。千万别忘了加 `mod`。
3. **Q: 两个 `int` 相乘取模，要注意什么？**
   - A: 必须强转 `long`：`(long) a * b % mod`，防止在取模前瞬间溢出。
