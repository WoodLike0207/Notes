# 1. 利用前缀和快速得到区域累加和

测试链接 : https://leetcode.cn/problems/range-sum-query-immutable/



## 代码

```java
class NumArray {
    public int[] sum;

    public NumArray(int[] nums) {
        sum = new int[nums.length + 1];
        for (int i = 1; i < sum.length; i++) {
            sum[i] = sum[i - 1] + nums[i - 1];
        }
    }

    public int sumRange(int left, int right) {
        return sum[right + 1] - sum[left];
    }
}
```



## 思路



### 1. 【一句话核心】

**“空间换时间”**：预先算好“从头开始的累加和”存入数组，将 $O(N)$ 的区间求和操作转化为 $O(1)$ 的**减法操作**。

### 2. 【算法技巧操作】

- **预处理 (Pre-computation)**：
  - 构造函数里跑一次循环，耗时 $O(N)$。
  - 计算出 `sum` 数组，其中 `sum[i]` 表示原数组 `nums` 中**前 i 个元素**的和。
- **索引偏移 (Index Shifting)**：
  - `sum` 数组的长度是 `nums.length + 1`。
  - **`sum[0] = 0`**：这是为了方便计算。当我们要算 `nums[0...i]` 的和时，可以直接用减法，不用单独判断边界。
- **区间减法 (Range Subtraction)**：
  - 想求 `nums[i...j]` 的和？
  - 公式：**`总和(前 j+1 个数) - 总和(前 i 个数)`**。
  - 代码对应：`sum[right + 1] - sum[left]`。

### 3. 【图解原理】

假设 `nums = [10, 20, 30, 40, 50]`。

我们要计算 `nums[1...3]` 的和（即 20 + 30 + 40 = 90）。

**图解详细说明：**

1. **原始数组 `nums`** (索引 0~4)：

   `[ 10, 20, 30, 40, 50 ]`

2. **前缀和数组 `sum`** (索引 0~5)：

   - 长度比 `nums` 多 1。
   - `sum[0]` 永远是 0。
   - `sum[1]` = 10 (前1个)
   - `sum[2]` = 10+20 = 30 (前2个)
   - `sum[3]` = 10+20+30 = 60 (前3个)
   - `sum[4]` = 60+40 = 100 (前4个)
   - `sum[5]` = 100+50 = 150 (前5个)
   - **数组内容**：`[ 0, 10, 30, 60, 100, 150 ]`

3. **计算区间 `sumRange(1, 3)`**：

   - 目标范围：`20, 30, 40`。
   - **大区间**：`0` 到 `3` (即前 4 个数) -> `sum[3+1]` = `sum[4]` = 100。
   - **切掉的部分**：`0` 到 `0` (即前 1 个数) -> `sum[1]` = 10。
   - **结果**：`100 - 10 = 90`。
   - **公式**：`sum[right + 1] - sum[left]`。

### 4. 【代码逐行精读】

Java

```
class NumArray {
    // sum[i] 存储 nums 中前 i 个元素的和
    public int[] sum;

    public NumArray(int[] nums) {
        // 技巧：多开一个空间，sum[0] 默认为 0
        // 这样可以避免处理 left == 0 时的数组越界问题
        sum = new int[nums.length + 1];
        
        // 预处理：O(N)
        for (int i = 1; i < sum.length; i++) {
            // sum[i] = 当前累加和 + 新进来的数字
            // 注意：nums 的索引要偏移，用 i-1
            sum[i] = sum[i - 1] + nums[i - 1];
        }
    }

    // 查询：O(1)
    public int sumRange(int left, int right) {
        // 公式背诵：右边界+1 的前缀和 减去 左边界 的前缀和
        return sum[right + 1] - sum[left];
    }
}
```

### 5. 【死记硬背点 / 易错点】

1. **数组长度定义**：`new int[nums.length + 1]`。一定要 `+1`，否则遇到求 `[0, right]` 的时候，你需要减去 `sum[-1]`，这会报错。
2. **构造循环**：`i` 从 1 开始，`nums` 取值用 `nums[i-1]`。
3. **查询公式**：**`right + 1`** 减 **`left`**。
   - 记忆口诀：**“右加一，减去左”**。
   - 理解：要算 `[left, right]`，就是把 `[0, right]` 这一大段，减去 `[0, left-1]` 这一小段。`sum` 数组里，`sum[k]` 代表前 `k` 个数，所以 `sum[right+1]` 就是前 `right+1` 个数（也就是下标到 `right`），`sum[left]` 就是前 `left` 个数（下标到 `left-1`）。

### 6. 【复习闪卡】

1. **Q: 为什么前缀和数组的长度通常设置为 N+1？**
   - A: 为了让 `sum[0] = 0`，方便处理 `left = 0` 的边界情况，使通用公式 `sum[right+1] - sum[left]` 始终成立。
2. **Q: 频繁查询数组区间和，什么算法最快？**
   - A: 前缀和 (Prefix Sum)，可以将查询复杂度从 $O(N)$ 降为 $O(1)$。
3. **Q: 前缀和数组中 `sum[i]` 的物理意义是什么？**
   - A: 原数组中 **前 i 个** 元素的和（即 `nums[0]...nums[i-1]` 的和）。



# 2. 累加和为k的最长子数组

测试链接 : https://www.nowcoder.com/practice/36fb0fd3c656480c92b569258a1223d5



## 代码

```java
import java.io.*;
import java.util.HashMap;

public class Code02_LongestSubarraySumEqualsAim {
    public static int MAXN = 100001;

    public static int[] arr = new int[MAXN];

    public static int n, aim;

    // key : 某个前缀和
    // value : 这个前缀和最早出现的位置
    public static HashMap<Integer, Integer> map = new HashMap<>();

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StreamTokenizer in = new StreamTokenizer(br);
        PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));
        while (in.nextToken() != StreamTokenizer.TT_EOF) {
            n = (int) in.nval;
            in.nextToken();
            aim = (int) in.nval;
            for (int i = 0; i < n; i++) {
                in.nextToken();
                arr[i] = (int) in.nval;
            }
            out.println(compute());
        }
        out.flush();
        out.close();
        br.close();
    }

    public static int compute() {
        map.clear();
        map.put(0, -1);

        int ans = 0;
        for (int i = 0, sum = 0; i < n; i++) {
            sum += arr[i];

            if (map.containsKey(sum - aim)) {
                ans = Math.max(ans, i - map.get(sum - aim));
            }

            if (!map.containsKey(sum)) {
                map.put(sum, i);
            }
        }

        return ans;
    }
}
```





## 思路

### 1. 【一句话核心】

**“反向查表法”**：不用暴力遍历所有子数组，而是遍历到一个位置 `i` 时，问自己：“以前有没有出现过一个前缀和，它的值等于 `当前前缀和 - aim`？”如果有，中间这段就是答案。

### 2. 【核心原理：前缀和的差分】

子数组 `arr[j...i]` 的累加和可以通过前缀和相减得到：

$$Sum(j...i) = Sum(0...i) - Sum(0...j-1)$$

如果我们希望子数组和为 `aim`，公式变为：

$$aim = Sum(0...i) - Sum(0...j-1)$$

移项得到我们查找的目标：

$$Sum(0...j-1) = Sum(0...i) - aim$$

- **当前状态**：我们要计算以 `i` 结尾的、和为 `aim` 的子数组。
- **已知条件**：`Sum(0...i)` (当前的累加和)。
- **查找目标**：我们需要找到一个最早出现的 `j-1`，使得它的前缀和等于 `Sum(0...i) - aim`。
- **计算长度**：`i - (j-1)`。

### 3. 【图解流程】

假设 `arr = [7, 3, 2, 1, 1, 7]`, `aim = 7`。

**逐步推演：**

1. **初始化**：
   - `Map = {0: -1}`。这是物理公理：一个数都不选，和为0，下标认为是 -1。
   - `sum = 0`, `ans = 0`。
2. **i = 0, value = 7**：
   - `sum` 变为 7。
   - **查**：需要找前缀和 `7 - 7 = 0`。Map里有吗？有！(value 是 -1)。
   - **算**：长度 = `0 - (-1) = 1`。`ans` 更新为 1。
   - **存**：Map 中没有 7，存入 `{7: 0}`。
3. **i = 1, value = 3**：
   - `sum` 变为 10。
   - **查**：需要找 `10 - 7 = 3`。Map里有吗？无。
   - **存**：Map 中没有 10，存入 `{10: 1}`。
4. **i = 2, value = 2**：
   - `sum` 变为 12。
   - **查**：需要找 `12 - 7 = 5`。无。
   - **存**：存入 `{12: 2}`。
5. **i = 3, value = 1**：
   - `sum` 变为 13。
   - **查**：需要找 `13 - 7 = 6`。无。
   - **存**：存入 `{13: 3}`。
6. **i = 4, value = 1**：
   - `sum` 变为 14。
   - **查**：需要找 `14 - 7 = 7`。Map里有吗？有！(value 是 0)。
   - **算**：长度 = `4 - 0 = 4`。`ans` 更新为 4 (子数组是 `3,2,1,1`)。
   - **存**：存入 `{14: 4}`。

### 4. 【代码逐行精读】

```java
public static int compute() {
    map.clear();
    // 【核心细节 1】初始化 Base Case
    // 如果不加这一行，如果数组开头就是 [aim, ...], 
    // sum-aim=0 在 map 里找不到，就会漏掉从头开始的解。
    map.put(0, -1); 
    
    int ans = 0;
    for (int i = 0, sum = 0; i < n; i++) {
        sum += arr[i]; // 计算当前前缀和
        
        // 【核心逻辑 2】查找以前是否出现过 (sum - aim)
        if (map.containsKey(sum - aim)) {
            // i 是当前位置，map.get(...) 是过去那个前缀和结束的位置
            // 两者相减就是中间子数组的长度
            ans = Math.max(ans, i - map.get(sum - aim));
        }
        
        // 【核心细节 3】只记录"最早"出现的位置
        // 我们想求"最长"子数组，所以减数的位置越靠左(越小)越好。
        // 如果 map 里已经有了 sum，说明之前已经出现过这个前缀和，
        // 现在的 i 肯定比之前的 index 大，保留之前的千万别覆盖！
        if (!map.containsKey(sum)) {
            map.put(sum, i);
        }
    }
    return ans;
}
```

### 5. 【IO 优化部分 (StreamTokenizer)】

这段代码使用了 `StreamTokenizer`，这在算法竞赛（如 ACM、蓝桥杯、NowCoder）中非常常见，比 `Scanner` 快几十倍。

- `StreamTokenizer.TT_EOF`: End Of File，判断是否读完。
- `in.nextToken()`: 读取下一个标记。
- `in.nval`: 获取读取到的数字 (默认是 double，需要强转 int)。
- `PrintWriter`: 也就是 `System.out` 的带缓冲版本，输出大量数据时极快。

### 6. 【易错点 / 死记硬背】

1. **Map 存什么？**
   - Key: 前缀和 `sum`。
   - Value: 该前缀和**最早**出现的下标 `index`。
2. **Base Case 不能忘**：
   - 一定要写 `map.put(0, -1)`。这代表“第 -1 个位置（数组开始前）的前缀和是 0”。
3. **更新 Map 的条件**：
   - **只在 Key 不存在时 put**。因为我们要“最长”子数组，所以希望减去的那个前缀和出现得越早越好（下标越小越好）。

### 7. 【复习闪卡】

1. **Q: 为什么要求 `sum - aim`？**
   - A: 因为 `当前前缀和 - 目标前缀和 = aim`，我们想确定中间这段是不是 `aim`，就要反过来找 `目标前缀和 = 当前前缀和 - aim` 是否在 Map 中存在。
2. **Q: `map.put(0, -1)` 的物理含义是什么？**
   - A: 它代表一个“空数组”的前缀和是 0，位置在数组下标 0 之前。这使得从下标 0 开始的子数组也能被通用公式 `i - prev_index` 计算出来。
3. **Q: 如果数组全是正数，可以用什么更优的方法？**
   - A: 可以用 **滑动窗口 (Sliding Window)**，空间复杂度 $O(1)$。但本题因为有**负数和0**，前缀和不再单调递增，滑动窗口失效，必须用 HashMap 模型。



# 3. 累加和为k的子数组数量

测试链接 : https://leetcode.cn/problems/subarray-sum-equals-k/



## 代码

```java
public class Code03_NumberOfSubarraySumEqualsAim {
    public int subarraySum(int[] nums, int aim) {
        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, 1);

        int sum = 0;
        int ans = 0;
        for (int i = 0; i < nums.length; i++) {
            sum += nums[i];
            ans += map.getOrDefault(sum - aim, 0);
            map.put(sum, map.getOrDefault(sum, 0) + 1);
        }

        return ans;
    }
}
```



## 思路

这是为你整理的 **Code03_NumberOfSubarraySumEqualsAim** (累加和为给定值的子数组数量) 复习笔记。

这道题对应 LeetCode 560 题：**Subarray Sum Equals K**。它是上一题（求最长子数组长度）的孪生兄弟，核心思路一样，但 Map 的含义变了。

------

### 📝 算法复习笔记：累加和为给定值的子数组数量

### 1. 【一句话核心】

**“前缀和计数器”**：遍历数组计算前缀和时，回头问 Map：“此前有多少个前缀和等于 `当前前缀和 - aim`？”如果有 N 个，说明有 N 个子数组是以当前位置结尾且和为 `aim` 的。

### 2. 【Map 含义的重大变化】

虽然还是用 Map + 前缀和，但这道题与“求最长长度”有本质区别：

| **特性**         | **求最长长度 (Longest)**       | **求数量 (Count)**          |
| ---------------- | ------------------------------ | --------------------------- |
| **Map Value**    | **最早出现的下标 (Index)**     | **出现的次数 (Frequency)**  |
| **Map Put 策略** | 只存**第一次** (`putIfAbsent`) | 每次都**更新/累加** (`put`) |
| **Base Case**    | `map.put(0, -1)` (虚拟下标)    | `map.put(0, 1)` (虚拟次数)  |
| **计算逻辑**     | `i - map.get(...)`             | `ans += map.get(...)`       |

### 3. 【核心推导】

我们寻找的是子数组 `nums[j...i]` 的和为 `aim`。

推导公式：

$$Sum[j...i] = PrefixSum[i] - PrefixSum[j-1] == aim$$

移项得：

$$PrefixSum[j-1] = PrefixSum[i] - aim$$

- **PrefixSum[i]**: 当前累加到的和。
- **aim**: 目标值。
- **PrefixSum[j-1]**: 我们要在 Map 里寻找的目标。
- **结论**: 如果 Map 里记录了 `PrefixSum[i] - aim` 出现了 **3次**，那就意味着有 **3个** 不同的起点 `j`，都能和当前终点 `i` 组成满足条件的子数组。

### 4. 【图解流程】

假设 `nums = [1, 2, 1, 2, 1]`, `aim = 3`。

**详细追踪：**

1. **初始化**:
   - `map = {0: 1}` (代表和为0的前缀出现过1次，即空数组)。
   - `sum = 0`, `ans = 0`。
2. **i=0, num=1**:
   - `sum` = 1。
   - **找**: `1 - 3 = -2`。Map里有吗？无。
   - **存**: Map `{0:1, 1:1}`。
3. **i=1, num=2**:
   - `sum` = 3。
   - **找**: `3 - 3 = 0`。Map里有吗？**有！(1次)**。
   - **加**: `ans += 1` (找到子数组 `[1, 2]`)。
   - **存**: Map `{0:1, 1:1, 3:1}`。
4. **i=2, num=1**:
   - `sum` = 4。
   - **找**: `4 - 3 = 1`。Map里有吗？**有！(1次)**。
   - **加**: `ans += 1` (找到子数组 `[2, 1]`，对应前缀和为1的位置是idx 0)。
   - **存**: Map `{..., 4:1}`。
5. **i=3, num=2**:
   - `sum` = 6。
   - **找**: `6 - 3 = 3`。Map里有吗？**有！(1次)**。
   - **加**: `ans += 1` (找到子数组 `[1, 2, 1]`，对应前缀和为3的位置是idx 1)。
   - **存**: Map `{..., 3:2, ...}` -> **注意这里3出现了第2次**。
6. **i=4, num=1**:
   - `sum` = 7。
   - **找**: `7 - 3 = 4`。Map里有吗？**有！(1次)**。
   - **加**: `ans += 1`。
   - **存**: Map更新。

### 5. 【代码逐行精读】

Java

```
public int subarraySum(int[] nums, int aim) {
    // Key: 前缀和
    // Value: 这个前缀和出现的次数
    Map<Integer, Integer> map = new HashMap<>();
    
    // 【易错点 1】初始化
    // 代表前缀和为 0 的情况已经出现了 1 次（什么都不选的时候）
    // 如果 nums=[3], aim=3。sum=3, 找 3-3=0。如果没有这一行，结果就是0，错了。
    map.put(0, 1);

    int sum = 0;
    int ans = 0;
    for (int i = 0; i < nums.length; i++) {
        sum += nums[i];
        
        // 【核心逻辑】
        // 必须先查 ans，再 put sum！
        // 也就是问：在我之前，有多少个前缀和等于 (sum - aim)？
        if (map.containsKey(sum - aim)) {
            ans += map.get(sum - aim);
        }
        
        // 【更新逻辑】
        // 累加次数。如果之前没有就是 1，如果有就是 N+1。
        map.put(sum, map.getOrDefault(sum, 0) + 1);
    }

    return ans;
}
```

### 6. 【死记硬背点 / 易错点】

1. **先查后存**：在循环体内，一定要**先** `get` 计算 `ans`，**再** `put` 更新 map。
   - *原因*：如果你先 put，当 `aim = 0` 时，你会把当前算出的前缀和自己减自己（`sum - 0 = sum`），错误地把“空集”或者“当前元素自己”算进去（取决于具体逻辑），标准做法是只找**之前**的前缀。
2. **Base Case**：`map.put(0, 1)`。含义是和为0的前缀默认有1个。
3. **Value 的含义**：这题 Value 是**次数**，不是下标！

### 7. 【复习闪卡】

1. **Q: 为什么这道题的 Map Value 存的是次数，而不是下标？**
   - A: 因为题目求的是“有多少个”，而不是“哪一个最长”。同一个前缀和可能出现多次（比如有负数抵消时），每一次出现都代表一种可能的子数组切分方案。
2. **Q: `map.put(0, 1)` 的作用是什么？**
   - A: 处理从数组下标 0 开始的子数组（即 `nums[0...i]` 正好等于 `aim` 的情况）。如果不加，`sum - aim = 0` 会查不到，导致漏算。
3. **Q: 循环中能不能先 `map.put` 再 `map.get`？**
   - A: 不能。必须先查之前的记录，再把自己的记录放进去，确保查到的是**严格处于当前位置之前**的前缀和。



# 4. 正负一样多的最长子数组

测试链接 : https://www.nowcoder.com/practice/545544c060804eceaed0bb84fcd992fb



## 代码

```java
import java.io.*;
import java.util.HashMap;

public class Code04_PositivesEqualsNegtivesLongestSubarray {
    public static int MAXN = 100001;

    public static int[] arr = new int[MAXN];

    public static int n;

    public static HashMap<Integer, Integer> map = new HashMap<>();

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StreamTokenizer in = new StreamTokenizer(br);
        PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));
        while (in.nextToken() != StreamTokenizer.TT_EOF) {
            n = (int) in.nval;
            for (int i = 0, num; i < n; i++) {
                in.nextToken();
                num = (int) in.nval;
                arr[i] = num != 0 ? (num > 0 ? 1 : -1) : 0;
            }
            out.println(compute());
        }
        out.flush();
        out.close();
        br.close();
    }

    public static int compute() {
        map.clear();
        map.put(0, -1);
        int ans = 0;

        for (int i = 0, sum = 0; i < n; i++) {
            sum += arr[i];

            if (map.containsKey(sum)) {
                ans = Math.max(ans, i - map.get(sum));
            }else {
                map.put(sum, i);
            }
        }
        
        return ans;
    }
}
```



## 思路

这道题是 **“转化思维” + “前缀和模型”** 的经典结合。它本质上就是求 **“累加和为 0 的最长子数组”**。

### 1. 【一句话核心】

**“数值归一化”**：把所有复杂的正数变为 `+1`，所有负数变为 `-1`，0 变为 `0`。题目瞬间变成了 **“求累加和为 0 的最长子数组长度”**。

### 2. 【核心转化逻辑】

为什么能这么做？

- 题目只关心 **个数**，不关心数值大小。
- 如果一个子数组中：(正数个数) == (负数个数)。
- 那么转换后：(+1 的个数) == (-1 的个数)。
- 它们加起来的总和一定是 **0**。
- **关于 0 的处理**：0 既不是正数也不是负数。把它变为 `0`，加入累加和时不会改变正负的平衡，但会增加子数组的物理长度。这完全符合题意。

### 3. 【算法步骤】

1. **数据清洗 (Pre-process)**：
   - 读取原数组，正数 $\to 1$，负数 $\to -1$，0 $\to 0$。
2. **前缀和 + 哈希表 (Map)**：
   - 问题转化为：**找最长的子数组，其累加和 `sum = 0`**。
   - 根据前缀和公式：`Sum[j...i] = PrefixSum[i] - PrefixSum[j-1]`。
   - 如果要 `Sum[j...i] == 0`，则意味着 `PrefixSum[i] == PrefixSum[j-1]`。
   - **策略**：只需要找 **“和你当前前缀和相等”** 的那个前缀和，最早出现在什么位置。

### 4. 【图解原理】

假设输入数组：`[ 10,  -5,   0,  20,  -8 ]`

**第一步：归一化**

```
arr` 变为：`[  1,  -1,   0,   1,  -1 ]
```

**第二步：前缀和推导**

**详细推演：**

1. **Init**: `Map = {0: -1}` (和为0最早在-1位置), `sum = 0`, `ans = 0`。
2. **i=0 (Val=1)**: `sum` = 1。Map无1。存 `{1: 0}`。
3. **i=1 (Val=-1)**: `sum` = 0。
   - 查 Map 有 0 吗？**有** (在 -1 位置)。
   - 长度 = `1 - (-1) = 2`。 `ans = 2`。 (子数组: `10, -5`)
   - Map有0了，不更新 (保留最早的)。
4. **i=2 (Val=0)**: `sum` = 0。
   - 查 Map 有 0 吗？**有** (在 -1 位置)。
   - 长度 = `2 - (-1) = 3`。 `ans = 3`。 (子数组: `10, -5, 0`)
5. **i=3 (Val=1)**: `sum` = 1。
   - 查 Map 有 1 吗？**有** (在 0 位置)。
   - 长度 = `3 - 0 = 3`。 `ans` 还是 3。
6. **i=4 (Val=-1)**: `sum` = 0。
   - 查 Map 有 0 吗？**有** (在 -1 位置)。
   - 长度 = `4 - (-1) = 5`。 `ans = 5`。 (子数组: `10, -5, 0, 20, -8`)

**归一化部分**

```
// num > 0 变 1
// num < 0 变 -1
// num == 0 变 0
arr[i] = num != 0 ? (num > 0 ? 1 : -1) : 0;
```

**计算最长子数组 (和为 0)**

Java

```
public static int compute() {
    map.clear();
    // 【重要 Base Case】
    // 整个数组从头开始累加和就是0的情况
    map.put(0, -1);
    
    int ans = 0;
    for (int i = 0, sum = 0; i < n; i++) {
        sum += arr[i];
        // 核心逻辑：
        // 1. 如果 map 里出现过当前的 sum，说明中间这段的和是 0。
        //    直接计算长度，尝试更新最大值。
        if (map.containsKey(sum)) {
            ans = Math.max(ans, i - map.get(sum));
        } else {
            // 2. 如果没出现过，才放进去。
            //    因为我们要"最长"，所以保留最早出现的那个下标。
            map.put(sum, i);
        }
    }
    return ans;
}
```

### 6. 【易错点 / 死记硬背】

1. **为什么 `aim` 是 0？**
   - 因为经过 `+1/-1` 转换后，数量相等在数学上等价于和为 0。
2. **`map.put` 的时机**：
   - 只有 **`else`** 的时候才 put。如果 key 已经存在，绝对不能覆盖！因为我们要找最早的下标（使得 `i - j` 最大）。
3. **0 的处理**：
   - 这道题里，0 虽然不贡献计数，但它占位置。归一化为 0 正好满足“不改变和，但增加索引距离”的特性。

### 7. 【复习闪卡】

1. **Q: 遇到“A的个数等于B的个数”这类子数组问题，第一反应是什么？**
   - A: **赋值法**。将 A 变成 1，B 变成 -1，然后求和为 0 的最长子数组。
2. **Q: 在求“最长”子数组时，Map 如果已经存在当前的前缀和，要更新下标吗？**
   - A: **不要更新**。保留老的下标，因为老的下标越小，和当前位置的距离（子数组长度）就越长。
3. **Q: 为什么输入处理时 `arr[i]` 要存转化后的值，而不是原值？**
   - A: 因为后续计算只关心正负属性，原值的大小（比如 100 和 1）对题目没有区别，存原值反而会干扰前缀和的计算。



# 5. 表现良好的最长时间段

测试链接 : https://leetcode.cn/problems/longest-well-performing-interval/



## 代码

```java
public int longestWPI(int[] hours) {
    Map<Integer, Integer> map = new HashMap<>();
    map.put(0, -1);

    int ans = 0;
    for (int i = 0, sum = 0; i < hours.length; i++) {
        sum += hours[i] > 8 ? 1 : -1;

        if (sum > 0) {
            ans = i + 1;
        }else {
            if (map.containsKey(sum - 1)) {
                ans = Math.max(ans, i - map.get(sum - 1));
            }
        }

        if (!map.containsKey(sum)) {
            map.put(sum, i);
        }
    }

    return ans;
}
```



## 思路

这道题是 **前缀和 + 哈希表** 的高阶应用，它巧妙地利用了数据的**连续性**（+1/-1）来简化查找逻辑。



### 1. 【一句话核心】

**“劳逸转化，只找邻居”**：将大于8小时记为 `+1`，小于等于8小时记为 `-1`，问题转化为求**累加和大于0的最长子数组**。在累加和小于等于0时，只需要找 `sum - 1` 最早出现的位置。

### 2. 【核心转化逻辑】

- **数值映射**：
  - 劳累的一天 (>8h) $\rightarrow$ `+1`
  - 不劳累的一天 (≤8h) $\rightarrow$ `-1`
- **目标**：找一个最长的子数组，使得其元素之和 `> 0`。
- **前缀和思路**：
  - 如果 `sum > 0`：说明从数组开头到当前位置，劳累天数已经多于不劳累天数了，直接取当前全长 `i + 1`。
  - 如果 `sum <= 0`：说明我们要“砍掉”前面一段“负能量”的前缀。

### 3. 【最难理解点：为什么只找 `sum - 1`？】

理解这个逻辑的关键在于两个字：**“连续”**。

因为数组里只有 `+1` 和 `-1`，前缀和的变化就像是**走楼梯**，你不能跳步。你要从 0 走到 -2，必须先踩过 -1。

------

#### 3.1 我们的目标是什么？

假设我们现在来到了位置 `i`，前缀和是 `curSum`（比如是 **-5**）。

我们要找一个之前的某个位置 `j`，它的前缀和是 `prevSum`。

使得中间这一段子数组的和大于 0：

$$curSum - prevSum > 0$$

也就是要：

$$prevSum < curSum$$

既然 `curSum` 是 **-5**，那么 `prevSum` 可以是 **-6, -7, -8, ...** 只要比 -5 小就行。

**关键问题来了：** 在 -6, -7, -8 这些候选人里，选谁能让子数组最长？

------

#### 3.2 为什么只选 `curSum - 1`？

这里有一个**“楼梯定律”**：

> 如果前缀和是从 0 开始变化的，且每一步只能 +1 或 -1。那么，**数字 K 第一次出现的位置，一定比 K-1 第一次出现的位置要早。**

**通俗解释（下楼梯理论）：**

想象前缀和是一条下坡的路。

- 你从 **0楼** 出发。
- 现在你此时此刻在 **-5楼** (`curSum`)。
- 你想找一个比你位置更低的历史位置作为起点（比如 -6楼、-7楼...）。

**请问：你历史上第一次到达 -6楼 早，还是第一次到达 -7楼 早？**

答案是：**肯定是 -6楼 早。**

因为你不可能通过“瞬移”跳过 -6楼 直接到达 -7楼。你必须先经过 -6，再往下走才能到 -7。

**结论：**

- `map.get(-6)` 的下标 **一定小于** `map.get(-7)` 的下标。
- 我们要找**最长**子数组，就是找**下标最小（最早）**的起点。
- 所以，**最早的 -6** 一定比 **最早的 -7** 更靠前，效果更好。

因此，我们不需要去试 -7, -8, -9... **只要看 `curSum - 1` (即 -6) 就足够了！**

------

#### 3.3 图解推演

让我们看一个具体的例子：`[-1, -1, -1, 1]`

- **Init**: `map = {0: -1}`
- **i = 0 (Val = -1)**:
  - `sum = -1`。
  - Map 记录：`-1` 最早出现在 idx **0**。 `map={0:-1, -1:0}`
- **i = 1 (Val = -1)**:
  - `sum = -2`。
  - Map 记录：`-2` 最早出现在 idx **1**。 `map={..., -2:1}`
  - *注意：要到 -2，必须先经过 -1。*
- **i = 2 (Val = -1)**:
  - `sum = -3`。
  - Map 记录：`-3` 最早出现在 idx **2**。 `map={..., -3:2}`
- **i = 3 (Val = 1) —— 关键时刻！**:
  - `sum = -2`。
  - 现在我们在 idx 3，高度是 **-2**。
  - 我们要找一个比 -2 小的历史高度。候选有：`-3` (idx 2)。
  - **思考**：如果有 `-4`，它会出现在哪里？肯定在 `-3` 之后（比如 idx 3 以后），或者根本没出现过。
  - 所以我们直接找 `sum - 1` 即 `-3`。
  - 查表：`-3` 最早在 idx 2。
  - 子数组：`idx 3` 到 `idx 2` 之间。长度 `3 - 2 = 1`。

#### 总结

代码中这句：

```java
if (map.containsKey(sum - 1)) {
    ans = Math.max(ans, i - map.get(sum - 1));
}
```

背后的逻辑链条是：

1. 我想找一个区间和 `>0`。
2. 所以我需要找一个前缀和 `prev < current`。
3. 因为数据连续性，`current - 1` 的最早出现位置，一定优于（早于）`current - 2` 的最早出现位置。
4. 所以**贪心策略**就是：只看 `current - 1` 这一位邻居就够了。

### 4. 【图解流程】

假设 `hours = [6, 6, 9, 6, 9, 9, 6]`。

转化后：`[-1, -1, 1, -1, 1, 1, -1]`。

**详细推演：**

1. **Init**: `map = {0: -1}`, `ans = 0`.
2. **i=0 (-1)**:
   - `sum = -1`。 `sum <= 0`。
   - 找 `sum - 1 = -2`？Map无。
   - 存 `{ -1 : 0 }`。

   - `sum = -2`。
   - 找 `sum - 1 = -3`？Map无。
   - 存 `{ -2 : 1 }`。
4. **i=2 (+1)**:
   - `sum = -1`。
   - 找 `sum - 1 = -2`？Map有！(idx 1)。
   - 长度 `2 - 1 = 1`。 `ans = 1`。
   - `-1` 已存在，不更新 Map。
5. **i=3 (-1)**:
   - `sum = -2`。
   - 找 `sum - 1 = -3`？Map无。
   - `-2` 已存在，不更新。
6. **i=4 (+1)**:
   - `sum = -1`。
   - 找 `sum - 1 = -2`？Map有！(idx 1)。
   - 长度 `4 - 1 = 3`。 `ans = 3`。
7. **i=5 (+1)**:
   - `sum = 0`。 `sum <= 0`。
   - 找 `sum - 1 = -1`？Map有！(idx 0)。
   - 长度 `5 - 0 = 5`。 `ans = 5`。
8. **i=6 (-1)**:
   - `sum = -1`。
   - 找 `sum - 1 = -2`？Map有！(idx 1)。
   - 长度 `6 - 1 = 5`。 `ans` 保持 5。

### 5. 【代码逐行精读】

```java
public static int longestWPI(int[] hours) {
    HashMap<Integer, Integer> map = new HashMap<>();
    // Base Case: 0 的最早位置是 -1
    map.put(0, -1);
    
    int ans = 0;
    for (int i = 0, sum = 0; i < hours.length; i++) {
        // 核心转化：>8小时记1，否则记-1
        sum += hours[i] > 8 ? 1 : -1;
        
        // 情况 1: 整个前缀就是"表现良好"的
        if (sum > 0) {
            ans = i + 1;
        } else {
            // 情况 2: 前缀是负的，需要减去一个更小的负数
            // 根据连续性性质，只需要找 sum - 1
            if (map.containsKey(sum - 1)) {
                ans = Math.max(ans, i - map.get(sum - 1));
            }
        }
        
        // 只记录最早出现的位置 (为了让子数组更长)
        if (!map.containsKey(sum)) {
            map.put(sum, i);
        }
    }
    return ans;
}
```

### 6. 【易错点 / 死记硬背】

1. **为什么 `sum > 0` 不需要查表？**
   - 因为如果当前 `sum > 0`，意味着从数组起点到现在的正数已经多于负数了，这肯定比任何“切掉一段前缀”得到的子数组更长。
2. **为什么 Map 不更新？**
   - `if (!map.containsKey(sum))`。我们要找的是**最长**子数组，所以减数的位置越靠前（下标越小），结果越大。
3. **Magic Value `sum - 1`**：
   - 这是本题特有的优化。仅适用于数值只有 `+1` 和 `-1` 的场景。如果数值是 `+3` 和 `-2`，这个规律就不成立了。

### 7. 【复习闪卡】

1. **Q: 这道题如何转化为前缀和问题？**
   - A: 把 $>8$ 看作 $1$，$\le 8$ 看作 $-1$，求累加和 $>0$ 的最长子数组。
2. **Q: 当 `sum <= 0` 时，为什么要找 `map.get(sum - 1)`？**
   - A: 因为我们要找 `Prefix[i] - Prefix[j] > 0`。由于前缀和是连续变化的，要让 `j` 最小（位置最早），最早出现的 `sum-1` 一定优于 `sum-2` 等更小的值。
3. **Q: 为什么不需要检查 `sum - 2` 或更小的数？**
   - A: 因为在下降过程中，你必须先经过 `sum-1` 才能到达 `sum-2`。所以 `sum-1` 的最早出现位置一定早于 `sum-2` 的最早出现位置。



# 6. 移除最短长度为了被p整除

测试链接 : https://leetcode.cn/problems/make-sum-divisible-by-p/



## 代码

```java
public class Code06_MakeSumDivisibleByP {
    public int minSubarray(int[] nums, int p) {
        int mod = 0;
        for (int num : nums) {
            mod = (mod + num) % p;
        }

        if (mod == 0) {
            return 0;
        }

        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, -1);

        int ans = Integer.MAX_VALUE;

        for (int i = 0, cur = 0, find; i < nums.length; i++) {
            cur = (cur + nums[i]) % p;
            find = cur >= mod ? cur - mod : cur + p - mod;

            if (map.containsKey(find)) {
                ans = Math.min(ans, i - map.get(find));
            }

            map.put(cur, i);
        }

        return ans == nums.length ? -1 : ans;
    }
}
```



## 思路

这道题是 **前缀和 + 同余定理** 的经典应用。它和之前几道题最大的不同在于：**我们要找最短的子数组，而不是最长的**，并且引入了**取模（Modulo）**运算。

------

### 1. 【一句话核心】

**“整体补救法”**：先算整个数组的余数 `mod`，如果 `mod` 不为 0，说明数组“多了”一部分。我们要做的就是找到一个**最短的子数组**，它的余数也是 `mod`，把这块“累赘”切掉，剩下的就能被 `P` 整除了。

### 2. 【核心推导：同余定理】

1. **目标**：`(TotalSum - SubArraySum) % p == 0`

2. **移项**：`TotalSum % p == SubArraySum % p`

3. **定义**：设 `TotalSum % p` 为 **`mod`**（这是我们要消除的“整体余数”）。

   - 问题转化为：**找到一个最短子数组，其元素和除以 `P` 的余数也是 `mod`。**

4. **前缀和转换**：

   - `SubArraySum = PrefixSum[i] - PrefixSum[j]`

   - `(PrefixSum[i] - PrefixSum[j]) % p == mod`

   - 移项找目标 `j`：

     **`PrefixSum[j] % p == (PrefixSum[i] - mod) % p`**

### 3. 【算法关键点】

- **我们要找谁 (`find`)？**
  - 当前前缀和余数是 `cur`，我们要找的历史前缀和余数是 `find`。
  - 公式：`find = (cur - mod + p) % p`。
  - *注意：因为 `cur - mod` 可能是负数，所以要 `+p` 再取模。*
- **Map 存什么？**
  - **Key**: 前缀和对 `p` 的余数。
  - **Value**: 该余数 **最晚（最近）** 出现的位置。
  - *区别*：求最长子数组时保留“最早”的位置；这里求**最短**子数组，所以要不断更新 Value 为当前位置 `i`，这样 `i - map.get(find)` 才会最小。

### 4. 【图解原理】

假设 `nums = [3, 1, 4, 2]`, `p = 6`。

总和 = 10，`10 % 6 = 4`。

**任务：找到一个最短子数组，其余数为 4。**

**详细推演：**

1. **Init**: `mod = 4`。 Map `{0: -1}`。
2. **i=0 (3)**: `cur = 3`。
   - 找 `(3 - 4) % 6` -> `-1` -> `5`。Map无。
   - 更新 Map `{0:-1, 3:0}`。
3. **i=1 (1)**: `cur = (3+1)%6 = 4`。
   - 找 `(4 - 4) % 6 = 0`。Map有 `0` (在 -1)。
   - 长度 `1 - (-1) = 2`。 (移除了 `[3, 1]`, 剩 `[4, 2]`=6，整除)。
   - 更新 Map `{..., 4:1}`。
4. **i=2 (4)**: `cur = (4+4)%6 = 2`。
   - 找 `(2 - 4) % 6` -> `-2` -> `4`。Map有 `4` (在 1)。
   - 长度 `2 - 1 = 1`。 (移除了 `[4]`, 剩 `[3, 1, 2]`=6，整除)。`ans` 更新为 1。
   - 更新 Map `{..., 2:2}`。
5. **i=3 (2)**: `cur = (2+2)%6 = 4`。
   - 找 `(4 - 4) % 6 = 0`。Map有 `0` (在 -1)。
   - 长度 `3 - (-1) = 4` (移除整个数组，非法，暂存)。
   - 最终对比，`ans = 1`。

### 5. 【代码逐行精读】

```java
public static int minSubarray(int[] nums, int p) {
    // 1. 先求整体的余数
    int mod = 0;
    for (int num : nums) {
        mod = (mod + num) % p;
    }
    // 如果整体已经能整除，不需要移除
    if (mod == 0) {
        return 0;
    }

    // Key: 前缀和 % p 的余数
    // Value: 该余数出现的下标
    HashMap<Integer, Integer> map = new HashMap<>();
    map.put(0, -1);
    
    int ans = Integer.MAX_VALUE;
    
    // cur: 当前前缀和的余数
    // find: 我们希望在 map 中找到的历史余数
    for (int i = 0, cur = 0, find; i < nums.length; i++) {
        cur = (cur + nums[i]) % p;
        
        // 2. 计算目标余数 find
        // 公式其实就是: (cur - mod + p) % p
        // 代码里用了三目运算符写法，避免负数取模的问题
        find = cur >= mod ? (cur - mod) : (cur + p - mod);
        
        if (map.containsKey(find)) {
            // 3. 求最短长度：i - map.get(find)
            ans = Math.min(ans, i - map.get(find));
        }
        
        // 4. 【关键差异】
        // 这里必须每次都 put 更新！
        // 因为我们要找"最短"移除长度，所以希望 map.get(find) 的下标越大越好（离 i 越近越好）。
        map.put(cur, i);
    }
    
    // 如果 ans 还是初始值，或者 ans 等于数组长度（题目要求不能移除整个数组），返回 -1
    return ans == nums.length ? -1 : ans;
}
```

### 6. 【易错点 / 死记硬背】

1. **Map 更新策略**：
   - **求最长**子数组（如累加和为 K）：只存**第一次**出现的下标 (`putIfAbsent`)。
   - **求最短**子数组（如本题）：存**最后一次**出现的下标 (每次都 `put` 覆盖)。
2. **负数取模处理**：
   - 在 Java 中，`(-2) % 6 = -2`，但我们通常需要正余数 `4`。
   - 通用写法：`(a % p + p) % p`。
   - 本题写法：`cur >= mod ? (cur - mod) : (cur + p - mod)`，手动修正负数。
3. **不能移除整个数组**：
   - 最后返回值要判断 `ans == nums.length`，如果是，说明必须删光才行，但这不符合题目要求，返回 -1。

### 7. 【复习闪卡】

1. **Q: 为什么这道题要找 `SubArraySum % p == TotalSum % p`？**
   - A: 因为 `TotalSum = Remaining + SubArray`。要让 `Remaining % p == 0`，根据同余性质，必须有 `TotalSum` 和 `SubArray` 对 `p` 同余。
2. **Q: 这道题 Map 里的 Value 需要像以前那样只存第一次吗？**
   - A: **绝对不要**。我们要找最短的切除段，所以被减数的位置越靠后（越大），切掉的长度 `i - j` 就越短。所以 Map 要一直更新为最新位置。
3. **Q: 如果 `find` 算出来是负数怎么办？**
   - A: 必须加 `p` 转为正数。在环形/同余问题中，`-x` 和 `p-x` 是等价的。



# 7. 元音偶数次的最长子串长度

测试链接 : https://leetcode.cn/problems/find-the-longest-substring-containing-vowels-in-even-counts/



## 代码

```java
public class Code07_EvenCountsLongestSubarray {
    public int findTheLongestSubstring(String s) {
        int n = s.length();
        int[] map = new int[32];

        Arrays.fill(map, -2);
        map[0] = -1;
        int ans = 0;

        for (int i = 0, status = 0, m; i < n; i++) {
            m = move(s.charAt(i));

            if (m != -1) {
                status ^= 1 << m;
            }

            if (map[status] != -2) {
                ans = Math.max(ans, i - map[status]);
            }else {
                map[status] = i;
            }
        }

        return ans;
    }

    public int move(char cha) {
        switch (cha) {
            case 'a': return 0;
            case 'e': return 1;
            case 'i': return 2;
            case 'o': return 3;
            case 'u': return 4;
            default: return -1;
        }
    }
}
```





## 思路

这道题是 **前缀和 + 状态压缩 (Bitmask)** 的教科书级应用。它把“前缀和”的概念从简单的数字累加，升华到了二进制位的异或状态。



### 1. 【一句话核心】

**“奇偶状态压缩”**：不用分别记录5个元音的具体出现次数，只记录它们的**奇偶性**（0偶1奇）。用一个 5 位的二进制数代表当前的前缀状态，如果在两个不同位置出现了**相同的二进制状态**，说明中间这段子字符串的所有元音都相互抵消了（都出现了偶数次）。

### 2. 【核心难点：状态压缩 (State Compression)】

我们有 5 个元音：`a, e, i, o, u`。

如果用哈希表存 `{ 'a': 3, 'b': 2... }` 太重了，而且我们根本不关心它是出现了 100 次还是 102 次，只关心是 **奇数** 还是 **偶数**。

- **奇偶性的数学运算**：异或 (XOR, `^`)。
  - `0 ^ 1 = 1` (偶变奇)
  - `1 ^ 1 = 0` (奇变偶)
- **5个元音的状态**：用一个整数的低5位来表示。
  - `00000` : a,e,i,o,u 都是偶数次。
  - `00001` : a 是奇数次，其他是偶数次。
  - `10000` : u 是奇数次，其他是偶数次。
  - 范围：`00000` ~ `11111` (也就是 0 ~ 31)。

### 3. 【核心推导：为什么找“相同状态”？】

假设：

- 位置 `j` 的前缀状态是 `status_j`。
- 位置 `i` 的前缀状态是 `status_i`。
- 如果我们希望子数组 `[j+1 ... i]` 中所有元音出现偶数次，意味着这段子数组的状态必须是 `00000`。

根据异或性质：

$$status_i \oplus status_j = \text{substring\_status}$$

$$status_i \oplus status_j = 0$$

$$\Rightarrow status_i = status_j$$

**结论：** 只要当前的 `status` 在之前出现过，那么 **(上一次出现的位置 ... 当前位置]** 这段子串，就是满足条件的（所有元音都增加了偶数次，导致状态没变）。



### 4. 解释map

这就好比你在打游戏时的**“存档记录”**。

这个 `int[] map = new int[32]` 在逻辑上其实就是一个 **哈希表 (HashMap)**，只不过因为它的 Key 只有 32 种可能，所以我们为了省空间和速度，直接用数组下标来代替 Key。

一定要把这个数组拆成两部分看：**下标 (Index)** 和 **值 (Value)**。

##### 4.1 数组的下标 (Index) 代表什么？

**下标代表：当前元音奇偶性的“状态”。**

我们有 5 个元音 `u, o, i, e, a`。每个元音只有两种情况：出现**偶数次**（记为 0）或 **奇数次**（记为 1）。

组合起来，就是一个 5 位的二进制数。

- `00000` (下标 0): 所有元音都出现了偶数次。
- `00001` (下标 1): 只有 'a' 出现了奇数次，其他偶数次。
- `00010` (下标 2): 只有 'e' 出现了奇数次，其他偶数次。
- ...
- `11111` (下标 31): 所有元音都出现了奇数次。

因为 $2^5 = 32$，所以状态范围是 `0` 到 `31`。这就是为什么数组大小是 32。

##### 4.2 数组的值 (Value) 代表什么？

**值代表：这个状态“最早”是在字符串的第几个位置出现的。**

- `map[status] = i` 的意思是：**“兄弟，`status` 这个奇偶组合，最早是在下标 `i` 此时此刻形成的。”**

##### 4.3 为什么要存这个？（核心逻辑）

这利用了异或的性质：**同性相消**。

想象你在操场跑步：

1. **位置 A (下标 2)**：你目前的状态是 `00010` (只有 'e' 是奇数)。我们记下来 `map[2] = 2`。
2. **跑了一段路 (子数组)...** 这段路里可能有好几个元音。
3. **位置 B (下标 8)**：你现在的状态**又是** `00010` 了！

**这意味着什么？**

意味着从 A 到 B 中间这段路，所有元音的变化量，肯定都是**偶数次**。

- 如果中间多了一个 'a'，状态就会变成 `00011`，不相等。
- 只有中间多了 2个 'a'，或者 4个 'e'，或者 0个元音，状态才会**变回** `00010`。

所以，一旦发现 `map[status]` 里面有值（不是 -2），说明**“历史重现”**了！

那么：`当前位置 - 历史最早位置 = 满足条件的子字符串长度`。

##### 4.4 举个例子手动模拟

字符串：`"a a"` (长度2)

**初始化：**

`map` 全部填 -2 (表示还没见过)。

`map[0] = -1` (状态 `00000` 最早在开始前就存在了)。

**第一步：遇到第一个 'a' (下标 0)**

- 'a' 代表二进制 `00001`。
- 当前状态 `status` 从 `00000` 变成 `00001` (十进制 1)。
- **查表**：`map[1]` 是多少？是 -2 (没见过)。
- **记录**：`map[1] = 0`。
  - *翻译：状态“a奇其余偶”，最早出现在下标 0。*

**第二步：遇到第二个 'a' (下标 1)**

- 'a' 代表二进制 `00001`。
- 当前状态 `status` 从 `00001` 异或 `00001` -> 变成 `00000` (十进制 0)。
- **查表**：`map[0]` 是多少？
- **发现**：`map[0]` 是 -1 (早就见过了！)。
- **计算**：当前下标 1 - 历史下标 (-1) = **2**。
- **结论**：长度为 2 的子串 "aa"，包含偶数个 'a'。符合题意！

##### 总结 `map` 的作用

这个 `map` 就是一个**“奇偶状态历史记录本”**。

- **Key (下标)**：你是哪种奇偶组合？
- **Value (值)**：这种组合第一次是在哪出现的？

只要当前的组合在记录本里出现过，这中间剪下来的这一段，就是我们要的“完美偶数子串”。



### 5. 【图解原理】

假设字符串 `s = "leetcoded"` (只关注元音)。

元音映射：`a:0, e:1, i:2, o:3, u:4`。初始状态 `00000`。

**详细推演（二进制最低位代表 'a', 次低位代表 'e' ...）：**

1. **Init**: `map` 全填 -2 (表示没出现过)，`map[0] = -1` (空串状态)。
2. **i=0 ('l')**: 非元音。`status` 不变 (`00000`)。
   - 查 `map[0]` 是 -1。长度 `0 - (-1) = 1`。 `ans = 1`。
3. **i=1 ('e')**: 元音(bit 1)。
   - `status` 从 `00000` 异或 `00010` $\rightarrow$ **`00010`** (2)。
   - `map[2]` 是 -2 (没见过)。
   - 记录 `map[2] = 1`。
4. **i=2 ('e')**: 元音(bit 1)。
   - `status` 从 `00010` 异或 `00010` $\rightarrow$ **`00000`** (0)。
   - 查 `map[0]` 是 -1 (最早出现位置)。
   - 长度 `2 - (-1) = 3`。`ans = 3`。 (子串 "lee")。
5. **i=3 ('t')**: 非元音。`status` 不变 (`00000`)。
   - 查 `map[0]` 是 -1。长度 `3 - (-1) = 4`。 `ans = 4`。 (子串 "leet")。
   - *注意：此时 map[0] 不更新，保持 -1，因为我们要最长。*
6. **...跳过中间...**
7. **i=7 ('o')**: 元音(bit 3)。
   - 假设之前状态乱七八糟，变成 `01000`。
   - 如果之前在 index 5 也出现过 `01000`。
   - 那 `7 - 5 = 2` 就是候选答案。

### 6. 【代码逐行精读】

```java
public static int findTheLongestSubstring(String s) {
    // 【优化技巧】用数组代替 HashMap
    // 因为状态只有 5 位，最大 11111(二进制) = 31(十进制)
    // 开一个 32 大小的数组比 HashMap 快得多，且省空间。
    int[] map = new int[32];
    
    // 初始化为 -2，代表该状态从未出现过
    // (不用 -1 是因为 -1 有特殊含义：下标)
    Arrays.fill(map, -2);
    
    // 【Base Case】
    // 状态 0 (所有元音偶数次) 最早出现在下标 -1 (字符串开始前)
    map[0] = -1;
    
    int ans = 0;
    for (int i = 0, status = 0, m; i < s.length(); i++) {
        // 1. 计算当前字符对应的位移 (move)
        m = move(s.charAt(i));
        
        // 2. 如果是元音，更新状态 (翻转对应的位)
        // 1 << m 生成掩码，比如 'e' -> 1 << 1 -> 00010
        // 异或操作实现奇偶翻转
        if (m != -1) {
            status ^= 1 << m;
        }
        
        // 3. 核心查询
        // 以前见过这个 status 吗？
        if (map[status] != -2) {
            // 见过！说明中间这段经历了“偶数次变化”
            ans = Math.max(ans, i - map[status]);
        } else {
            // 没见过，记录下这个状态第一次出现的位置
            map[status] = i;
        }
    }
    return ans;
}

// 辅助函数：将元音映射为 0-4 的整数，辅音返回 -1
public static int move(char cha) {
    switch (cha) {
        case 'a': return 0;
        case 'e': return 1;
        case 'i': return 2;
        case 'o': return 3;
        case 'u': return 4;
        default: return -1;
    }
}
```

### 7. 【高分技巧 / 易错点】

1. **数组代替 Map**：
   - 这是本题的亮点。当 Key 的范围非常小且连续（0~31）时，**一定**要用数组 (`int[]`) 代替 `HashMap`。在笔试中，这种优化可以把运行时间从 100ms 降到 5ms。
2. **状态定义的每一位**：
   - 不需要关心哪一位对应哪个元音，只要一一对应即可（a对应0还是4都无所谓）。
3. **异或的物理意义**：
   - 遇到一个元音，就像按了一下开关。再遇到一次，又按了一下（还原）。我们找的就是**开关状态完全一样**的两个时间点，中间不管按了多少次，最终效果是抵消的。

### 8. 【复习闪卡】

1. **Q: 遇到“奇偶性”相关的子数组问题，应该想到什么算法？**
   - A: **前缀和 + 异或状态压缩**。
2. **Q: 为什么这里用 `status ^= 1 << m`？**
   - A: `1 << m` 制造了一个只在第 m 位是 1 的掩码。`XOR` 操作能让该位的 0 变 1，1 变 0，完美模拟奇偶切换。
3. **Q: 为什么 `map[status]` 存在时，不更新 map？**
   - A: 因为题目求**最长**子字符串。对于同一个状态，我们要保留它**最早**出现的位置，这样 `current_index - earliest_index` 才能最大。
