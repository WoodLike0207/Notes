# 1. 累加和大于等于target的最短子数组长度

测试链接 : https://leetcode.cn/problems/minimum-size-subarray-sum/



## 代码

```java
public class Code01_MinimumSizeSubarraySum {
    public int minSubArrayLen(int target, int[] nums) {
        int ans = Integer.MAX_VALUE;

        for (int l = 0, r = 0, sum = 0; r < nums.length; r++) {
            sum += nums[r];

            while (sum - nums[l] >= target) {
                sum -= nums[l++];
            }

            if (sum >= target) {
                ans = Math.min(ans, r - l + 1);
            }
        }

        return ans == Integer.MAX_VALUE ? 0 : ans;
    }
}
```



## 思路

### 1. 【核心策略】

**“进一退多”**：

- **进**：右指针 `r` 只要不越界，就一直往右加数字（累加和变大）。
- **退**：每当加入一个新数字后，检查左指针 `l` 指向的数字是不是“多余的”。如果去掉它，剩下的和依然达标，那就毫不犹豫地把它扔掉，让窗口变小（寻找更短的答案）。

### 2. 【数组图解演练】

假设目标 `target = 7`，数组 `nums = [2, 3, 1, 2, 4, 3]`。

我们用 `[ ]` 表示窗口范围，`L` 和 `R` 表示指针，`Sum` 表示当前和。

#### **阶段一：扩张期 (R 向右跑)**

窗口不断吃进数据，直到总和达标。

1. `[2], 3, 1...` -> Sum=2 (不够)
2. `[2, 3], 1...` -> Sum=5 (不够)
3. `[2, 3, 1], 2...` -> Sum=6 (不够)
4. `[2, 3, 1, 2], 4...` -> Sum=8 (**达标！**) $\ge 7$

此时触发 **“缩窗逻辑”** (`while` 循环)：

- **试探**：总和是 8，如果我扔掉左边的 `2` (L位置)，剩 6。
- **判断**：$6 < 7$ (不达标)。
- **结论**：这个 `2` 不能扔，扔了就不够了。
- **记录**：当前长度 **4**。

#### **阶段二：继续扩张与极致压缩**

R 继续向右移动，加入 `4`。

1. `2, [3, 1, 2, 4], 3` -> Sum = 8 + 4 = 12 (**严重超标**)

此时触发 **“缩窗逻辑”** (循环判断)：

- **第1次试探**：Sum=12。能扔掉左边的 `2` 吗？
  - 剩 10 $\ge$ 7。**可以扔！**
  - 动作：`L` 右移，Sum 变 10。
  - 窗口状态：`2, [3, 1, 2, 4], 3`
- **第2次试探**：Sum=10。能扔掉左边的 `3` 吗？
  - 剩 7 $\ge$ 7。**可以扔！**
  - 动作：`L` 右移，Sum 变 7。
  - 窗口状态：`2, 3, [1, 2, 4], 3`
- **第3次试探**：Sum=7。能扔掉左边的 `1` 吗？
  - 剩 6 < 7。**不能扔！** 再扔就不够了。
  - 动作：停止。
- **记录**：当前长度 **3** (比刚才的4更小，更新答案)。

#### **阶段三：最后的冲刺**

R 继续向右移动，加入 `3`。

1. `... 1, [2, 4, 3]` -> Sum = 7 + 3 = 10 (**超标**)

此时触发 **“缩窗逻辑”**：

- **第1次试探**：Sum=10。能扔掉左边的 `1` 吗？
  - 剩 9 $\ge$ 7。**可以扔！**
  - 动作：`L` 右移，Sum 变 9。
  - 窗口状态：`... 1, [2, 4, 3]`
- **第2次试探**：Sum=9。能扔掉左边的 `2` 吗？
  - 剩 7 $\ge$ 7。**可以扔！**
  - 动作：`L` 右移，Sum 变 7。
  - 窗口状态：`... 1, 2, [4, 3]`
- **第3次试探**：Sum=7。能扔掉左边的 `4` 吗？
  - 剩 3 < 7。**不能扔！**
- **记录**：当前长度 **2** (更新答案)。

最终结果：**2**。

------

### 3. 【代码逻辑精读】

```java
public int minSubArrayLen(int target, int[] nums) {
    int ans = Integer.MAX_VALUE;

    // l: 窗口左边界, r: 窗口右边界
    for (int l = 0, r = 0, sum = 0; r < nums.length; r++) {
        // 【第一步：进窗】
        // 无论如何，先把右边的数加进来
        sum += nums[r];

        // 【第二步：缩窗 (关键逻辑)】
        // 只要 sum - nums[l] >= target 成立，说明 nums[l] 是多余的“赘肉”。
        // 既然去掉它还能达标，为了求“最小长度”，我们当然要把它扔掉。
        while (sum - nums[l] >= target) {
            sum -= nums[l]; // 减去左边的值
            l++;            // 左边界右移
        }

        // 【第三步：结算】
        // 经过上面的 while 循环，现在的窗口是“极限卡在 target 边缘”的状态。
        // 如果它满足条件，就算一下长度。
        if (sum >= target) {
            ans = Math.min(ans, r - l + 1);
        }
    }

    return ans == Integer.MAX_VALUE ? 0 : ans;
}
```

### 4. 【复杂度分析】

- **时间复杂度**: $O(N)$。
  - 虽然代码里有一个 `while` 循环套在 `for` 循环里，看起来像 $O(N^2)$，但请注意观察：
  - 指针 `R` 从头走到尾，走了 N 步。
  - 指针 `L` 也只能从头走到尾，最多也走 N 步。
  - 两个指针都不回退，所以总操作次数是 $2N$，即线性复杂度。
- **空间复杂度**: $O(1)$。
  - 只使用了 `l`, `r`, `sum`, `ans` 这几个变量，没有开辟额外的数组。

### 5. 【总结】

这道题不需要想复杂的比喻，只需要记住**“双指针”**的配合：

1. **R 负责探路**：无脑往右扩，寻找可行解。
2. **L 负责优化**：一旦有可行解，就尝试往右缩，寻找**更优解**（更短的长度）。





# 2. 无重复字符的最长子串

测试链接 : https://leetcode.cn/problems/longest-substring-without-repeating-characters/



## 代码

```java
public int lengthOfLongestSubstring(String str) {
    char[] s = str.toCharArray();
    int[] last = new int[256];
    Arrays.fill(last, -1);

    int ans = 0;
    for (int l = 0, r = 0; r < s.length; r++) {
        if (last[s[r]] != -1) {
            l = Math.max(l, last[s[r]] + 1);
        }
        
        ans = Math.max(ans, r - l + 1);
        last[s[r]] = r;
    }
    
    return ans;
}
```



## 思路

这是为您整理的 **Code02_LongestSubstringWithoutRepeatingCharacters** (无重复字符的最长子串) 复习笔记。

这道题是 **滑动窗口 (Sliding Window)** 结合 **哈希表 (Hash Map)** 的经典入门题，对应 LeetCode 第 3 题。

------

### 📝 算法复习笔记：无重复字符的最长子串

### 1. 【一句话核心】

**“记录上次位置，左边界只进不退”**：

用一个数组（当作哈希表）记录每个字符**上一次出现的下标**。当 `R` 指针遇到重复字符时，`L` 指针直接跳到**该字符上次出现位置的下一位**，从而一步跨过重复区，保证窗口内永远没有重复字符。

### 2. 【核心逻辑解析】

这道题的高效解法不需要真正的“删除”窗口左边的元素，而是通过**跳跃**来移动左边界 `L`。

- **`last` 数组**：`last[char]` 存储字符 `char` 上一次出现的下标。初始化为 -1。
- **`R` 指针**：一直往右走，探索新字符。
- **`L` 指针 (关键)**：
  - 当我们遇到一个字符 `s[r]`，查表发现它之前出现过（假设位置是 `last_pos`）。
  - 如果 `last_pos` 在当前窗口内（`last_pos >= l`），说明重复了！
  - **动作**：`L` 直接跳到 `last_pos + 1`。
  - **注意**：`L` 只能向右移动，不能回头。所以公式是 `Math.max(l, last_pos + 1)`。

### 3. 【图解演示】

字符串：`"a b c a b c b b"`

目标：找不含重复字符的最长子串。

**详细推演：**

1. **R=0 ('a')**: `last['a']` 是 -1。`L` 不动 (0)。长度 1。记录 `last['a']=0`。

2. **R=1 ('b')**: `last['b']` 是 -1。`L` 不动 (0)。长度 2。记录 `last['b']=1`。

3. **R=2 ('c')**: `last['c']` 是 -1。`L` 不动 (0)。长度 3。记录 `last['c']=2`。

   - *此时窗口 `[a, b, c]`，长度 3。*

4. **R=3 ('a') —— 撞车了！**:

   - 查表：`last['a']` 是 **0**。
   - 决策：`L` 需要跳过旧的 'a'。`L = max(0, 0 + 1) = 1`。
   - 新窗口：`b, c, a` (下标 1~3)。长度 3。
   - 更新：`last['a']=3`。

5. **R=4 ('b') —— 又撞车！**:

   - 查表：`last['b']` 是 **1**。
   - 决策：`L` 跳过旧的 'b'。`L = max(1, 1 + 1) = 2`。
   - 新窗口：`c, a, b` (下标 2~4)。长度 3。
   - 更新：`last['b']=4`。

6. **特殊情况：防止 L 回退**

   假设字符串是 `"a b b a"`。

   - 走到第二个 'b' 时，`L` 跳到了 2 (第二个 'b' 的位置)。
   - 走到第二个 'a' 时，`last['a']` 是 0。
   - 此时 `last['a'] + 1 = 1`，但是 `L` 已经在 2 了。
   - **核心代码发挥作用**：`L = Math.max(2, 1) = 2`。**L 保持不动，不能退回到 1**。

### 4. 【代码逐行精读】

Java

```
public static int lengthOfLongestSubstring(String str) {
    char[] s = str.toCharArray();
    int n = s.length;
    
    // 【技巧 1】用数组代替 HashMap
    // ASCII 码范围 0-127，扩展 ASCII 到 255。
    // last[x] = y 表示：字符 x 上一次出现在下标 y
    int[] last = new int[256];
    
    // 初始化为 -1，表示所有字符都没出现过
    Arrays.fill(last, -1);
    
    int ans = 0;
    // l: 窗口左边界, r: 窗口右边界
    for (int l = 0, r = 0; r < n; r++) {
        // 【核心技巧 2】更新左边界 L
        // last[s[r]] 是当前字符上次出现的位置。
        // last[s[r]] + 1 就是去除重复后，L 应该跳到的新起点。
        // Math.max 保证 L 绝不回退。
        l = Math.max(l, last[s[r]] + 1);
        
        // 更新最大长度
        ans = Math.max(ans, r - l + 1);
        
        // 【核心技巧 3】更新记录表
        // 无论是否重复，当前位置 r 都是该字符"最新"出现的位置
        last[s[r]] = r;
    }
    return ans;
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(N)$。`R` 指针遍历一次字符串，`L` 指针也是单调递增，没有嵌套循环。
- **空间复杂度**: $O(1)$ (或 $O(\Sigma)$)。虽然申请了 `last` 数组，但大小固定为 256，不随字符串长度 $N$ 变化。

### 6. 【易错点 / 面试常问】

1. **为什么用 `int[256]` 而不是 `HashMap`？**
   - 字符也是整数。用数组访问下标比 HashMap 计算哈希值更快，且对于本题字符集（ASCII）来说，空间占用极小。
2. **`Math.max(l, ...)` 这一行能去掉 `Math.max` 吗？**
   - **绝对不能**。如果当前字符上次出现的位置在 `L` 的左边（也就是在当前窗口之外），如果不取 Max，`L` 会退回去，导致把窗口外的重复字符又算进来，甚至逻辑错误。
3. **`last` 数组为什么要填充 -1？**
   - 因为数组默认是 0，而下标 0 是有意义的。如果不填 -1，遇到第一个字符时逻辑会变复杂。



# 3. 最小覆盖子串

测试链接 : https://leetcode.cn/problems/minimum-window-substring/



## 代码

```java
public class Code03_MinimumWindowSubstring {
    public String minWindow(String str, String tar) {
        char[] s = str.toCharArray();
        char[] t = tar.toCharArray();

        int[] cnts = new int[256];
        int debt = t.length;

        for (char cha : t) {
            cnts[cha]--;
        }

        int start = 0;
        int len = Integer.MAX_VALUE;

        for (int l = 0, r = 0; r < s.length; r++) {
            if (cnts[s[r]]++  < 0) {
                debt--;
            }

            if (debt == 0) {
                while (cnts[s[l]] > 0) {
                    cnts[s[l]]--;
                    l++;
                }

                if (r - l + 1 < len) {
                    len = r - l + 1;
                    start = l;
                }
            }
        }

        return len == Integer.MAX_VALUE ? "" : str.substring(start, start + len);
    }
}
```



## 思路

这道题是 **滑动窗口 (Sliding Window)** 中难度较高、也是面试频率极高的 **Hard** 级别题目（LeetCode 76）。



### 1. 【一句话核心】

**“欠债模型”**：先把 `t` 中的字符看作“负债”（负数）。窗口右扩时“还钱”（++），当所有债务还得干干净净（`debt == 0`）时，窗口左侧就开始“挥霍盈余”，把多余的钱（正数）扔掉，直到遇到第一笔必须保留的“烂账”（0），此时窗口长度就是当前的最小覆盖长度。

### 2. 【核心变量含义】

- **`cnts[256]` (账本)**：
  - **负数 (< 0)**：说明这个字符是我们在 `t` 中需要的，还**欠**着没还完。
  - **零 (== 0)**：说明这个字符刚好够用了，**不欠不余**。
  - **正数 (> 0)**：说明这个字符是**多余**的（盈余），或者是 `t` 里根本不需要的废字符。
- **`debt` (总债务)**：
  - 代表我们要凑齐 `t` 还差多少个**有效**字符。
  - 当 `debt == 0` 时，说明当前窗口已经包含了 `t` 的所有字符。

### 3. 【图解流程】

假设 `s = "ADOBECODEBANC"`, `t = "ABC"`。

**Step 1: 建立债务 (初始化)**

- 遍历 `t` ("ABC")，在 `cnts` 里记账。
- `cnts['A'] = -1`, `cnts['B'] = -1`, `cnts['C'] = -1`。其他都是 0。
- `debt = 3`。

**Step 2: 窗口右扩 (还钱阶段)**

`r` 指针向右走，把遇到的字符加入窗口 (`cnts[s[r]]++`)。

- 遇到 'A': `cnts['A']` 从 -1 变 0。**是有效还款** (原值 < 0)，`debt` 减 1 (剩2)。
- 遇到 'D': `cnts['D']` 从 0 变 1。**是多余款** (原值 >= 0)，`debt` 不变。
- ... (继续走) ...
- 直到 `r` 走到某个位置，包含了 A, B, C。此时 `cnts` 里 A,B,C 都 >= 0，`debt` 变成了 0。

**Step 3: 窗口左缩 (挥霍盈余阶段)**

当 `debt == 0` 时，说明现在的窗口 `[l...r]` 已经达标了（覆盖了ABC）。

我们要尝试缩小 `l`，让窗口变小。

- **核心逻辑**：`while (cnts[s[l]] > 0)`
- 看 `l` 位置的字符：
  - 如果它的账面上是 **正数 (> 0)**：说明它是多余的（要么是废字符，要么是重复的有效字符）。**扔掉！** (`l++`, `cnts--`)。
  - 如果它的账面上是 **零 (== 0)**：说明它是**关键资产**，扔了就破产了（不能覆盖 `t` 了）。**停！**
- 此时记录长度 `len`。

**Step 4: 继续右扩**

记录完答案后，`r` 继续往右走，寻找下一个可能更短的组合。

------

### 4. 【代码逐行精读】

```java
public static String minWindow(String str, String tar) {
    char[] s = str.toCharArray();
    char[] t = tar.toCharArray();
    int[] cnts = new int[256];
    
    // 【技巧 1】初始化负债
    // 把 t 里的字符记为负数，表示"欠这么多"
    for (char cha : t) {
        cnts[cha]--;
    }
    
    int len = Integer.MAX_VALUE;
    int start = 0;
    // 总债务数量
    int debt = t.length;
    
    for (int l = 0, r = 0; r < s.length; r++) {
        // 【核心逻辑 2】进窗 + 有效还款判断
        // s[r] 是当前进来的字符。
        // cnts[s[r]]++ : 不管是不是 target 里的，先入账。
        // check < 0 : 如果入账之前是负数，说明这笔钱是用来"还债"的，debt 减少。
        // 如果入账之前是 >= 0，说明是"存款"或"废纸"，debt 不减。
        if (cnts[s[r]]++ < 0) {
            debt--;
        }
        
        // 【核心逻辑 3】达标后的极致压缩
        if (debt == 0) {
            // 只要 l 位置的字符是"富余"的(>0)，就尽管扔！
            // 扔到什么程度？扔到 l 位置的字符刚好是 0 (必须保留) 为止。
            while (cnts[s[l]] > 0) {
                cnts[s[l++]]--;
            }
            
            // 此时 l 位置一定是一个"关键字符" (cnts == 0)
            // [l...r] 就是当前以 r 结尾的最短覆盖子串
            if (r - l + 1 < len) {
                len = r - l + 1;
                start = l;
            }
            
            // 注意：这里没有显式地让 l++ 来破坏平衡。
            // 而是让 r 继续往右走。
            // 只有当 r 遇到了第二个 'A'，让 cnts['A'] 变成正数(盈余)后，
            // 上面的 while 循环才会把左边那个旧的 'A' 扔掉。
        }
    }
    
    return len == Integer.MAX_VALUE ? "" : str.substring(start, start + len);
}
```

### 5. 【难点解析：为什么不用 `l++` 破坏平衡？】

很多标准写法是：当 `debt == 0`，记录答案，然后强制 `l++` 造成 `debt > 0`，强迫 `r` 继续找。

但这份代码的逻辑更精妙（也更隐晦）：

- 它利用 **“盈余挤出机制”**。
- 假设当前窗口 `A...B...C` 达标。`l` 指向 `A`。此时 `cnts['A'] == 0`。
- 代码不动 `l`，让 `r` 继续跑。
- 直到 `r` 遇到了**下一个** `A`。此时 `cnts['A']` 变成了 1 (盈余)。
- 下一次循环的 `while (cnts[s[l]] > 0)` 就会发现左边的 `A` 已经是多余的了，于是 `l` 才会向右移，去寻找下一个边界。

### 6. 【复杂度分析】

- **时间复杂度**: $O(N)$。虽然有嵌套循环，但 `l` 和 `r` 都是单调递增，最多各走一次全长。
- **空间复杂度**: $O(1)$ (常数级 256 数组)。

### 7. 【复习闪卡】

1. **Q: 为什么 `cnts` 数组初始化要用减法？**
   - A: 为了区分“欠债”和“盈余”。负数表示还需要几个，正数表示多余几个。这样判断 `debt` 是否减少非常方便（只看 `< 0`）。
2. **Q: `debt` 什么时候减少？**
   - A: 只有当进入窗口的字符是 `t` 中必须的，且当前还未凑齐该字符（即 `cnts` 值为负）时，`debt` 才会减少。
3. **Q: 窗口左边界 `l` 什么时候收缩？**
   - A: 当 `debt == 0` 时，只要 `l` 指向的字符是多余的（`cnts > 0`），就一直收缩，直到遇到第一个关键字符（`cnts == 0`）。



# 4. 加油站

测试链接 : https://leetcode.cn/problems/gas-station/



## 代码

```java
public class Code04_GasStation {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int n = gas.length;

        for (int l = 0, r = 0, sum; r < n; l = r + 1, r = l) {
            sum = 0;

            while (sum + gas[r % n] - cost[r % n] >= 0) {
                if (r - l + 1 == n) {
                    return l;
                }

                sum += gas[r % n] - cost[r % n];
                r++;
            }
        }

        return -1;
    }
}

```



## 思路

这道题是 **贪心算法 (Greedy)** 的经典题目。它利用了一个非常关键的数学推论，将复杂度从 $O(N^2)$ 降低到了 $O(N)$。



### 1. 【一句话核心】

**“哪里跌倒，就从哪里爬起来的下一站重新开始”**：

如果在从 A 出发试图走到 B 的途中，油箱在 C 处空了（无法到达 D），那么 **A 到 C 之间的任何一个站点都不可能作为起点**。直接跳到 D (C+1) 重新尝试。

### 2. 【核心变量与逻辑】

- **`gas[i] - cost[i]` (净余量)**：
  - 我们不关心具体的 `gas` 和 `cost`，只关心在这个站是“存油”还是“耗油”。
  - 记 `diff[i] = gas[i] - cost[i]`。
- **`l` (尝试的起点)**：当前假设的出发站。
- **`r` (能到达的最远位置)**：从 `l` 出发，当前已经探索到的位置。
- **`sum` (油箱余量)**：从 `l` 走到 `r` 的过程中，油箱里累积剩下的油。

### 3. 【核心推导：为什么可以跳过？】

这是本题能在 $O(N)$ 解决的根本原因。

**推导过程：**

1. 假设从 `l` 出发，途经 `k`，最后在 `r` 位置挂了（`sum < 0`，去不了 `r+1`）。
2. 这说明：`sum(l...r) < 0`。
3. 但是，既然能从 `l` 走到 `k` (k 在 l 和 r 之间)，说明 `sum(l...k) >= 0`。
4. **如果把起点换成 k 呢？**
   - 从 `l` 出发时，到达 `k` 点可能还带着一点“老本”（之前的余油）。
   - 如果直接从 `k` 出发，是“净身出户”（初始为 0）。
   - 带着老本都走不到 `r+1`，净身出户肯定更走不到！
5. **结论**：`l` 到 `r` 之间的所有点都不可能是起点。直接把起点设为 `r + 1`。

### 4. 【图解流程】

假设 `gas = [1, 2, 3, 4, 5]`, `cost = [3, 4, 5, 1, 2]`

净余量 `diff = [-2, -2, -2, 3, 3]`

**详细推演：**

1. **尝试 l = 0**:
   - `r = 0`: 净余量 -2。`0 + (-2) < 0`。**失败！**
   - 跳过 0。下一次 `l` 设为 `0 + 1 = 1`。
2. **尝试 l = 1**:
   - `r = 1`: 净余量 -2。`0 + (-2) < 0`。**失败！**
   - 跳过 1。下一次 `l` 设为 `1 + 1 = 2`。
3. **尝试 l = 2**:
   - `r = 2`: 净余量 -2。**失败！**
   - 跳过 2。下一次 `l` 设为 `2 + 1 = 3`。
4. **尝试 l = 3 (关键)**:
   - `r = 3`: 净余量 3。`sum = 3` (>=0)。**成功，继续！**
   - `r = 4`: 净余量 3。`sum = 3 + 3 = 6`。**成功！**
   - `r = 5 (即下标0)`: 净余量 -2。`sum = 6 - 2 = 4`。**成功！**
   - `r = 6 (即下标1)`: 净余量 -2。`sum = 4 - 2 = 2`。**成功！**
   - `r = 7 (即下标2)`: 净余量 -2。`sum = 2 - 2 = 0`。**成功！**
   - 此时 `r - l + 1 = 7 - 3 + 1 = 5` (等于数组长度)。
   - **返回 l = 3**。

### 5. 【代码逐行精读】

```java
public static int canCompleteCircuit(int[] gas, int[] cost) {
    int n = gas.length;
    // l: 当前尝试的起点
    // r: 当前到达的位置
    // sum: 油箱里的油
    // l < n: 如果起点尝试超过了 n，说明没有解
    // l = r + 1: 【核心优化】如果 l 在 r 处失败，直接跳到 r + 1 开始尝试
    // r = l: 每次换新起点，r 重置为 l
    for (int l = 0, r = 0, sum; l < n; l = r + 1, r = l) {
        sum = 0;
        
        // 模拟环形路：下标使用 % n
        // 判断条件：当前油量 + 本站补给 - 去下一站消耗 >= 0
        while (sum + gas[r % n] - cost[r % n] >= 0) {
            
            // 如果走过的站点数等于 n，说明转了一圈回来了
            if (r - l + 1 == n) {
                return l;
            }
            
            // 累加净余量
            sum += gas[r % n] - cost[r % n];
            // 继续去下一站
            r++;
        }
        // 如果 while 中断，说明从 l 出发，在 r 这个位置断油了。
        // for 循环的步进表达式会执行 l = r + 1，跳过中间所有点。
    }
    return -1;
}
```

### 6. 【复杂度分析】

- **时间复杂度**: $O(N)$。
  - 看起来是两层循环，但实际上 `l` 和 `r` 都是单调递增的。
  - `l` 最多增加 $N$ 次，`r` 最多增加 $2N$ 次（因为可能跨越边界转一圈）。
  - 每个加油站最多被访问两次。
- **空间复杂度**: $O(1)$。只用了几个变量。

### 7. 【复习闪卡】

1. **Q: 为什么这道题可以用 $O(N)$ 解决？**
   - A: 因为如果从 A 出发无法到达 B，那么 A 和 B 之间的任何站点也不可能到达 B。利用这个性质可以跳过大量无效的起点。
2. **Q: 代码中 `r % n` 的作用是什么？**
   - A: 处理**环形数组**。当 `r` 超过 `n-1` 时，取模让它回到数组开头，模拟绕圈的过程。
3. **Q: 什么时候返回 `-1`？**
   - A: 当 `l` 尝试了所有可能的起点（`l` 增加到了 `n`），依然没有找到能走完一圈的路径。或者更简单的判断依据：如果总油量 < 总消耗，一定无解（虽然本代码是直接模拟寻找起点）。



# 5. 替换子串得到平衡字符串

测试链接 : https://leetcode.cn/problems/replace-the-substring-for-balanced-string/



## 代码

```java
/**
 * @Title: Code05_ReplaceTheSubstringForBalancedString
 * @Author Wood
 * @Package PACKAGE_NAME
 * @Date 2026/2/8 16:15
 * @description:
 */
public class Code05_ReplaceTheSubstringForBalancedString {
    public int balancedString(String str) {
        int n = str.length();

        int[] s = new int[n];
        int[] cnts = new int[4];

        for (int i = 0; i < n; i++) {
            char c = str.charAt(i);
            s[i] = c == 'W' ? 1 : (c == 'E' ? 2 : (c == 'R' ? 3 : 0));
            cnts[s[i]]++;
        }

        int debt = 0;
        for (int i = 0; i < 4; i++) {
            if (cnts[i] < n / 4) {
                cnts[i] = 0;
            }else {
                cnts[i] = n/4 - cnts[i];
                debt -= cnts[i];
            }
        }

        if (debt == 0) {
            return 0;
        }

        int ans = Integer.MAX_VALUE;
        for (int l = 0, r = 0; r < n; r++) {
            if (cnts[s[r]]++ < 0) {
                debt--;
            }

            if (debt == 0) {
                while (cnts[s[l]] > 0) {
                    cnts[s[l]]--;
                    l++;
                }

                ans = Math.min(ans, r - l + 1);
            }
        }

        return ans;
    }
}
```





## 思路

这道题是 **滑动窗口** 的变型题（LeetCode 1234），它的核心难点在于 **“逆向思维”** 的转化。



### 1. 【一句话核心】

**“捉拿捣乱分子”**：

与其去想“怎么补齐不够的字符”，不如去想**“哪些字符多了（捣乱分子）”**。我们需要找到一个最小的窗口，把所有**超出配额 ($N/4$)** 的字符都框进去。只要把这些多余的字符“扣”在窗口里，我们就可以把它们任意替换成其他缺少的字符，从而实现平衡。

### 2. 【核心转化逻辑】

1. **目标**：每个字符出现次数 = $N / 4$。
2. **现状**：有些字符多了，有些少了。
3. **策略**：
   - 如果一个字符出现次数 $> N/4$，它就是“多余”的。
   - 比如 $N=8$，目标是每个 2 次。如果 'Q' 出现了 5 次，那它就多了 3 个。
   - **我们的任务**：必须找一个子串，这个子串里**至少**包含 3 个 'Q'。
   - 只要把这 3 个 'Q' 包含在待替换区域（窗口）里，我们就能把它们删掉（替换掉），整个字符串的 'Q' 就平衡了。

**结论**：这道题等价于 **“求包含所有多余字符的最小覆盖子串”**。

这就完全变成了上一题（Code03 最小覆盖子串）的模型！

### 3. 【图解原理】

假设 $s = \text{"Q Q Q W"}$, $n = 4$, 目标每种 1 个。

- **统计现状**：
  - Q: 3个 (目标1，**多了2个**) $\rightarrow$ 记账 `cnts['Q'] = -2` (负数表示欠债/必须在窗口里消除)
  - W: 1个 (目标1，正好) $\rightarrow$ 记账 `cnts['W'] = 0`
  - E: 0个 (目标1，少了) $\rightarrow$ 记账 `cnts['E'] = 0` (我们不关心少的，窗口里随便换)
  - R: 0个 (目标1，少了) $\rightarrow$ 记账 `cnts['R'] = 0`
- **总债务 (debt)**：2 (需要框住 2 个 Q)。

**滑动过程：**

我们要找一个包含 2 个 'Q' 的最短子串。

1. **R=0 ('Q')**: `cnts['Q']` 从 -2 变 -1。有效还债。`debt` 剩 1。
2. **R=1 ('Q')**: `cnts['Q']` 从 -1 变 0。有效还债。`debt` 剩 0。
   - **达标！** 窗口 `[0, 1]` ("QQ") 包含了所有多余的 Q。
   - **缩窗**：尝试 L 右移。
   - `L=0 ('Q')`: `cnts['Q']` 目前是 0，不是 >0 (盈余)。不能扔。
   - 当前长度 2。
3. **R=2 ('Q')**: `cnts['Q']` 变 1 (盈余)。
   - **缩窗**：`L=0` 的 Q 现在是多余的了，扔掉！L 变 1。
   - **缩窗**：`L=1` 的 Q 目前是 0，不能扔。
   - 当前长度 2。

### 4. 【代码逐行精读】

```java
public static int balancedString(String str) {
    int n = str.length();
    // 简单的字符映射：Q->0, W->1, E->2, R->3
    // 省去 HashMap 开销
    int[] s = new int[n];
    int[] cnts = new int[4];
    for (int i = 0; i < n; i++) {
        char c = str.charAt(i);
        s[i] = c == 'W' ? 1 : (c == 'E' ? 2 : (c == 'R' ? 3 : 0));
        cnts[s[i]]++;
    }
    
    int debt = 0; // 总共需要框住多少个"多余"字符
    // 【核心预处理】
    for (int i = 0; i < 4; i++) {
        // 如果出现次数 < N/4，说明它不需要被框住，cnts 设为 0
        if (cnts[i] < n / 4) {
            cnts[i] = 0;
        } else {
            // 如果出现次数 > N/4，比如多了 k 个
            // 记为 -k，表示我们在窗口里"欠"了 k 个这样的字符
            cnts[i] = n / 4 - cnts[i];
            debt -= cnts[i]; // debt 累加 k
        }
    }
    
    // 如果没有债务，说明原串本身就是平衡的
    if (debt == 0) {
        return 0;
    }
    
    int ans = Integer.MAX_VALUE;
    // 【标准滑动窗口 - 欠债还钱模型】
    // 代码逻辑与 Code03_MinimumWindowSubstring 完全一致
    for (int l = 0, r = 0; r < n; r++) {
        // r 进窗，如果是我们需要的"多余字符" (cnts < 0)，debt 减少
        if (cnts[s[r]]++ < 0) {
            debt--;
        }
        
        // 当所有多余字符都被框住后
        if (debt == 0) {
            // l 缩窗，扔掉窗口左边多余的部分
            while (cnts[s[l]] > 0) {
                cnts[s[l++]]--;
            }
            // 更新最小长度
            ans = Math.min(ans, r - l + 1);
        }
    }
    return ans;
}
```

### 5. 【对比 Code03 与 Code05】

这两道题的代码结构惊人地相似，唯一的区别在于 **“账本(`cnts`)的初始化”**：

| **特性**          | **Code03 (最小覆盖子串)** | **Code05 (平衡字符串)**         |
| ----------------- | ------------------------- | ------------------------------- |
| **题目目标**      | 包含目标串 T 的所有字符   | 包含原串 S 中所有**多余**的字符 |
| **初始化来源**    | 来源于字符串 T            | 来源于 `TotalCount - N/4`       |
| **cnts 负数含义** | 窗口里还缺 T 中的字符     | 窗口里还缺 S 中的**多余**字符   |
| **cnts 正数含义** | 窗口里多余的/无关的字符   | 窗口里多余的/原本就少的字符     |
| **滑动逻辑**      | **完全一样**              | **完全一样**                    |

### 6. 【复习闪卡】

1. **Q: 为什么这道题是“最小覆盖子串”问题？**
   - A: 因为只要把超出 `N/4` 的那些字符都圈在窗口里，剩下的字符数量都 $\le N/4$。无论窗口里是什么，我们都可以把它们变成缺少的字符，从而配平。
2. **Q: 为什么 `cnts` 数组里，原本数量少的字符要设为 0？**
   - A: 因为数量少的字符不是“问题”，我们不需要刻意把它们框进窗口里去替换。它们不是“债务”。
3. **Q: 能够只替换窗口里的一部分字符吗？**
   - A: 题目说“替换一个子串”，意味着窗口里的所有字符都会被重写。所以只要窗口覆盖了所有的“捣乱分子”，我们一定能构造出平衡串。



# 6. K个不同整数的子数组

测试链接 : https://leetcode.cn/problems/subarrays-with-k-different-integers/



## 代码

```java
public class Code06_SubarraysWithKDifferentIntegers {
    public static int subarraysWithKDistinct(int[] nums, int k) {
        return numsOfMostKinds(nums,k) - numsOfMostKinds(nums, k - 1);
    }

    public static int MAXN = 20001;

    public static int[] cnts = new int[MAXN];

    public static int numsOfMostKinds(int[] arr, int k) {
        Arrays.fill(cnts, 1, arr.length + 1, 0);
        int ans = 0;
        for (int l = 0, r = 0, collect = 0; r < arr.length; r++) {
            if (++cnts[arr[r]] == 1) {
                collect++;
            }

            while (collect > k) {
                if (--cnts[arr[l++]] == 0) {
                    collect--;
                }
            }

            ans += r - l + 1;
        }
        return ans;
    }
}
```





## 思路

这道题是 **滑动窗口** 技巧的高级应用，对应 LeetCode 992 题。它用到了一个非常经典的**“恰好转最多”**的数学转化思想。

### 1. 【一句话核心】

**“恰好 K 个 = 最多 K 个 - 最多 (K-1) 个”**。

因为直接求“恰好 K 个”的滑动窗口很难控制边界（窗口伸缩条件不明确），而求“最多 K 个”的滑动窗口非常标准且简单（单调性明显）。

### 2. 【核心转化逻辑】

- **定义函数** `atMost(k)`：计算数组中有多少个子数组，其中不同整数的个数 **小于等于** `k`。

- **推导**：

  - `atMost(K)` 包含：恰好1种 + 恰好2种 + ... + 恰好K种。
  - `atMost(K-1)` 包含：恰好1种 + 恰好2种 + ... + 恰好(K-1)种。

- **结论**：

  $$Answer = atMost(K) - atMost(K-1)$$

### 3. 【子函数逻辑：求“最多 K 种”】

这是一个标准的滑动窗口模型。

- **R 向右扩**：进数，更新词频。如果该数是第一次出现，`collect`（种类数）加 1。
- **L 向右缩**：当 `collect > k` 时，窗口不达标了。L 必须向右缩，扔掉左边的数，直到 `collect <= k`。
- **累加答案**：**关键点！**
  - 当窗口 `[l, r]` 满足条件（种类 $\le k$）时，**以 `r` 结尾** 的所有子数组都满足条件。
  - 这些子数组是：`[l...r], [l+1...r], ..., [r...r]`。
  - 数量正好是：**`r - l + 1`**。

### 4. 【图解原理】

假设 `arr = [1, 2, 1, 3]`, 求 **最多 2 种** (`k=2`)。

**详细推演 `numsOfMostKinds(arr, 2)`：**

1. **R=0 (Val=1)**:
   - `cnts`={1:1}, `collect`=1 ($\le 2$)。
   - 有效窗口 `[1]`。
   - 以 R 结尾的有效子数组：`[1]`。
   - `ans += 1`。
2. **R=1 (Val=2)**:
   - `cnts`={1:1, 2:1}, `collect`=2 ($\le 2$)。
   - 有效窗口 `[1, 2]`。
   - 以 R 结尾的有效子数组：`[2]`, `[1, 2]`。
   - `ans += 2`。
3. **R=2 (Val=1)**:
   - `cnts`={1:2, 2:1}, `collect`=2 ($\le 2$)。
   - 有效窗口 `[1, 2, 1]`。
   - 以 R 结尾的有效子数组：`[1]`, `[2, 1]`, `[1, 2, 1]`。
   - `ans += 3`。
4. **R=3 (Val=3)**:
   - `cnts`={1:2, 2:1, 3:1}, `collect`=3 (**> 2, 超标！**)。
   - **缩窗 (L右移)**：
     - 扔掉 `arr[0]=1` -> `cnts`={1:1, 2:1, 3:1}, `collect`=3 (还是超标)。L变成1。
     - 扔掉 `arr[1]=2` -> `cnts`={1:1, 2:0, 3:1}, `collect`=2 (达标！)。L变成2。
   - 当前窗口 `[1, 3]` (下标 2~3)。
   - 以 R 结尾的有效子数组：`[3]`, `[1, 3]`。
   - `ans += 2`。

**总数**：$1 + 2 + 3 + 2 = 8$。

### 5. 【代码逐行精读】

```java
public static int numsOfMostKinds(int[] arr, int k) {
    // 这是一个优化：每次复用 cnts 数组，不用 new 新的
    // 只清空我们需要用到的部分 (1 ~ arr.length)
    Arrays.fill(cnts, 1, arr.length + 1, 0);
    
    int ans = 0;
    // collect: 当前窗口内有多少种不同的数字
    for (int l = 0, r = 0, collect = 0; r < arr.length; r++) {
        // 【进窗逻辑】
        // ++cnts[...] == 1 说明这个数字之前的频次是 0，现在是第一次出现
        if (++cnts[arr[r]] == 1) {
            collect++;
        }
        
        // 【缩窗逻辑】
        // 只要种类数超过了 k，L 就一直往右缩
        while (collect > k) {
            // --cnts[...] == 0 说明扔掉这个数字后，它的频次变成了 0
            // 意味着窗口里彻底没有这个数字了，种类数 -1
            if (--cnts[arr[l++]] == 0) {
                collect--;
            }
        }
        
        // 【核心结算】
        // 以 r 结尾的、满足条件的子数组个数 = 窗口长度
        ans += r - l + 1;
    }
    return ans;
}
```

### 6. 【复杂度分析】

- **时间复杂度**: $O(N)$。
  - 虽然有两层循环，但 `numsOfMostKinds` 中 `L` 和 `R` 指针都单调不退。
  - 总共调用了两次该函数，所以是 $2N$。
- **空间复杂度**: $O(N)$。
  - 取决于 `MAXN` 或输入数据的最大值，用于开辟 `cnts` 数组。如果数值很大需要用 HashMap，那就是 $O(N)$。

### 7. 【复习闪卡】

1. **Q: 为什么不能直接用滑动窗口求“恰好 K 个”？**
   - A: 因为当 `collect == k` 时，R 继续向右扩可能还是 `k`（增加了重复数字），L 向右缩也可能还是 `k`（删除了重复数字）。窗口无法确定是该“扩”还是该“缩”，失去了单调性。
2. **Q: `ans += r - l + 1` 的物理含义是什么？**
   - A: 它代表 **以当前 `r` 为右端点**，且左端点在 `[l, r]` 范围内的所有子数组。因为 `[l, r]` 是满足“最多 K 种”的最长区间，所以它的所有子区间（只要以 `r` 结尾）也都满足条件。
3. **Q: 这道题的公式是什么？**
   - A: `Result = f(K) - f(K-1)`，其中 `f(x)` 是求“最多 x 种不同整数的子数组个数”。



# 7. 至少有K个重复字符的最长子串

测试链接 : https://leetcode.cn/problems/longest-substring-with-at-least-k-repeating-characters/



## 代码

```java
public class Code07_LongestSubstringWithAtLeastKRepeating {
    public int longestSubstring(String str, int k) {
        char[] s = str.toCharArray();
        int n = s.length;
        int[] cnts = new int[256];
        int ans = 0;

        for (int require = 1; require <= 26; require++) {
            Arrays.fill(cnts,0);

            for (int l =0, r = 0, collect = 0, satisfy = 0; r < n; r++) {
                cnts[s[r]]++;
                if (cnts[s[r]] == 1) {
                    collect++;
                }

                if (cnts[s[r]] == k) {
                    satisfy++;
                }

                while (collect > require) {
                    if (cnts[s[l]] == 1) {
                        collect--;
                    }

                    if (cnts[s[l]] == k) {
                        satisfy--;
                    }

                    cnts[s[l++]]--;
                }

                if (satisfy == require) {
                    ans = Math.max(ans, r - l + 1);
                }
            }
        }

        return ans;
    }
}
```





## 思路

这道题是 **滑动窗口** 的一个特殊变种。直接使用标准滑动窗口很难解决，因为我们不知道“多长才算长”以及“什么时候该缩窗口”。

解题的关键在于**“枚举字符种类数”**。

### 1. 【核心痛点与突破口】

- **痛点**：通常的滑动窗口都有明确的“爆窗条件”（比如和大于 target、重复字符出现等）。但这道题要求“每个字符都 $\ge k$”，这个条件不具备单调性——窗口变大可能达标，也可能因为引入新字符而不达标。
- **突破口**：虽然字符串很长，但**字符的种类（小写字母）只有 26 种**。
- **策略**：我们可以把问题拆分成 26 个子问题：
  - 子问题 1：只有 **1种** 字符，且该字符出现次数 $\ge k$ 的最长子串。
  - 子问题 2：恰好有 **2种** 字符，且这 2 种字符出现次数都 $\ge k$ 的最长子串。
  - ...
  - 子问题 26：恰好有 **26种** 字符，且这 26 种字符出现次数都 $\ge k$ 的最长子串。

一旦限制了“窗口内只能有 `require` 种字符”，**单调性**就回来了：如果窗口内种类超过了 `require`，左边界 `L` 必须收缩！

### 2. 【核心变量含义】

- **`require` (外层循环)**：我们当前假设子串里**必须且只能**包含多少种不同的字符（1~26）。
- **`collect` (收集到的种类)**：当前窗口 `[l, r]` 里实际上有几种字符。
  - 目标是控制 `collect <= require`。
- **`satisfy` (达标的种类)**：当前窗口里，有多少种字符的出现次数已经 $\ge k$ 了。
  - **最终目标**：当 `satisfy == require` (且 `collect == require`) 时，说明窗口里所有种类的字符都达标了，此时更新最大长度。

### 3. 【图解原理】

假设 `s = "aabcb"`, `k = 2`。

我们要找：包含 **2种** 字符 (`require = 2`)，且每种都 $\ge 2$ 的子串。

**详细推演 (`require = 2`)：**

1. **R=0 ('a')**: `cnts`={a:1}. `collect`=1. `satisfy`=0. (a不够k)
2. **R=1 ('a')**: `cnts`={a:2}. `collect`=1. `satisfy`=1 (a达标).
3. **R=2 ('b')**: `cnts`={a:2, b:1}. `collect`=2. `satisfy`=1.
4. **R=3 ('c')**: `cnts`={a:2, b:1, c:1}. `collect`=3.
   - **爆了！** (`collect > require`).
   - **缩窗 (L右移)**：
     - 扔掉 `s[0]('a')`. `cnts`={a:1...}. `satisfy` 变 0 (a不达标了).
     - 扔掉 `s[1]('a')`. `cnts`={a:0...}. `collect` 变 2. (a没了).
     - 停！`collect` 恢复为 2。
   - 当前窗口 `[b, c]`.
5. **R=4 ('b')**: `cnts`={b:2, c:1}. `collect`=2. `satisfy`=1 (b达标, c不达标).
   - `satisfy != require` (1 != 2)，不更新答案。

*(注：这个例子为了演示缩窗逻辑，实际上最优解可能是其他情况)*

### 4. 【代码逐行精读】

```java
public static int longestSubstring(String str, int k) {
    char[] s = str.toCharArray();
    int n = s.length;
    int[] cnts = new int[256];
    int ans = 0;
    
    // 【核心循环】枚举子串中包含的字符种类数量 (1~26)
    // 只有固定了种类数量，滑动窗口才有明确的收缩条件
    for (int require = 1; require <= 26; require++) {
        Arrays.fill(cnts, 0);
        
        // collect: 当前窗口有多少种字符
        // satisfy: 当前窗口有多少种字符达标了 (count >= k)
        for (int l = 0, r = 0, collect = 0, satisfy = 0; r < n; r++) {
            
            // --- 进窗逻辑 ---
            cnts[s[r]]++;
            if (cnts[s[r]] == 1) {
                collect++; // 新来了一种字符
            }
            if (cnts[s[r]] == k) {
                satisfy++; // 这种字符达标了
            }
            
            // --- 缩窗逻辑 ---
            // 只要窗口里的种类数 > 要求的种类数，必须缩！
            while (collect > require) {
                // 此时要从 l 位置吐出字符 s[l]
                
                // 1. 如果这个字符原本只有1个，吐完就没了，种类-1
                if (cnts[s[l]] == 1) {
                    collect--;
                }
                // 2. 如果这个字符原本刚好 k 个，吐完变成 k-1，达标数-1
                if (cnts[s[l]] == k) {
                    satisfy--;
                }
                // 3. 真正的扣减操作
                cnts[s[l++]]--;
            }
            
            // --- 结算逻辑 ---
            // 只有当"达标种类数" == "要求种类数"时，才是一个有效解。
            // 隐含条件：collect 此时一定等于 require (因为 while 保证了 <=，而 satisfy==require 意味着 collect 至少是 require)
            if (satisfy == require) {
                ans = Math.max(ans, r - l + 1);
            }
        }
    }
    return ans;
}
```

### 5. 【复杂度分析】

- **时间复杂度**: $O(26 \times N) \approx O(N)$。
  - 外层循环固定跑 26 次。
  - 内层滑动窗口 `l` 和 `r` 各跑一次数组。
  - 所以整体是线性的。
- **空间复杂度**: $O(1)$。
  - 只用到一个 `cnts` 数组（常数大小 256）。

### 6. 【易错点 / 思考】

1. **为什么 `cnts[s[l]] == 1` 时 `collect--` 要放在 `cnts[s[l++]]--` 之前？**
   - 因为我们是根据**“扣减之前”**的状态来判断是否发生变化的。如果先减了，`cnts` 变成 0，你就不知道它之前是不是 1 了（虽然也可以判断变成 0，但逻辑上对应起来更容易理解：先看能不能减指标，再减实际数量）。
2. **为什么不直接统计所有 >= k 的子串？**
   - 因为如果不固定 `require`，当你发现窗口里有一个字符次数 $< k$ 时，你是应该**右移 R** (增加次数) 还是 **右移 L** (减少种类)？无法确定。固定了 `require` 后，只要种类不超标，我们就无脑扩 R，逻辑就顺了。

### 7. 【复习闪卡】

- **Q: 遇到“最长子串 + 某种限制条件不具备单调性”怎么办？**
  - A: 考虑**增加限制条件**来构造单调性。比如本题，限制“子串中字符种类数”后，就具备了单调性。
- **Q: 本题的内层 while 循环条件是什么？**
  - A: `collect > require`。只要种类数超了，就必须缩窗，直到种类数回到 `require`。
- **Q: `satisfy` 什么时候增加？**
  - A: 当某个字符的计数**刚刚达到** `k` 时 (`== k`)。如果从 `k` 变成 `k+1`，`satisfy` 不变。
